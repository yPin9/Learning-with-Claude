# Ch 3 — 模式與基本移動

> **目標**：搞懂 Neovim 的四個模式，並把基本 motion（移動指令）練成反射。讀碼 99% 的時間你待在 **normal mode**——它不是「還沒開始打字的閒置狀態」，它是**導航模式**，是你在大檔裡精準跳來跳去的操作台。這一章不教你怎麼寫程式，教你怎麼用鍵盤在一份陌生 C 檔裡「用意圖移動」而不是「用方向鍵一格一格爬」。

> **環境**：Neovim v0.12.4，WSL2 / Ubuntu。範例檔用 Lua 直譯器原始碼 `lvm.c`（1978 行，`git clone --depth 1 https://github.com/lua/lua`），這是一份真實、夠大、你八成沒讀過的 C 檔——正是這門課的靶。

## 為什麼需要這個？

大部分人第一次進 Vim 的反應是：怎麼移動游標？然後發現方向鍵能動，就一路 `↓↓↓↓↓` 按下去。這能用，但它把 Vim 降級成一個很難用的記事本。

讀碼是**導航密集**的活。你打開 `lvm.c`，想看 `luaV_execute` 這個主迴圈——它在第 1204 行。你不會想按 1204 次 `j`。你也不會想動滑鼠拖捲軸——拖到大概位置，再瞇眼找。這兩種做法的共同問題是：**它們消耗你的注意力**。你本來要想「這個 VM 怎麼 dispatch opcode」，結果注意力全花在「往下捲到那個函式」。

Vim 的 motion 解決的是這件事：**用一個意圖表達的指令，一步到位**。「跳到第 1204 行」是 `1204G`。「跳到下一個單字」是 `w`。「跳到這行的 `=` 號」是 `f=`。你腦子想的是位置，手直接把你送過去，中間不經過「一格一格爬」。省下的不是打字時間，是**維持思路的認知資源**——這正是 `reading_code` 反覆強調的：讀碼慢下來的元凶是 working memory 被瑣事塞爆。

## 先建立直覺：模式是「同一組按鍵、不同語意」

一般編輯器裡，`d` 永遠是打出字母 d。Vim 不是。Vim 的核心設計是**模式（mode）**：同一個實體按鍵，在不同模式下代表不同意思。

```
        ┌─────────────────────────────────────────────┐
        │              NORMAL（導航/命令模式）          │
        │   讀碼 99% 待在這。h j k l w b 都是「移動」    │
        │   d y c 是「操作」，不是打字                   │
        └───┬──────────┬──────────┬─────────────┬──────┘
     i/a/o │      v/V  │       :  │         Esc │（隨時回 normal）
            ▼          ▼          ▼             │
     ┌──────────┐ ┌────────┐ ┌──────────┐      │
     │  INSERT  │ │ VISUAL │ │ COMMAND  │──────┘
     │ 真的打字 │ │ 選文字 │ │ :w :g /..│
     └──────────┘ └────────┘ └──────────┘
```

心智模型：**normal mode 是家**。你從家出發去 insert（打字）、去 visual（選取）、去 command（下 ex 指令），做完事按 `Esc` 就回家。寫程式的人常年住在 insert，Vim 老手則相反——**住在 normal，偶爾出門**。讀碼的人更是幾乎不出門，因為讀碼不打字，只導航。

這也是為什麼 Vim 對讀碼特別強：一個不打字、只移動與選取的活，剛好就是 normal mode 的主場。單字母就能觸發一個導航動作，不用按 `Ctrl` 也不用移到滑鼠。

## 四個模式，讀者只真正住在一個

| 模式 | 怎麼進 | 幹嘛用 | 讀碼用量 |
|---|---|---|---|
| **Normal** | `Esc`（從任何模式回來） | 移動、跳轉、選取、下操作指令 | 幾乎全部時間 |
| **Insert** | `i` `a` `o` `I` `A` `O` | 真的打字改內容 | 讀碼幾乎不用 |
| **Visual** | `v`（字元）`V`（整行）`Ctrl-v`（區塊） | 選一段來看範圍、或當操作對象 | 常用（選中看範圍） |
| **Command** | `:` | 下 ex 指令（`:g` `:s` `:w` `:%!`） | 常用（搜尋、批次列出） |

讀碼時你進 insert 的機會極少——頂多加個 debug 註解。但 `v`（visual）你會一直用：選中一個 `if` block「看它涵蓋到哪」，選中一個函式體「看它多長」。command 模式你也常用：`:1204`（跳行）、`:g/pattern/`（列出所有配對行，Ch 6 詳談）。

**新手最大的坑：不知道自己在哪個模式。** 按鍵沒反應、或打出一堆奇怪字元，八成是模式不對。解法簡單粗暴：**手指卡住就先按 `Esc` 回 normal**，重新開始。老手按 `Esc` 是肌肉反射，一個動作結束隨手就按。

## 基本移動一：h j k l（別鄙視，但別依賴）

最基本的四向移動。位置在鍵盤 home row，手不用離開：

```
        k          ↑
      h   l      ←   →
        j          ↓
```

`j` 下、`k` 上、`h` 左、`l` 右。記法：`j` 像個往下的勾。它們比方向鍵好的地方只有一個——**手不用離開 home row**，日積月累省下的移動很可觀。

但關鍵觀念：**`hjkl` 是最後手段，不是主力**。如果你在讀碼時發現自己連按十下 `j`，那是訊號——你該用更精準的 motion（`w`、`f`、`}`、`G`、`/`）一步到位。`hjkl` 適合的是「微調一兩格」。

配合 count 才有威力：`5j` 往下五行、`12k` 往上十二行。Ch 0 的 config 開了 `relativenumber`（相對行號），就是為了讓你一眼看出「那行在下面 7 行」→ 直接 `7j`，不用心算。

## 基本移動二：word motion（讀 C 的主力）

以「單字」為單位跳，這是讀一行 code 時的主力：

```
    if (ttisinteger(pinit) && ttisinteger(pstep)) {
    ^   ^          ^      ^  ^
    w   w          w      w  w  ...（每按一次 w 跳一個 word 開頭）
```

- `w`：跳到**下一個** word 開頭（word = 字母數字底線串，標點自成一個 word）
- `b`：跳回**上一個** word 開頭（back）
- `e`：跳到**這個/下一個** word 結尾（end）
- `W B E`（大寫）：以 **WORD** 為單位——WORD 是「被空白隔開的一整串」，標點不切開

差別在讀 C 時很有感。看這行：`ttisinteger(pinit)`：

- `w` 會停在 `ttisinteger` → `(` → `pinit` → `)`——把括號也當 word 切開
- `W` 會把 `ttisinteger(pinit)` 當成一整個 WORD（因為中間沒空白），一下跳過整串

讀碼時的取捨：**想精準落在某個 identifier 或某個標點上，用小寫 `w`/`e`；想大跨度掠過一整串（如跳過整個 `foo->bar[i].baz`），用大寫 `W`。** 追一個變數名時，`e` 特別好用——它讓游標停在單字尾巴，接著配 `*`（Ch 6）搜同名，或配 `viw`（Ch 4）選整個 word。

## 基本移動三：行內精準跳（f t F T ; ,）

在一行內跳到某個字元，這是讀一行長 code 的殺手鐧：

- `f<char>`：往右跳到**下一個** `<char>` 上（find）。`f=` 跳到這行的 `=`
- `t<char>`：往右跳到 `<char>` **前一格**（till）
- `F<char>` / `T<char>`：同上但往**左**找
- `;`：重複上次 `f`/`t`，往同方向再找一次
- `,`：重複上次 `f`/`t`，往**反**方向

讀這行（`lvm.c` 的 `forlimit`）：

```
    if (forlimit(L, init, plimit, &limit, step))
```

想跳到第三個逗號後的 `&limit`？`f,` 到第一個逗號，`;` `;` 連按跳到第三個逗號，再 `w` 到 `&limit`。或直接 `f&`——一步到位跳到 `&`。**行內導航別用 `l` 一格一格爬，用 `f`/`t` 瞄準。** 這是區分新手和老手最明顯的一個習慣。

## 基本移動四：行首行尾與檔頭尾

跳到行內或整檔的邊界：

- `0`：跳到行首第 0 欄（最左）
- `^`：跳到行首**第一個非空白字元**（讀縮排 code 時你要的通常是這個，不是 `0`）
- `$`：跳到行尾
- `gg`：跳到**檔案第一行**
- `G`：跳到**檔案最後一行**
- `<N>G` 或 `:<N>`：跳到第 N 行。`1204G` 直接飛到 `luaV_execute`

讀碼情境：`^` 讓你跳到一行實際 code 的開頭（略過縮排），配合 `d`/`c` 這種操作特別自然。`gg` 和 `G` 是你打開一個陌生檔的第一組動作——`gg` 看檔頭的 `#include` 和 copyright、`G` 看檔尾（很多 C 檔把重點函式或 `luaL_register` 表放檔尾）。`<N>G` 是你從 grep/LSP 拿到「第 1204 行」後，直接飛過去的方式。

## 基本移動五：段落跳（{ }）——函式間快速移動

`{` 和 `}` 以**空行**為界跳段落：

- `}`：跳到下一個空行（往下一個「段落」）
- `{`：跳到上一個空行（往上一個「段落」）

為什麼讀 C 特別有用？因為**寫得好的 C 用空行分隔函式與邏輯塊**。在 `lvm.c` 裡，每個函式之間、每個邏輯段落之間都有空行。所以連按 `}` 就是在**函式與函式之間跳**，比一格一格捲快得多。

```
    static int forprep (lua_State *L, StkId ra) {
      ...
    }
                          ← 空行，} 停這
    static int floatforloop (lua_State *L, StkId ra) {
      ...
    }
                          ← 空行，} 停這
```

這是「掃讀」（reading_code 的三種閱讀模式之一）的利器：`}` `}` `}` 一路往下，每停一次就瞄一眼「這是哪個函式」，快速建立檔案的地形圖。Ch 5 的 `[[` `]]` 會做得更精準（真的以函式為單位），但 `{` `}` 是零設定就有的粗略版。

## 基本移動六：捲動（Ctrl-d/u/f/b）與螢幕定位（H M L）

大檔裡移動視窗，不移動邏輯位置：

- `Ctrl-d`：往下捲**半頁**（down）
- `Ctrl-u`：往上捲**半頁**（up）
- `Ctrl-f`：往下捲**整頁**（forward）
- `Ctrl-b`：往上捲**整頁**（back）
- `H`：游標跳到**螢幕最上**行（High）
- `M`：跳到**螢幕中間**（Middle）
- `L`：跳到**螢幕最下**（Low）

讀碼情境：`Ctrl-d`/`Ctrl-u` 是你「掃過一個長函式」時的節奏——半頁半頁往下，保留一半舊內容當上下文（比整頁 `Ctrl-f` 不容易迷失）。`H M L` 讓你在**已經看到的一屏內**快速把游標挪到你想細看的那一塊，不用 `j`/`k` 數。

Ch 8 會講 `zz`（把當前行置中）——它跟捲動是一組的：`1204G` 跳到函式後常接 `zz`，讓那個函式定義置中，上下文一次看好看滿。

## 對比與取捨

| 你想做的事 | 慢做法（新手） | 快做法（motion） |
|---|---|---|
| 到第 1204 行 | 捲滑鼠 / 連按 `j` | `1204G` |
| 到這行的 `=` | 連按 `l` | `f=` |
| 跳過一整個 `foo->bar.baz` | 多次 `w` | 一次 `W` |
| 到下一個函式 | 連按 `j` | `}`（或 Ch 5 的 `]]`） |
| 掃過一個長函式 | 拖捲軸 | `Ctrl-d` 半頁半頁 |
| 到行首 code（略過縮排） | `0` 再 `w` | `^` |

核心原則貫穿全表：**先想「我要到哪」，再選最短的 motion 過去。** 不要反射性地按方向鍵。每次你發現自己連按同一個鍵超過三下，停下來問：有沒有一個 motion 一步到位？

## 踩雷集錦

1. **一路 `j` 到底，把 Vim 當難用記事本**。這是最大的浪費。訓練自己：想移動超過幾行，就用 `<N>j`、`}`、`/搜尋`、`<N>G` 其中一個。`relativenumber` 就是逼你養成這習慣的設定。
2. **搞不清 `0` 和 `^`**。讀有縮排的 C，你 99% 想要的是 `^`（跳到 code 開頭，略過縮排），不是 `0`（跳到最左邊的空白）。用錯會讓你多一個 `w`。
3. **忘記自己在 insert mode**，狂打 motion 鍵結果打出一堆 `jjjjwww` 字元。看到編輯器在「打字」而不是「移動」，立刻 `Esc`。養成「一個動作做完隨手 Esc」的反射。
4. **`f` 找不到就放棄**。`f=` 只找**這一行**內的 `=`，找不到不會跳行。要往下找請用 `/`（Ch 6）。`f`/`t` 是行內工具，別期待它跨行。
5. **`w` 在標點多的 C 裡「跳不動」**。`foo->bar` 裡 `w` 會卡在 `-`、`>` 上跳很多次。這時 `W` 一下跳過整串，或直接 `f` 瞄準你要的字元。認清 `w`（切標點）vs `W`（不切）的差別，選對工具。

## 進階：再往深一層

- **motion 是「名詞」，operator 是「動詞」**：Vim 的威力來自 `operator + motion` 組合。`d`（刪）+ `w`（到下個 word）= `dw`。`y`（複製）+ `$`（到行尾）= `y$`。這章教的每個 motion，之後都能當 operator 的受詞。讀碼時最常用的是 `y`（複製一段去別處看/貼到筆記）。Ch 4 會把這套組合玩到極致（operator + text object）。
- **`:help motion.txt`** 是這章的權威來源，裡面把 motion 分成 **charwise / linewise / exclusive / inclusive** 四類——這影響 `d`/`y` 到底吃不吃到落點那個字元。讀碼階段先不用鑽，等你開始用 operator 才需要。
- **count 可以放在 operator 和 motion 兩邊**：`2d3w` = 刪 6 個 word（2×3）。這種正交組合是 Vim 的設計哲學，也是它「學一次、到處通用」的原因——你不用背幾百個指令，你背幾十個 motion + 幾個 operator，然後自由組合。

## 本章重點整理

- Neovim 有四個模式；**讀碼 99% 待在 normal mode，它是導航模式不是閒置**。手指卡住就 `Esc` 回家。
- 核心信條：**用意圖 motion 精準到達，別用方向鍵一格一格爬**。連按同鍵三下就是換 motion 的訊號。
- 讀 C 的主力 motion：word（`w b e` / `W B E`）、行內瞄準（`f t ; ,`）、行邊界（`^ $`）、檔邊界（`gg G <N>G`）、段落/函式間（`{ }`）。
- 大檔用捲動（`Ctrl-d/u/f/b`）掃過，用 `H M L` 在一屏內挪游標。
- motion 之後會變成 operator 的受詞（`dw`/`y$`），這是 Vim 威力的來源——下一章的 text object 把它推到極致。
