# Ch 5 — 跳轉與 jumplist：導航命脈

> **目標**：掌握 Neovim 的 **jumplist（跳轉列表）** 與相關跳轉機制——這是**讀碼導航的命脈**。追一條 call chain 時，你會一路跳進去（跳定義、跳定義、再跳定義），看懂之後要能**原路退回來**。`Ctrl-O`/`Ctrl-I` 就是這條路上的「上一頁/下一頁」。沒有這個，你在大檔裡追兩層就迷路了。這一章教你怎麼在幾十萬行裡追一條路徑，並且隨時知道自己怎麼回去。

> **環境**：Neovim v0.12.4，WSL2。範例用 Lua 的 `lvm.c`。本章的 `Ctrl-O`/`Ctrl-I`/`` `` ``/`gd`/`gf`/`%`/`*` 全是 Neovim 內建 motion，不需外掛。

## 為什麼需要這個？

讀 `reading_code` 的核心動作之一是**追 data flow / call chain**：從 `luaV_tointeger`（157 行）看它呼叫 `luaV_tointegerns`（142 行），再看 `luaV_tointegerns` 呼叫 `luaV_flttointeger`（126 行）。你一層一層跳進去讀。

問題是——**跳進去容易，退回來難**。你跳到第三層看懂了，想回到最上面那個呼叫點繼續讀，怎麼回？新手的做法：憑記憶按 `157G`……欸剛剛是 157 還是 175？或者拼命捲，找回原來那行。這一來一回，你剛才追出來的思路就斷了。

Vim 有一個專門機制解決這件事：**jumplist**。每次你做一個「大跳轉」（跳定義、搜尋、`G`、`%`……），Vim 就在一個堆疊裡記下你**跳之前**的位置。`Ctrl-O` 沿堆疊往回退，`Ctrl-I` 往前進。這讓「追一條路徑再原路退回」變成兩個鍵的事——**這是讀碼導航最重要的一個機制，沒有之一**。

## 先建立直覺：jumplist 是你的麵包屑

```
    你的閱讀路徑（每個 ● 是一個「跳」的落點）：

    luaV_tointeger (157) ●
            │  gd 跳定義
            ▼
    luaV_tointegerns (142) ●
            │  gd 跳定義
            ▼
    luaV_flttointeger (126) ●  ← 你現在在這，看懂了
            │
        Ctrl-O ↑（退回 142）
        Ctrl-O ↑（退回 157，回到起點）
        Ctrl-I ↓（後悔了，再往前跳回 142）

    jumplist（堆疊）：[157] [142] [126]
                              ↑ Ctrl-O 往左，Ctrl-I 往右
```

心智模型：**jumplist 是你這趟閱讀留下的麵包屑**。你走多深都不怕，`Ctrl-O` 一路撿麵包屑回家。`Ctrl-I` 是「我退太多了，往回走一格」。

關鍵：**不是所有移動都進 jumplist**。`j`/`k`/`w`/`h`/`l` 這種「小移動」**不記**（否則麵包屑會被瑣碎移動淹沒）。只有「跳」——搜尋 `/`、`gd`、`G`、`%`、`{ }`、`*`——才在你跳走前記下舊位置。這個設計很精妙：它只保留你「有意義的落腳點」。

## 核心一：Ctrl-O / Ctrl-I（追路徑的命根子）

| 按鍵 | 作用 | 讀碼場景 |
|---|---|---|
| `Ctrl-O` | 跳回 jumplist 中**上一個**位置（往回退） | 追進去看完，退回呼叫點 |
| `Ctrl-I` | 跳到 jumplist 中**下一個**位置（往前進） | 退太多了，再往前 |
| `:jumps` | 顯示整個 jumplist（看你走過哪些點） | 迷路時看路徑 |

`Ctrl-O` 讀成 "**O**lder"（更舊的位置），`Ctrl-I` 讀成 "newer"（`I` 和 `Tab` 是同一鍵，記成「Tab 前進」）。這兩個是你讀碼**按最多次**的鍵，超過 `gd`——因為每跳進去一次，遲早要退回來。

實戰節奏（在 `lvm.c` 裡追那條 `tointeger` 鏈）：

1. 游標在第 157 行 `luaV_tointeger` 內，看到它 `return luaV_tointegerns(...)`
2. 游標移到 `luaV_tointegerns` 上，`gd`（跳到它的定義，142 行）
3. 讀 142 行的 `luaV_tointegerns`，看到它 `return luaV_flttointeger(...)`
4. 游標移到 `luaV_flttointeger`，`gd`（跳到 126 行）
5. 讀懂了 → `Ctrl-O`（退回 142）→ `Ctrl-O`（退回 157，回起點）

整趟你按了兩次 `gd` 進去，兩次 `Ctrl-O` 回來，**完全不用記行號、不用捲動**。這就是「追一條路徑不迷路」。

> jumplist 是 **per-window** 的，跨檔也有效。`gd` 若跳到別的檔（如跳進 header），`Ctrl-O` 一樣能把你帶回原檔原位——它記的是「檔案+位置」，不只是行號。

## 核心二：gd（內建的跳到區域定義）

`gd` = **g**o to **d**efinition（**local**）。注意：這裡講的是 **Vim 內建**的 `gd`，不是 LSP 的那個（Part 4）。內建 `gd` 的行為：**跳到游標下這個 identifier 在當前函式/檔案內第一次出現的地方**——它靠簡單的文字啟發式（往回找同名 + 像宣告的樣子），不懂型別、不跨檔。

- `gd`：跳到區域變數/符號的定義（當前檔內）
- `gD`：跳到全域符號的定義（從檔頭找起）

讀碼場景：你看到一個區域變數 `count`，想知道它哪來的——游標放上去 `gd`，跳到它宣告的那行。這在**沒有 LSP、沒 compile_commands.json** 的檔子裡是救命工具（Part 5 的 tags 是更強的後備）。有 LSP 時，我們把 `gd` 重綁到 `vim.lsp.buf.definition`（Ch 0 config 那樣），因為 LSP 版懂型別、能跨檔、更準。**兩個 `gd` 打同一個位置——內建版是無 LSP 時的退路。**

> 這是這門課「config 逐 Part 累加」的一個具體例子：內建 `gd` 是免費的地基，Part 4 我們用 LSP 覆蓋它拿到語意級精準，Part 5 用 tags 當第三層退路。同一個鍵，三層能力。

## 核心三：gf（跳到游標下的檔案）——讀 #include 神器

`gf` = **g**o to **f**ile。游標放在一個檔名/路徑上，`gf` 直接打開那個檔。

讀 C 的 `#include` 時無敵。`lvm.c` 檔頭有：

```c
#include "lapi.h"
#include "ldebug.h"
```

游標放在 `lapi.h` 上按 `gf`——**直接跳進 `lapi.h`**，看那些被 include 的宣告。看完 `Ctrl-O` 退回 `lvm.c`（`gf` 也進 jumplist）。這比「telescope 找檔、打字 `lapi.h`、Enter」快，因為檔名就在你眼前，不用重打。

`gf` 靠 `path` 選項找檔。讀 C 專案時，把 include 目錄加進 `path`（如 `:set path+=./include`），`gf` 才找得到不在當前目錄的 header。`Ctrl-W f` 是「在新 split 開這個檔」的變體（Ch 7 講 window 時會用到，左邊 `.c` 右邊 `.h` 對照讀）。

## 核心四：`` `` `` 與各種 mark 跳（跳回上次位置）

Vim 自動維護幾個特殊 mark，`` ` `` + 字母跳過去：

| 按鍵 | 跳到 | 讀碼用途 |
|---|---|---|
| `` `` `` （兩個反引號） | **上次跳轉前**的位置 | 「我剛跳走，跳回去看一眼」 |
| `` `. `` | 上次**修改**的位置 | 回到你剛加註解/改的地方 |
| `` `^ `` | 上次**離開 insert** 的位置 | 回到剛打字的點 |
| `` `" `` | 上次**關閉此檔**時的位置 | 重開檔案跳回離開處 |

`` `` `` 特別好用：它是「來回切」的鍵。你在 A 位置，跳到 B 看一眼，`` `` `` 跳回 A，再 `` `` `` 又到 B——**在兩個位置間反覆橫跳**。追 data flow 時你常要在「定義處」和「使用處」之間來回對照，`` `` `` 就是這個。（`Ctrl-O`/`Ctrl-I` 是走整條路徑，`` `` `` 是最近兩點來回。）

Ch 8 會講**自訂 mark**（`ma` 設、`` `a `` 跳），標記你的「攻堅點」——那是更主動的外化。這裡先掌握這幾個 Vim 自動維護的。

## 核心五：結構跳（% 與 [[ ]] [{ ]}）

以語法結構為單位跳，不靠行號：

- `%`：配對括號跳（`()` `{}` `[]`）——Ch 4 講過，這裡強調它進 jumplist，是追 block 範圍的跳
- `[[` / `]]`：往上/下跳到**上一個/下一個函式開頭**（找第一欄的 `{`）
- `[{` / `]}`：往上/下跳到**包住當前位置的 `{` / `}`**（跳出當前 block）
- `[(` / `])`：同理，未配對的 `(` / `)`

讀碼場景：`]]` `]]` `]]` 一路往下，**一個函式一個函式地跳**（比 Ch 3 的 `}` 段落跳更精準，它認函式邊界不只是空行）。`[{` 在深巢狀裡「跳到包住我這層的 block 開頭」——你在 `luaV_execute` 某個 `vmcase` 深處，`[{` 跳到那個 case 的 `{`，再 `[{` 跳到外層 switch 的 `{`，一層層往外定位「我現在在哪個 block 裡」。

> `[[` `]]` 依賴「函式的 `{` 在第一欄」這個 C 慣例。K&R 風格（`{` 在第一欄）它很準；`{` 不在第一欄的風格（Allman 縮排、或某些 C++）它會失準。這時 treesitter（Part 3 Ch 14）或 LSP symbol（Part 4）是更可靠的「函式間跳」。

## 核心六：* 和 #（跳同名符號的下/上一個）

- `*`：搜尋游標下的 word，跳到它**下一個**出現處
- `#`：跳到**上一個**出現處
- `g*` / `g#`：同上但不要求整字匹配（`foo` 也會配到 `foobar`）

讀碼場景：這是**追一個變數/函式在檔內所有出現**的最快方式。游標放在 `luaV_flttointeger` 上按 `*`——直接跳到它下一個出現處（如 437 行的呼叫），再 `*` 跳下一個，`n`/`N`（Ch 6）繼續。你不用打字，游標下的字自動變成搜尋詞。這是「這個函式在本檔哪裡被呼叫」的窮人版（單檔內；跨檔要 `gr`/gtags，Part 4/5）。

`*` 會進 jumplist，所以你 `*` `*` 追了幾個出現處後，`Ctrl-O` 能一路退回起點。`changelist`（`g;`/`g,`）則是另一套堆疊，追的是「你**改**過的位置」而非「跳過的位置」——讀碼加了幾個 debug 註解後，`g;` 巡回這些修改點。

## 對比與取捨

| 你想做的事 | 沒 jumplist 的做法 | jumplist 做法 |
|---|---|---|
| 追進去看完退回呼叫點 | 記行號、手動捲回 | `gd` 進、`Ctrl-O` 回 |
| 在定義與使用處來回對照 | 兩邊記行號跳來跳去 | `` `` `` 反覆橫跳 |
| 看某函式在本檔哪被呼叫 | `/函式名` 再 `n` | 游標放上 `*` 連按 |
| 讀 `#include` 的 header | telescope 打字找檔 | 游標放檔名上 `gf` |
| 定位「我在哪層 block」 | 往上捲數縮排 | `[{` 一層層往外跳 |

**jumplist（`Ctrl-O`/`Ctrl-I`）vs mark（`` `a ``）vs harpoon（Part 6）** 的分工：jumplist 是**自動**記錄的線性路徑（適合「追一趟再退回」）；mark 是你**手動**標的定點（適合「這幾個攻堅點我要反覆回來」）；harpoon 是 mark 的升級（跨 session、選單化）。這章先把自動的 jumplist 練熟，它覆蓋讀碼 80% 的來回需求。

## 踩雷集錦

1. **以為 `Ctrl-I` 是「跳定義」**。不是——`Ctrl-I`（=`Tab`）是 jumplist **往前**，跟 `Ctrl-O` 成對。有些人把 `Ctrl-]`（tag 跳，Part 5）記混。`gd` 才是跳定義。
2. **`j`/`k`/`w` 之後想 `Ctrl-O` 退回卻沒動**。因為這些小移動**不進 jumplist**。只有「跳」（`/`、`gd`、`G`、`%`、`*`、`{}`）才記。這是設計，不是 bug——否則麵包屑全是雜訊。
3. **內建 `gd` 跳錯地方**。內建 `gd` 是文字啟發式，遇到同名的區域變數、macro、多個宣告會猜錯。它是**無 LSP 時的退路**，不是精準工具。有 clangd 時用 LSP 版 `gd`（Ch 0 config 已重綁），準得多。
4. **`gf` 說 "can't find file"**。`gf` 靠 `path` 選項找檔，預設不含專案的 include 目錄。讀 C 前先 `:set path+=./include`（或用 `**` 遞迴），header 才找得到。
5. **`*` 追同名時漏掉「不同大小寫/子字串」的出現**。`*` 是整字 + 依 `smartcase` 匹配。想連 `foobar` 裡的 `foo` 也配到，用 `g*`。想跨檔找所有出現，`*` 不夠（單檔內），要 `gr`（LSP，Part 4）或 gtags（Part 5）。

## 進階：再往深一層

- **jumplist 有大小上限且是堆疊語意**：預設記 100 個位置。當你在中途（`Ctrl-O` 退了幾格）又做新跳轉，前面的「未來」會被截斷——就像瀏覽器上一頁後又點新連結，前進歷史沒了。`:jumps` 看得到完整堆疊與你目前的游標位置（`>` 標記）。
- **jumplist 與 tagstack 是兩套獨立堆疊**：`Ctrl-O`/`Ctrl-I` 走 jumplist；`Ctrl-]`/`Ctrl-T`（Part 5）走 tagstack。LSP 的 `gd` 通常也會推 jumplist。搞清楚「我剛剛是用什麼跳的」才知道用哪組退回——這在 Part 5 tags 那章會再強調。
- **`:help jump-motions`** 列出**所有**會進 jumplist 的 motion（`' ` G / ? n N % ( ) { } [[ ]] L M H` 等）。值得掃一遍建立「哪些算大跳、會留麵包屑」的直覺。反過來，**加 `<count>` 前綴的 `j`/`k`**（如 `10j`）**會**進 jumplist（因為算「有意圖的跳」），純 `j` 不會——這個細節解釋了為什麼有時 `Ctrl-O` 意外能退回一個 `10j`。

## 本章重點整理

- **jumplist（`Ctrl-O` 退 / `Ctrl-I` 進）是讀碼導航的命脈**：追一條 call chain 進去，原路退回來，全靠這兩鍵——讀碼按最多次的鍵。
- 只有「大跳」（`/`、`gd`、`G`、`%`、`*`、`{}`、`[[`）進 jumplist；`j`/`k`/`w` 這種小移動不記，麵包屑才乾淨。
- `gd`（內建區域定義，無 LSP 退路）、`gf`（跳 `#include` 的 header）、`` `` ``（兩點來回）、`*`/`#`（追同名符號）、`[{`/`]}`（跳出/定位 block）——每個都對應一個具體讀碼動作。
- 內建 `gd` 是啟發式退路；Part 4 用 LSP 覆蓋它、Part 5 用 tags 當第三層——同一個鍵三層能力，是本課 config 逐 Part 累加的縮影。
