# Ch 4 — text objects：選中一個結構

> **目標**：學會 text object（文字物件）——**讀碼時「選中一個結構來看範圍」的核心操作**。text object 讓你用一個指令選中「整個括號內的參數」「整個大括號 block」「整個字串」「整段」，而不用手動一格一格框。這是 Vim 之所以是 Vim 的殺手鐧：**語意化選取（selection by structure）**取代了手動選取。對讀者而言，最有用的組合是 `v`（visual）+ text object「選中看範圍」，再加 `%`（配對括號跳）。

> **環境**：Neovim v0.12.4，WSL2。範例續用 Lua 的 `lvm.c`。

## 為什麼需要這個？

讀一個大函式時，你常想問一個很具體的問題：**「這個 block 到底涵蓋哪幾行？」** 你看到 `luaV_execute` 裡有個 `for (;;) { ... }` 主迴圈，`{` 在第 1237 行，你想知道它的 `}` 在哪、這個 block 有多長。

新手做法：把游標放到 `{`，然後 `Shift-V`（行選）一路 `j` 往下按，一邊按一邊數大括號，希望在對的 `}` 停下。這在有巢狀 `{}` 的 C 裡是災難——`luaV_execute` 裡面每個 `vmcase` 都有自己的 `{}`，你數到眼花還數錯。

text object 做法：游標放在 block 內任何一個地方，按 `vi{`——**整個大括號 block 瞬間被選中，配對正確、巢狀正確**。你不用找 `}` 在哪，Vim 用它對語法結構的理解幫你框好。這就是「語意化選取」：你說「這個 block」，不是「從這裡到那裡」。

讀碼是理解「結構」的活。函式、參數列、block、字串、標籤——這些都是結構。text object 讓你能**直接對著結構操作**，而不是把結構翻譯成「第幾行到第幾行」。這是讀碼摩擦下降最明顯的一個工具。

## 先建立直覺：operator + text object 是一個句子

Vim 的操作語法像英文句子：**動詞 + 修飾詞 + 名詞**。

```
    d       i        {
    ↑       ↑        ↑
  operator  修飾    text object
  （動詞）  inner   （名詞：大括號 block）
```

- **operator（動詞）**：`d`(刪) `y`(複製) `c`(改) `v`(選)
- **修飾**：`i`(inner，內容) 或 `a`(around/a，含邊界)
- **text object（名詞）**：`{` `(` `"` `w` `p` `t` …

組合起來讀出來就是完整意圖：

- `di{` = **d**elete **i**nner **{** → 刪掉大括號**裡面**的內容（留大括號）
- `da{` = **d**elete **a**round **{** → 連大括號一起刪
- `yi(` = **y**ank **i**nner **(** → 複製小括號裡面（不含括號）
- `ci"` = **c**hange **i**nner **"** → 改掉引號裡的字串
- `vi{` = **v**isually select **i**nner **{** → **選中**大括號內容來看

對讀者最重要的動詞是 `v`（選中看範圍）和 `y`（複製一段去筆記/貼別處）。`d`/`c` 是編輯用的，讀碼少用——但語法完全一樣，學一次全通。

## inner vs around：差一個邊界，差很多

`i`（inner）和 `a`（around）的差別是**含不含邊界字元**：

```
    "hello world"
     └───inner───┘        ← i"  選 hello world（不含引號）
    └────around────┘       ← a"  選 "hello world"（含引號）

    (L, init, plimit)
     └────inner────┘       ← i(  選 L, init, plimit（不含括號）
    └─────around─────┘      ← a(  選 (L, init, plimit)（含括號、含前面的空白）
```

讀碼取捨：想**看**一段內容用 `i`（乾淨，只有內容）。想把一整個東西**搬走或算範圍**用 `a`（含界符才是完整單位）。例如複製一個字串內容去搜尋別處，用 `yi"`（不要引號）；複製整個 `(...)` 參數列連括號，用 `ya(`。

## 讀碼最有用的 text objects

| text object | 選中的東西 | 讀碼用途 |
|---|---|---|
| `iw` / `aw` | 一個 word / 含後方空白 | 選中一個 identifier（配 `*` 搜同名） |
| `i(` / `a(`（或 `ib`/`ab`） | 小括號內 / 含括號 | 選整組函式參數、整個判斷式 |
| `i{` / `a{`（或 `iB`/`aB`） | 大括號 block 內 / 含括號 | **選整個函式體 / if block（最常用）** |
| `i[` / `a[` | 中括號內 / 含括號 | 選陣列索引、initializer |
| `i"` / `a"` | 雙引號字串內 / 含引號 | 抄一個字串常數去 grep |
| `i'` / `a'` | 單引號內 / 含引號 | 抄字元常數 |
| `it` / `at` | XML/HTML tag 內 / 含 tag | 讀 markup（C 少用） |
| `ip` / `ap` | 一段（空行分隔） / 含後空行 | 選中一整個「段落」——常好對應一個函式 |

`i(` 可以寫成 `ib`（**b**lock/bracket），`i{` 可以寫成 `iB`（大 **B**lock）——記不住括號符號時的替代寫法。

## 殺手鐧一：vi{ 選整個 block「看範圍」

這是讀者最該練成反射的一個動作。看 `lvm.c` 的 `luaV_tonumber_`（第 108 行起）：

```c
int luaV_tonumber_ (const TValue *obj, lua_Number *n) {
  TValue v;
  if (ttisinteger(obj)) {
    *n = cast_num(ivalue(obj));
    return 1;
  }
  else if (l_strton(obj, &v)) {  /* string coercible to number? */
    *n = nvalue(&v);
    return 1;
  }
  else
    return 0;  /* conversion failed */
}
```

問題：那個 `if (ttisinteger(obj)) { ... }` block 涵蓋到哪？把游標放進去（比如放在 `*n = cast_num` 那行），按 `vi{`——**那三行（`*n = ...; return 1;`）被高亮選中**，你一眼看到這個分支就這麼點大。想看外層整個函式體？把游標放函式內任一處，按 `vi{`——如果你在最外層 block，整個函式體被選中，狀態列顯示選了幾行。

進階：`vi{` 選中後，再按 `i{` 會**往外擴一層**（在 visual mode 裡重複 text object 會擴展選取）。所以 `vi{` 然後連按 `i{` `i{`，就是「這個 block → 包住它的 block → 再外一層」，一層層看巢狀結構的範圍。這在讀 `luaV_execute` 那種深巢狀的 switch 時非常有用。

> **互動 UI（visual 高亮）headless 截不了圖**：以上是鍵位操作描述。visual 選取是即時高亮，在終端裡看是反白區塊。底層行為（text object 的邊界計算）是 Vim 核心功能，`:help text-objects` 有完整定義。

## 殺手鐧二：% 在配對括號間跳

`%` 把游標從一個括號跳到它的**配對括號**：`(`↔`)`、`{`↔`}`、`[`↔`]`。

讀碼情境：游標放在函式開頭那個 `{` 上，按 `%`——**直接飛到對應的 `}`**，你立刻知道函式在哪結束、有多長。反過來，游標在 `}` 上按 `%` 跳回 `{`。這是「這個 block 到哪結束」最快的答案，比 `vi{` 更輕（不選取，只跳）。

`%` 在追巢狀結構時尤其關鍵。`luaV_execute` 有一個超長的 `for (;;) { switch { case: {} case: {} ... } }`。游標放在最外層 `{`，`%` 一下跳到最外層 `}`——中間所有巢狀 case 的 `{}` 都自動跳過，因為 `%` 認得配對。你瞬間知道整個 dispatch 迴圈的範圍。

`%` 也能配 operator：`d%`（從當前括號刪到配對括號）、`y%`（複製一整個括號範圍，含巢狀）、`v%`（選中一整個配對範圍）。`v%` 是 `vi{`/`va{` 的近親——當游標剛好在括號上時特別順手。

## 殺手鐧三：語意選取 vs 手動選取的本質差別

為什麼說 text object 是 Vim 的殺手鐧？因為它把「**選取**」從一個「空間動作」變成一個「**語意動作**」。

```
    手動選取（一般編輯器 / Shift+方向鍵）：
      「從這裡……拖到……那裡」——你要自己算範圍、自己找邊界
      巢狀括號會讓你數錯、選過頭或選不足

    語意選取（text object）：
      「這個 block」「這組參數」「這個字串」
      Vim 用它對括號配對的理解，幫你把邊界算對
      巢狀無所謂——它認得配對
```

一般編輯器你也能雙擊選一個 word、或有些能選括號內。但 Vim 把它**正交化**了：任何 operator（`d y c v`）× 任何 text object（`w ( { [ " ' p t`）× inner/around，自由組合出幾十種精準操作，用一致的語法。你學會 `i{` 一個概念，`di{`/`yi{`/`ci{`/`vi{` 全都會了。這種「少數規則組合出大量能力」正是 Vim 讓讀碼摩擦趨近於零的原因。

| n | `vi[` / `va[` | 選中中括號內 / 含括號 |

| n | `yi{` / `yi(` / `yi"` | 複製 block / 參數 / 字串內容（抄去筆記或搜尋） |

## 對比與取捨

| 你想做的事 | 手動做法 | text object 做法 |
|---|---|---|
| 看一個 if block 涵蓋範圍 | `V` 一路 `j` 數 `}` | `vi{`（一鍵，配對正確） |
| 找函式的結束 `}` | 捲動找 | 游標在 `{` 上按 `%` |
| 抄一個字串去搜尋 | 手動框選字串內容 | `yi"` |
| 選中整組參數 | 從 `(` 拖到 `)` | `vi(` 或 `va(` |
| 看巢狀 block 的每一層 | 反覆數括號 | `vi{` 後連按 `i{` 往外擴 |
| 選一個 identifier | 雙擊 / 拖 | `viw` |

## 踩雷集錦

1. **`vi{` 但游標不在任何 `{}` 內**，結果什麼都沒選中或選錯。text object 需要游標**在那個結構的範圍內**。想選某函式體，游標要先在那函式裡（隨便哪行都行），不能在函式外。
2. **搞混 `i` 和 `a` 導致多選/少選一個字元**。`ci"` 改字串內容（留引號），`ca"` 連引號一起沒了——如果你只想換字串內容卻用了 `a`，就把引號也刪了。讀碼看範圍時 `i`（乾淨）通常是你要的。
3. **`%` 在非括號字元上不會跳到「最近的括號」**——它只在游標**正好停在括號上**時，或當前行後方有括號時才跳。想從一行中間跳到括號，先 `f{` 或 `f(` 落到括號上，再 `%`。（treesitter textobjects，Part 3 Ch 14，能放寬這個限制。）
4. **`vi{` 在只有一行的 block 上**（如 `if (x) { return 1; }`）選的是那行內容——沒問題，但初學者常以為 text object 只對跨行 block 有效。它對單行、多行、巢狀都有效。
5. **忘了 visual mode 裡能重複 text object 擴展選取**。很多人 `vi{` 選錯層（選到內層），就 `Esc` 重來。其實在 visual 裡再按一次 `i{` 就往外擴一層，不用重來。

## 進階：再往深一層

- **內建 text object 是「語法無知」的**：`i{` 只認字元配對，不認 C 語法。它不知道「函式」「參數」是什麼概念，只知道括號配對。這在多數情況夠用，但遇到字串裡的 `{`、註解裡的括號會被誤配。**Part 3 的 treesitter textobjects（Ch 14）解決這個**——它用真正的語法樹提供 `if`(function inner)、`ia`(argument) 這種「懂 C 語意」的 text object，例如 `vif` 選整個函式體（不用你把游標放在 `{` 上），`vaa` 選一個完整參數。內建 text object 是地基，treesitter 版是升級。
- **`ip`/`ap`（段落）意外好用**：寫得好的 C 用空行分隔邏輯段。`vip` 常常剛好選中「一個函式」或「一組相關的宣告」，是零設定就有的粗略「函式選取」。配 `yip` 複製一整段去筆記。
- **text object 可以自訂**：透過 plugin（如 `nvim-various-textobjs`）能加 `ii`(indent，同縮排區塊，讀 Python 很讚)、`ir`(regex 定義的區塊) 等。讀碼機器不一定需要，但知道「text object 是可擴充的」有助你理解為什麼它是 Vim 生態的核心抽象。

## 本章重點整理

- text object 是**語意化選取**：你說「這個 block / 這組參數 / 這個字串」，Vim 幫你算對邊界——取代「從這到那」的手動框選。
- 語法是句子：**operator（`d y c v`）+ 修飾（`i` inner / `a` around）+ text object（`{ ( [ " w p`）**。學一次組合全通。
- 讀者最該練成反射的：**`vi{`（選整個 block 看範圍）**、**`%`（跳配對括號、找 block 結束）**、**`yi"`（抄字串去搜尋）**。
- `i`（不含界符，乾淨看內容）vs `a`（含界符，完整單位搬移）——讀碼看範圍多用 `i`。
- 內建 text object 只認字元配對（語法無知）；Part 3 的 treesitter 版懂 C 語意，是它的升級。
