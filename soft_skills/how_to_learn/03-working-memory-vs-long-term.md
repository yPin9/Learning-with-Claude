# Ch 3 — 工作記憶 vs 長期記憶

> 你的大腦有兩個記憶系統，**特性完全不同**。把它們搞混，你的學習策略就會錯。這一章講這兩個系統的差別、為什麼你會「讀完就忘」、以及為什麼大腦設計成這樣是合理的。

## 兩個記憶系統

大腦的記憶可以簡化成兩個系統：

```
感官輸入 → [工作記憶] ← 思考、處理
                ↓ （會掉光）
           [長期記憶]（事實、技能、經驗）
                ↑ （需要提取）
```

### 工作記憶（Working Memory）

你**當下**意識到的東西、正在處理的資訊。

- **容量極小**：Miller 1956 的經典研究說「7±2」個單位；更新的研究認為是 **4±1** 個
- **持續時間極短**：幾秒到幾十秒
- **不主動複習就消失**
- **可以主動操作**（你能思考、組合、推理）

例：你心裡默算「13 × 17」。「13」、「17」、中間計算步驟都在工作記憶裡。算完之後你可能就忘了中間步驟。

### 長期記憶（Long-Term Memory）

**已經儲存**到腦中的知識、技能、事件。

- **容量極大**：事實上沒有明確上限
- **持續時間**：幾分鐘到一輩子
- **不需要意識持續維持**
- **需要主動提取才能「回到」工作記憶**

例：你知道台灣首都是台北、你會騎腳踏車、你記得去年的生日。這些都在長期記憶裡，平常你不意識它們，需要時才提取。

## 容量：4±1 vs 無限

工作記憶的容量是**整個學習科學最重要的限制**。

**「4±1」的含義**：

你一次能**主動思考、處理**的「資訊單位」大概只有 3–5 個。

超過這個數，其他東西就會從工作記憶中掉出去（forgotten）。

**實驗**：

- 給你看 5 個隨機數字 —— 你能記住
- 給你看 10 個隨機數字 —— 你只記住 4–5 個
- 給你看 15 個隨機數字 —— 還是 4–5 個

這個限制**不會因為智力提高而顯著提高**。愛因斯坦的工作記憶跟你差不多。

## 一個關鍵概念：chunking（分塊）

**既然工作記憶只能容納 4±1 個單位，為什麼人能做複雜的事？**

答案：**chunking** —— 把多個元素組合成一個「單位」。

**例**：

- 「2024」記成四個數字（2, 0, 2, 4）= 4 個單位
- 「2024」記成「今年年份」= 1 個單位
- 「2024」記成「AI 熱潮第二年」= 1 個單位（包了更多意義）

**chunking 的威力**：

- 新手下棋看棋盤：看到 30 多個棋子，工作記憶超載
- 大師下棋看棋盤：看到「某某開局的第 15 手變化」= 1 個 chunk

**大師的工作記憶容量跟新手一樣**（4±1）。但大師的每個 chunk 包了更多資訊。

### 為什麼 chunking 對學習關鍵

這意味著：**學習的核心，是把散亂的資訊 chunk 成更大的單位**。

一個領域的專家 ≠ 記住更多資訊。
一個領域的專家 = **把同樣的資訊 chunk 到更大、更有意義的單位**。

**實例**：

- 新手程式員看一段 Python 程式碼：每一行要慢慢讀、理解語法、查變數
- 資深程式員看同樣程式碼：一眼看出「這是個 LRU cache 的實作」

差別不在智力，在**腦中既有的 chunk**。

**學習的目標之一**：**累積你領域的 chunks**，讓你的工作記憶可以處理越來越複雜的東西。

## 長期記憶的兩種類型

長期記憶進一步分兩種：

### 陳述性記憶（Declarative Memory）

**可以用語言表達**的知識。

進一步分：

- **語義記憶**（Semantic）：事實、概念（「水的化學式是 H₂O」）
- **情節記憶**（Episodic）：個人經驗（「去年生日我去了鹿港」）

### 程序性記憶（Procedural Memory）

**動作、技能**的記憶，難以用語言描述。

- 騎腳踏車
- 打字
- 鋼琴指法
- 開車

**關鍵差別**：

| 維度 | 陳述性 | 程序性 |
|---|---|---|
| 獲取方式 | 閱讀、聽 | 練習、重複 |
| 表達方式 | 說出來 | 做出來 |
| 遺忘速度 | 快（幾天到幾週） | 極慢（幾年到幾十年） |
| 受損腦區 | 海馬迴 | 基底神經節、小腦 |

**實例**：

- 學 Python 的**語法規則** = 陳述性（要讀、要背）
- 寫 Python 程式的**流暢度** = 程序性（要練、要做）

**學程式**、**學樂器**、**學一個工具** 都**同時**需要兩種學習：知識 + 技能。Ch 22 會詳細講這個分化。

## 為什麼會「讀完就忘」

理解了兩個系統，「讀完就忘」的現象變得清楚：

```
你讀書 → 內容進入「工作記憶」
    ↓（沒做深度處理）
幾分鐘後 → 工作記憶清空
    ↓
    （什麼都沒有留在長期記憶）
結果：什麼都沒記住
```

**關鍵**：資訊**必須從工作記憶轉移到長期記憶**，才是真的學會。

這個轉移**不會自動發生**。需要條件：

1. **足夠的注意力**（工作記憶裡停留夠久）
2. **深度編碼**（Ch 2 講過）
3. **提取練習**（Ch 2 講過）
4. **睡眠鞏固**（Ch 6 會講）

**多數人的學習失敗在這個轉移**：資訊進了工作記憶、但從來沒轉進長期記憶。

## 工作記憶限制的實務意義

理解 4±1 的限制，有很多實務含義：

### 實務 1：不要超載

學新東西時，**一次處理的新概念不該超過 4 個**。

如果一個教材一次丟 10 個概念給你，你能做的是：

- 先處理 3–4 個，把它們 chunk 到長期記憶
- 再處理下 3–4 個
- 最後整合

**多數人試圖一次消化所有東西 → 結果一個都沒消化**。

### 實務 2：分段式學習

**Pomodoro 技巧**（25 分鐘學習 + 5 分鐘休息）的神經學基礎：

工作記憶會疲勞。長時間連續輸入而不停下整理，資訊只是在流動不會積累。

分段讓你有時間：
- 讓工作記憶清空
- 讓大腦做**隱性的 chunking**（背景處理）
- 準備下一段的容量

### 實務 3：不要同時學多個新主題

很多人犯這個錯：同時學 Python + C++ + JavaScript + Rust。

**工作記憶會把概念混淆**。你學到的每個語言的概念會互相串味。

**正確做法**：一段時間只深入一個。**3–6 個月深入一個**，超過 3 個並行幾乎一定失敗。

Ch 28 會談長期的學習節奏規劃。

### 實務 4：先建結構，再填細節

**新手的錯誤**：先學一堆細節，希望自己後來會 figure out 整體結構。

**有效做法**：先了解領域的**骨架**（chunks 的骨架），再填細節。

這就是為什麼讀一本新書時，**先看目錄 + 前言 + 結論** 比直接從第一章開始更有效。

## 長期記憶的建立需要時間

很多人的另一個錯誤認知：「我今天花了 4 小時學 XXX，應該就學會了吧？」

**不，長期記憶的建立是一個過程**，需要：

- 多次重複的提取
- 時間間隔（睡眠）
- 與其他知識的連結

**一般的時間尺度**：

- 幾分鐘：工作記憶中
- 幾小時：短期記憶鞏固中（fragile）
- 幾天到幾週：正在轉入長期記憶（還會忘很多）
- 幾個月：穩定的長期記憶
- 幾年：幾乎永久

**這意味什麼**：**當天的成就感不是學習的指標**。你當天覺得學得很好，不代表一個月後記得。反之，當天覺得一團糟的學習，如果有後續的鞏固，反而可能記得清楚。

## 一個誤區：「我沒有記憶天份」

很多人覺得自己「記憶力不好」。

**事實上**，**所有健康大腦的記憶能力差別沒那麼大**。

你覺得自己記憶差，多半是：

- 方法錯了（Ch 1）
- 沒有做提取練習（Ch 2）
- 沒有用間隔重複（Ch 9）
- 注意力不夠（工作記憶沒真的處理資訊）
- 睡眠不足（Ch 6）

「記憶力」不是一個天生固定的容量，是一個**技能 + 方法**的組合。

**那些記性好的人**通常不是大腦特別好，是他們**有系統地使用間隔重複、主動回憶、有強烈動機**。

你也可以。

## 一個技能性能力：metacognition（元認知）

**元認知** = **對自己認知的認知**。也就是「知道自己知道什麼、不知道什麼」。

這是學習的一個關鍵技能：**知道自己處於兩個記憶系統的哪裡**。

問自己：

- 「這個東西我能**馬上**拿出來用，還是需要想？」
- 「如果我現在合上書，我能不能寫出剛才那段的重點？」
- 「一個月後我還記得這個嗎？」

元認知好的人知道：

- **「我以為我懂了」** 和 **「我真的懂了」** 的差別
- 什麼時候該停下來做提取練習
- 什麼時候可以 move on

**元認知差的人**會被流暢性錯覺騙，以為自己學會了但其實沒有。

這門課一直在培養你的元認知。每個「自我檢核」都是在練習這件事。
