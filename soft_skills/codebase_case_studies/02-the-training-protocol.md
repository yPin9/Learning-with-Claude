# Ch 2 — 訓練協定：限時攻堅 → 萃取 pattern → 費曼複述

> **目標**：把上一章的「刻意累積 chunk 庫」從口號變成一套可執行的 SOP。這門課每個 codebase 都跑同一套三階段循環：限時偵察攻堅（自己撞牆）→ 對照與深挖（讀教材補漏）→ 萃取 + 費曼複述（結晶進 LTM）。這章給每個階段的**具體產出物**（架構地圖長怎樣、pattern 卡片長怎樣、費曼複述怎麼檢核），並講清楚為什麼「先自己撞牆再看解答」在認知科學上比「直接讀解答」有效。跑完這章，你手上就有一份日後攻任何 codebase 都能套的訓練模板。

## 為什麼需要這個？

上一章給了結論：讀碼變快 = 擴充 LTM 的 chunk 庫，而 chunk 庫靠反覆真讀經典 code 養大。但「反覆真讀」四個字太滑了——**怎麼讀，決定你有沒有真的長 chunk。**

反例很常見。很多人「讀」一個開源專案的方式是：打開專案的架構文件，讀作者寫的導覽，看幾張漂亮的分層圖，「喔原來 SQLite 是這樣分層的」，關掉，感覺自己懂了。三週後遇到另一個資料庫，他一個 chunk 都沒長出來——因為他**被動接收了別人整理好的結論，自己沒攻過**。這等於看健身教學影片而不進健身房：你知道深蹲怎麼做，肌肉沒長。

這門課的核心方法論就是要擋掉這種假讀。做法是把每個 codebase 的訓練固定成一套 SOP，強制你：**先自己在痛苦中撞出一張地圖，再拿教材對照補漏，最後把撞出來的東西結晶成 pattern。** 這章講清楚這套 SOP 的每一步、每一步的產出物、以及它為什麼有效。

## 先建立直覺：一個 codebase = 一次三階段循環

```
 ┌─────────────────────────────────────────────────────────────┐
 │ 階段 1：限時偵察攻堅（60 分鐘，不看教材，自己撞）            │
 │   用 reading_code SOP 自己建架構地圖                          │
 │   產出：一張你親手畫的架構地圖 + 一串「我不確定」的問號       │
 └─────────────────────────────────────────────────────────────┘
                          │  時間到，鈴響，停手
                          ▼
 ┌─────────────────────────────────────────────────────────────┐
 │ 階段 2：對照與深挖（讀教材，補你漏掉的路徑）                 │
 │   讀本課這個 Part 怎麼攻、補漏掉的路徑、讀關鍵機制的深挖章    │
 │   產出：地圖上的紅筆修正 + 想通的問號                        │
 └─────────────────────────────────────────────────────────────┘
                          │  合上教材
                          ▼
 ┌─────────────────────────────────────────────────────────────┐
 │ 階段 3：萃取 + 費曼複述（結晶進 LTM）                        │
 │   寫下認出的 pattern 卡片；對空氣把核心機制講一遍            │
 │   產出：2–4 張 pattern 卡片 + 一次講得順（或講不順）的複述   │
 └─────────────────────────────────────────────────────────────┘
```

六個 Part（Lua / SQLite / nginx / git / CPython / PostgreSQL）各跑一次這個循環。每個 Part 的章節編排就是照這個循環設計的：偵察章對應階段 1、機制深挖章對應階段 2、萃取章對應階段 3、練習章是階段 1 的加強版（追一條完整路徑）。你只要知道每翻開一個新 Part，就是重跑一次這三步。

## 階段 1：限時偵察攻堅——自己撞牆 60 分鐘

**規則：拿到一個新 codebase，先給自己 60 分鐘，不准打開本課教材，用 `reading_code` 的 SOP 自己建一張架構地圖。** 時間到就停，不管建到哪。

為什麼限時？因為讀碼是速度技能，無限時間會讓你退回「逐行讀到懂為止」的新手模式（上一章講過這是最糟的讀法）。時限逼你做策略取捨：60 分鐘不可能讀懂 2 萬行 Lua，你被迫**只掃 beacon、只追幾條關鍵路徑、大膽跳過**——這正是要練的肌肉。

這 60 分鐘照 `reading_code` 的 SOP 走，具體動作：

1. **先讀專案的自述再讀 code**（`reading_code` Ch 5 的偵察）：`README`、`doc/` 目錄、原始碼頂層註解。Lua 的 `README`、SQLite 的 `arch.html`、git 的 `Documentation/technical/`——這些是作者親自埋的 top-down 假設骨架，10 分鐘讀它省你一小時瞎撞。
2. **掃目錄結構找分層**：`ls src/` 看檔名，好專案的檔名就是 beacon（Lua 的 `lvm.c`=VM、`lgc.c`=GC、`ltable.c`=table；一眼分工）。
3. **找 entry point 與主迴圈**（`reading_code` Ch 6）：`main` 在哪、主迴圈長怎樣。Lua 你會找到 `luaV_execute` 那個 dispatch loop、nginx 你會找到 event loop。
4. **對幾個關鍵檔案掃 beacon 建假設**（`reading_code` Ch 10 假設驅動）：不讀 body，只看函式名、struct 名、關鍵字串，寫下「我猜這個檔在幹嘛」。
5. **全程外化**：把上面所有東西畫成一張架構地圖，寫下每個「我不確定」的問號。腦中讀不算讀（上一章 working memory 只有 4 格，不外化必爆）。

### 產出物：架構地圖長什麼樣

架構地圖不是藝術品，是你 60 分鐘攻堅的外化殘骸。它該長這樣（以 Lua 為例，這是階段 1 你自己會撞出來的粗胚，不是標準答案）：

```
 Lua v5.4.7  ── 我的 60 分鐘偵察地圖 ──

 entry: lua.c main() → 互動式 REPL / 跑 script
                │
                ▼
 [編譯] llex.c(?) 詞法 → lparse.c(?) 語法 → lcode.c(?) 產 bytecode
                │  ← 我沒細追，只看到 luaY_parser 這個名字
                ▼
 [執行] lvm.c luaV_execute  ← ★核心！一個大迴圈跑 opcode
                │            猜：register-based VM（看到很多 R(A) 巨集）
                ├── 值：lobject.h TValue（tag + union？沒確認）
                ├── table：ltable.c（array + hash 混合？看到兩個部分）
                └── GC：lgc.c（incremental？看到 "gcstate" 這種字）

 問號（階段 2 要解）：
   ? OP_CALL 一個函式呼叫的完整流程是什麼
   ? luaV_execute 到底怎麼 dispatch——switch 還是 computed goto?
   ? GC 什麼時候被觸發、跟 luaV_execute 怎麼交錯
   ? TValue 的 tag 到底怎麼編碼
```

重點在**那串問號**。問號是你自己撞牆撞出來的知識邊界——你知道自己不知道什麼。這比任何整理好的文件都珍貴，因為它是**你的** working memory 在 60 分鐘裡真的卡住的地方。階段 2 讀教材時，你會帶著這串問號去讀，讀起來像「終於解惑」而不是「被動接收」——這個差別就是 chunk 進不進得了 LTM 的差別。

## 階段 2：對照與深挖——讀教材補漏

時間到、地圖畫完、問號列好，**現在**才打開本課這個 Part 的章節。做兩件事：

**1. 對照：拿教材的攻法比對你的地圖。** 你漏了哪條路徑？哪個假設猜錯了（教材說 TValue 其實是這樣編碼，你猜錯了）？哪個檔案你以為不重要其實是核心？用紅筆在你的地圖上修正。**修正的地方就是你 chunk 庫的缺口**——你之所以漏或錯，是因為 LTM 沒有那個 pattern，現在補上。

**2. 深挖：帶著階段 1 的問號讀機制深挖章。** 每個 Part 有 2–3 個機制深挖章（如 Lua 的 Ch 4 register VM、Ch 6 incremental GC），它們帶你讀關鍵路徑、引用真實 source 的真函式真行號。你階段 1 列的問號——「OP_CALL 的完整流程」「dispatch 是 switch 還是 computed goto」——在這裡被一條一條解掉。**因為問題是你自己撞出來的，答案讀起來會黏在你腦裡**，而不是左耳進右耳出。

深挖時的紀律（延續 Ch 0 的鐵律）：**教材說某個函式在 `lvm.c` 的 `luaV_execute`，你的動作是 `rg` 它、跳過去、親眼確認。** 教材是帶路的，不是替你讀的。你在階段 1 已經 clone 了釘死版本（Ch 0），行號對得上，親眼核對只要幾秒，但這幾秒是把「教材說的」變成「我看過的」——後者才進 LTM。

### 產出物：修正過的地圖 + 想通的問號

階段 2 的產出不是新東西，是**階段 1 產出的升級版**：紅筆修正過的架構地圖，加上一串從問號變成句號的理解。理想狀態是你回頭看階段 1 的問號清單，每一條都能劃掉並在旁邊寫一句話答案：

```
   ? luaV_execute 怎麼 dispatch?
     → computed goto（vmdispatch 巨集），比 switch 快，因為省了範圍檢查
       + 每個 case 結尾直接跳下一個 opcode。這是「VM dispatch」pattern 的一種變體。
   ? GC 什麼時候觸發?
     → 分配記憶體時檢查 debt，超過就跑一步 incremental GC（luaC_step）。
       GC 和執行交錯，不 stop-the-world。這是「incremental GC」pattern。
```

注意這兩個答案末尾——我已經在替它們**命名 pattern** 了（「VM dispatch」「incremental GC」）。這是通往階段 3 的橋：一旦你能替一段機制取一個 pattern 名字，它就準備好被萃取成卡片了。

## 階段 3：萃取 + 費曼複述——結晶進 LTM

前兩階段你建了理解。但理解會流失（上一章 spacing effect）。階段 3 是把理解**結晶成可長期保存、可遷移的形式**，這一步做不做，決定你三週後還記不記得。

**合上教材。** 這是硬規定——萃取和複述都必須在教材關閉的狀態下做，因為它們靠的是**主動回想（active recall）**，不是被動重讀。攤開教材抄一遍 pattern，chunk 進不了 LTM；合上教材自己擠出來，才進。

### 產出物一：pattern 卡片

這是這門課最重要的產出物，每個 Part 的萃取章都會用，Ch 30 會把六個 Part 的卡片收斂成一張總字典。卡片格式固定四欄：

```
┌─────────────────────────────────────────────────────────────┐
│ Pattern 名  ： register-based VM 的 opcode dispatch loop       │
├─────────────────────────────────────────────────────────────┤
│ 長怎樣的 beacon：                                             │
│   一個大 for(;;)/while(1)，裡面 fetch 一條指令 → 解出 opcode  │
│   → 依 opcode 跳到對應處理。信號：computed goto 表 / 巨大     │
│   switch / vmcase 巨集；指令操作 R(A),R(B),R(C) 這種暫存器欄位 │
├─────────────────────────────────────────────────────────────┤
│ 在哪個 codebase 見過：                                        │
│   Lua v5.4.7 lvm.c:luaV_execute（computed goto 版）           │
├─────────────────────────────────────────────────────────────┤
│ 可遷移到哪：                                                  │
│   SQLite VDBE（Part 2 Ch 9，同樣是 dispatch loop 但 stack-ish）│
│   CPython ceval.c（Part 5 Ch 23，第三個 VM）                  │
│   任何 bytecode 直譯器 / regex 引擎 / 狀態機驅動的系統        │
└─────────────────────────────────────────────────────────────┘
```

四欄各有作用：

- **Pattern 名**：這是 LTM 裡的索引 key。取得越精準（不是「VM」而是「register VM 的 dispatch loop」），日後越容易被 beacon 觸發提取。
- **長怎樣的 beacon**：這欄是 chunk 的「觸發條件」——寫下什麼形狀/命名/結構會讓你認出這個 pattern。這是把上一章「beacon 觸發 chunk」變成可查的清單。
- **在哪個 codebase 見過**：具體 anchor（真檔案:真函式），讓卡片可回溯、可重讀複習。附釘死版本讓行號對得上。
- **可遷移到哪**：這欄是 pattern 卡片的靈魂。寫下「這個 pattern 還會在哪出現」，就是在**預先建立遷移連結**——所以你在 Part 2 讀 SQLite VDBE 時，會「啊這是同一個 pattern」而不是從頭學。Ch 27（三個 VM 橫向對照）就是這欄預先鋪的遷移在該章一次引爆。

每個 codebase 萃取 2–4 張卡片就好，寧精勿多。灌一堆你其實沒真懂的卡片沒用——只寫你**在階段 2 真的追過路徑、親眼確認過**的 pattern。

### 產出物二：費曼複述

pattern 卡片檢驗「你認得出形狀」，費曼複述檢驗「你懂機制怎麼運作」。做法（`reading_code` Ch 36 費曼測試的實戰版）：

**合上教材與卡片，對著空氣（或一隻假想的資淺同事）把這個 codebase 的核心機制從頭講一遍。** 例如講 Lua：「你寫的 Lua script 先被編譯成 bytecode，bytecode 是給一個 register-based 的虛擬機跑的。這個 VM 的心臟是 `luaV_execute`，一個大迴圈，每一圈 fetch 一條 bytecode、解出 opcode、用 computed goto 跳到對應處理……講到函式呼叫時，VM 會……」

**檢核（費曼測試的核心）：講不順的地方，就是你沒真懂的地方。** 這比任何自我感覺都準。你會發現有些你以為懂的地方，一開口就卡——「呃，GC 到底什麼時候被觸發來著？」——那個卡點就是 chunk 沒成形。具體檢核三問：

1. **有沒有卡殼、跳過、含糊帶過的地方？** 那裡回去重讀階段 2 的對應段落。
2. **能不能不用術語、用比喻講給不懂的人？** 講不出比喻通常代表你只記得術語、沒建 mental model。
3. **講的順序對不對？** 如果你得跳來跳去、「喔對還有一件事」，代表你腦中的 mental model 結構還沒理順。

費曼複述講不順就回階段 2，講順了這個 Part 才算真的通過。這也是為什麼每個 Part 結束 README 都要你「對著空氣把核心機制講一遍」——不是形式，是驗收。

## 底層機制：為什麼「先自己撞再看解答」比「直接讀解答」有效

這套 SOP 最反直覺的設計是階段 1——**明明有教材，卻逼你先花 60 分鐘自己痛苦地撞**。為什麼不直接讀教材省時間？認知科學給了三個硬理由：

**1. desirable difficulty（合意困難）。** Bjork 夫婦的研究發現：學習時適度的困難，反而讓記憶更牢、更持久、更可遷移。太順的學習（被動讀整理好的答案）產生「流暢的錯覺」——你當下感覺懂了，但沒真的建構記憶。自己撞牆是困難的，但正是這個困難逼你的大腦**主動建構**理解，建構出來的才進 LTM。跳過階段 1 直接讀教材，省下的時間是用「三週後全忘光」換的。

**2. 主動回想 vs 被動閱讀。** 記憶研究裡最穩固的結論之一：主動從腦中提取資訊（testing effect），比被動重讀，記得牢得多。階段 1 你在做的正是主動提取——你逼自己從既有 chunk 庫裡擠出假設（「這應該是 register VM」），這個「擠」的動作本身就在強化記憶通路。被動讀教材的地圖，你的大腦是接收端，通路沒被激活。這也是為什麼階段 3 硬性要求「合上教材」——同一個原理。

**3. 假設驅動讓後續閱讀有掛勾點。** 這連到 `reading_code` Ch 10（假設驅動讀碼）。階段 1 你撞出的那串問號和猜錯的假設，在階段 2 讀教材時變成**掛勾點**：新資訊不是懸空進來的，是掛到你已有的問號/假設上（「喔原來我猜的 TValue 編碼錯了，實際是這樣」）。有掛勾點的資訊記得牢；懸空進來的（直接讀教材、沒有問題在等）左耳進右耳出。認知科學稱這為 elaborative encoding——新知識和既有結構連結越多，記得越牢，而你自己的假設就是最好的既有結構。

```
 直接讀解答                        先撞牆再看解答（本課）
 ┌──────────────┐                 ┌──────────────┐
 │ 讀教材地圖    │                 │ 60 分鐘自己撞  │ ← 主動提取(testing)
 │ 「喔原來如此」│                 │ 撞出問號+錯假設│ ← desirable difficulty
 │  當下感覺懂    │                 └──────┬───────┘
 └──────┬───────┘                        │ 帶著問號
        │  被動接收                        ▼
        ▼                          ┌──────────────┐
   流暢的錯覺                       │ 讀教材=解惑    │ ← 有掛勾點
   三週後全忘                       │ 新知掛到舊假設 │   elaborative
                                   └──────┬───────┘
                                          ▼
                                    chunk 進 LTM，記得牢
```

一句話：**60 分鐘的自己撞牆不是浪費，是把後面讀教材的效果從「看過」升級成「刻進去」的必要投資。** 這門課所有「先自己做再看答案」的設計（先建地圖再讀偵察章、先寫 pattern 再讀萃取章、先講一遍費曼測試）都是同一個原理。

## 走一遍完整循環：以 Part 1（Lua）為例

把三階段串起來跑一次，你就知道實際體感是什麼。以你翻開 Part 1 的第一天為例：

**第 0 分鐘（階段 1 開始）**：你 clone 好 `lua v5.4.7`（Ch 0 已做），設一個 60 分鐘鬧鐘，**把本課 Ch 3–7 全部關掉**。先花 8 分鐘讀 Lua 的 `README` 和 `doc/`，知道 Lua 是個嵌入式語言、原始碼在 `src/`。

**第 8–20 分鐘**：`ls src/`，靠檔名 beacon 猜分工——`lvm.c`(VM)、`lparser.c`(語法)、`llex.c`(詞法)、`lgc.c`(GC)、`ltable.c`(table)、`lobject.h`(值)。你在地圖上把這些畫成方塊。

**第 20–50 分鐘**：`rg "int main"` 找到 `lua.c` 的入口，順著追到「執行」這條路徑，`rg "luaV_execute"` 跳進 `lvm.c`，看到一個大迴圈裡滿是 `vmcase` 巨集和 `R(A)` 這種形狀——你的 chunk 庫（如果讀過 Ch 1）會觸發「這是 register VM 的 dispatch loop」。但你不確定 dispatch 到底怎麼做的，也不確定函式呼叫怎麼走。寫下問號。

**第 50–60 分鐘**：外化——把地圖畫完（就是前面那張 Lua 地圖的樣子），列出四個問號。鬧鐘響，**停手**。你現在有一張粗地圖 + 四個你親手撞出來的問號。這 60 分鐘你多半覺得挫折、覺得「我還有一堆沒懂」——**這個挫折感正是 desirable difficulty 在起作用，別逃避它。**

**第 60 分鐘+（階段 2）**：**現在**打開 Ch 3（Lua 偵察）對照——你會發現教材確認了你大半猜對，但點出你漏了 `lcode.c`（bytecode 產生）這條路徑，也修正了你對 table 的誤解。紅筆改地圖。接著帶著「dispatch 怎麼做」這個問號讀 Ch 4（register VM），它帶你追 `luaV_execute` 的 computed goto，你的問號當場變句號。全程 `rg` 教材提到的每個函式，親眼確認。

**階段 3**：**合上 Ch 3–7**。憑記憶擠出兩張 pattern 卡片（「register VM dispatch loop」「incremental GC step」），「可遷移到哪」欄填上你的預測（SQLite VDBE、CPython ceval）。然後對著空氣講一遍「一段 Lua code 怎麼從原始碼跑到結果」，講到 GC 觸發時卡住了——回 Ch 6 重讀那段，再講一次，順了。**這個 Part 才算通過。**

整套跑下來約 3–4 小時。比「直接讀 Ch 3–7」慢，但三週後你對 register VM 的 dispatch loop 還認得出來，而直接讀的人早忘了。這就是這門課要你付的價，和它換回來的東西。

## 對比與取捨

| 維度 | 假讀（直接讀作者的架構文件/教材） | 本課三階段協定 |

| 階段 1 | 跳過，直接看整理好的結論 | 60 分鐘自己撞牆，撞出問號 |

| 讀教材時 | 懸空接收，無掛勾點 | 帶問號去解惑，有掛勾點 |
| 產出物 | 一種「我懂了」的感覺 | 地圖 + pattern 卡片 + 費曼複述 |

## 踩雷集錦

1. **錯誤直覺**：「我時間有限，直接讀教材的攻法最快，階段 1 自己撞是浪費。」
   **正確認識**：階段 1 撞出的問號和錯假設，是後面讀教材的掛勾點。跳過它，教材的內容懸空進你腦裡，看過即忘。你省的 60 分鐘，是用「三週後這個 codebase 對你又變回陌生」換的。desirable difficulty 不是虐待，是記憶得以形成的條件。

2. **錯誤直覺**：「pattern 卡片抄教材萃取章就好，反正內容一樣。」
   **正確認識**：萃取必須**合上教材、自己從腦裡擠**。抄一遍是被動閱讀，chunk 不進 LTM；自己擠出來（哪怕擠得沒教材漂亮）才觸發主動回想的記憶強化。卡片的價值不在文字漂不漂亮，在「這是你自己想出來的」。

3. **錯誤直覺**：「我讀完覺得都懂了，費曼複述是多餘的儀式。」
   **正確認識**：「覺得懂」是流暢的錯覺，最不可靠。費曼複述一開口就把假懂暴露出來——你會在某個地方卡殼「呃這裡怎麼運作來著」，那個卡點就是沒真懂。不開口講，你永遠不知道自己哪裡是空的。

4. **錯誤直覺**：「60 分鐘不夠讀懂整個 codebase，所以階段 1 沒意義。」
   **正確認識**：階段 1 的目標**不是**讀懂全部——2 萬行 Lua 60 分鐘不可能讀懂。目標是建一張粗地圖 + 撞出問號，並且逼你練「限時取捨、只追關鍵路徑、大膽跳過」的速度肌肉。想讀懂全部才是錯的（`reading_code` Ch 11 收斂到你要的 200 行）。

5. **錯誤直覺**：「卡片『可遷移到哪』那欄我還沒讀後面的 codebase，填不出來，先空著。」
   **正確認識**：這欄正是要你**預測**——就算你還沒讀 SQLite，你也可以寫「這個 VM dispatch pattern 應該會在其他直譯器出現」。這個預測本身就是遷移連結的種子，等你 Part 2 真讀到 VDBE，「啊被我料中」的那一刻，chunk 遷移就完成了。空著就浪費了預建連結的機會。

## 進階：再往深一層

- **這套協定就是刻意練習（deliberate practice）的落地。** Ericsson 的刻意練習理論要求：明確目標、超出當前能力的難度、即時回饋、反覆修正。三階段剛好對上——階段 1 是超出能力的挑戰（限時攻堅硬 codebase）、階段 2 是即時回饋（教材對照你哪裡錯）、階段 3 是修正與固化。這門課本質上是把讀碼變成一項可刻意練習的技能，而不是「讀多了自然會」的玄學。

- **pattern 卡片是你的 spaced repetition 材料。** 上一章提過 chunk 需要間隔複習才固化。把 pattern 卡片存成一個檔案（或丟進 Anki 之類的間隔複習工具），每隔一段時間重看「beacon 長怎樣」那欄、試著回想在哪見過——這是把一次性的閱讀變成長期記憶的關鍵。Ch 30 收斂出的總字典，就是你整門課的複習卡組。

- **限時的時鐘會逼出你真實的策略。** 沒有時限，你會退回「讀到懂為止」的舒適區，永遠練不出取捨。刻意設一個略嫌緊的時限（偵察 60 分鐘、追一條路徑 30 分鐘），逼自己在資訊不足時下判斷、猜假設、跳過細節——這種「在不確定下決策」的能力，正是 onboarding 一個新專案時最值錢的東西，也是本課練習章全部限時的原因。

## 本章重點整理

- 每個 codebase 跑同一套**三階段循環**：限時偵察攻堅（自己撞 60 分鐘）→ 對照與深挖（讀教材補漏）→ 萃取 + 費曼複述（結晶進 LTM）。六個 Part 各跑一次。
- **階段 1 產出**：親手畫的架構地圖 + 一串自己撞出來的問號。問號是你的知識邊界，是階段 2 的掛勾點。
- **階段 2 產出**：紅筆修正過的地圖 + 想通的問號。紀律：教材說某函式在哪，`rg` 過去親眼確認，教材是帶路不是替讀。
- **階段 3 產出**：合上教材寫的 **pattern 卡片**（名 / beacon / 在哪見過 / 可遷移到哪，每 codebase 2–4 張）+ 一次**費曼複述**（講不順=沒懂，回階段 2）。
- **為什麼先撞再看解答有效**：desirable difficulty（合意困難逼大腦主動建構）、主動回想 vs 被動閱讀（testing effect）、假設驅動給後續閱讀掛勾點（elaborative encoding）。捷徑省今天 60 分鐘，賠掉 chunk 進不進 LTM。
- pattern 卡片「可遷移到哪」欄預建遷移連結，Ch 27 三個 VM 對照一次引爆，Ch 30 收斂成總字典兼複習卡組。
