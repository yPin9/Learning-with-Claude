# Ch 25 — 技術自學的專屬策略

> 本課前 24 章的方法對所有學習通用。這一章針對一種特殊情境：**技術自學** — 工程師、程式員、技術人員自學新技術的情境。這個情境有自己的最佳實踐。

## 技術自學的特殊性

**技術自學**（programming、系統工程、資料科學、DevOps、Security 等）跟其他學習**有四個特殊點**：

### 特殊點 1：需要實作

**程式、系統、資料庫、網路** — 這些**只能做**才能學會。光讀書完全不行。

### 特殊點 2：技術變化快

- 今天最紅的 framework，3 年後可能過時
- API 常更新
- 最佳實踐會變

**你學「底層原理」的投資報酬率遠高於學「特定框架」**。

### 特殊點 3：有極好的免費資源

- **官方文件**（所有主流技術都有）
- **Stack Overflow**
- **GitHub**（學別人的 code）
- **MIT / Stanford 的 OpenCourseWare**
- **YouTube 的深度教學頻道**

**技術自學者是全世界學習資源最豐富的群體之一**。

### 特殊點 4：有客觀的回饋

- **程式能跑**：對錯很客觀
- **測試通過**：客觀驗證
- **實際用**：用戶 / 系統回饋

**技術學習的客觀性讓它特別適合 deliberate practice**（Ch 10）。

## 技術自學的三層結構

我建議把技術學習分**三層**：

### 第 1 層：理論基礎

**長期穩定的知識**：

- 演算法與資料結構
- 作業系統概念
- 網路基礎（TCP/IP、HTTP）
- 資料庫理論
- 電腦架構
- 軟體工程原則（抽象、模組化、測試）

**這些 10 年、20 年不會過時**。

**學習方法**：看 MIT / Stanford 的 OCW、讀經典教科書、做實作專案。

### 第 2 層：領域知識

**中期穩定**：

- 語言的核心（Python 的物件、JavaScript 的 event loop、C 的 pointer）
- 主流 framework 的核心概念
- 工具鏈（Git、Docker、CI/CD）
- 架構模式

**5–10 年會慢慢演化**。

**學習方法**：官方文件、權威書、做實戰專案。

### 第 3 層：具體細節

**快速變化**：

- 特定 library 的 API
- 某版本的 bug 與 workaround
- 工具的新版本的細節

**1–3 年會變**。

**學習方法**：**主要靠查詢**。只在**日常工作常用的**才記住。

## 分層的時間分配

**時間分配建議**（一個技術學習者的週時間）：

- **第 1 層**（理論）：**每週 20%**
- **第 2 層**（領域）：**每週 50%**
- **第 3 層**（細節）：**每週 30%**

**多數自學者搞反了**：

- 85% 時間追新技術的細節（React 18 的新功能、這個 library 的新版本）
- 10% 時間看 framework 概念
- 5% 時間學理論

**結果**：他們**跟上**當下的技術潮流，但**沒累積深度**。

**應該反過來**：**大量時間在基礎和框架上、定期追新但不密集**。

## 基礎理論為什麼這麼重要

**沒有底層理解**，你：

- **不能 debug 難題**（你看不懂底層發生什麼）
- **不能做架構決策**（你只會套框架）
- **容易被潮流帶**（新框架一出你就想學，沒有判斷）
- **工作能力受限**（停留在「堆疊框架」的水準）

**有底層理解**，你：

- **能看懂任何新框架**（背後的設計原則相似）
- **能在新技術出現時快速判斷**
- **能做深度 debug**
- **工作能力更強**（能設計系統，不只是實現）

**巨大的長期投資報酬**。

## 技術自學的核心動作

### 動作 1：選一個你想「真正會」的領域

**不要同時學 5 個領域**。選一個：

- Full-stack web
- 資料工程 / 資料科學
- 系統程式（C / Rust / Linux）
- 機器學習
- Security
- 行動開發

**花 2–3 年深入**，比 5 年略懂 5 個有用 10 倍。

### 動作 2：建立基礎

**先建立你領域的基礎**：

**例：想成為 Backend engineer**

- **基礎層**：演算法、資料結構、OS、網路、資料庫
- **領域層**：一個語言（深入）、一個 framework、API 設計、資料庫操作

**建議學習順序**：

1. **一個語言到流利**（Python、Go、Java 任一）— 6 個月
2. **OS + 網路基礎** — 3 個月
3. **資料結構 + 演算法**（到能過 LeetCode medium）— 3 個月
4. **資料庫** — 2 個月
5. **一個 web framework** — 3 個月
6. **系統設計** — 6 個月

**總計**：約 2 年達到 junior-to-mid level 能力。

這是一個**認真的自學者**的時間表。比一般 bootcamp 慢，但**深度遠超過**。

### 動作 3：大量寫程式

**程式員的 10000 小時**：

- 前 1000 小時：學語法、做簡單專案
- 1000–5000 小時：做中大型專案、debug 各種問題
- 5000+ 小時：能設計架構、能帶領他人

**你寫的程式行數**跟**你的能力**高度相關。

**如果你一天只寫 10 行，5 年後你寫過 15,000 行 — 不夠**。

**如果你一天寫 500 行，5 年後你寫過 900,000 行 — 這才是能力的基礎**。

**寫**。多寫。不要讀而不寫。

### 動作 4：讀好 code

**除了寫，也要讀**。

**讀好的 open source 專案的 code**：

- Redis 的 source
- SQLite 的 source
- Linux kernel 的某些部分
- React / Vue 的 source
- 你用的 library 的 source

**閱讀程式的能力**比**寫程式**還難訓練，但**極重要**。

**實用做法**：

- 挑一個你用的 library
- 讀它的 source（從 `main` 或核心邏輯開始）
- 試著理解整體結構
- 寫筆記：這個 library 怎麼設計的？

**這比看 10 個教學影片有用 10 倍**。

### 動作 5：做有挑戰性的專案

**一個你能自豪的專案** > 10 個 tutorial 跟做的東西。

**好的自學專案的特徵**：

- **解決真實問題**（自己或朋友的問題）
- **有挑戰性**（剛好超過你能力）
- **能持續維護**（不是做完就丟）
- **有用戶**（即使只有你一個）

**這樣的專案**：
- 強迫你面對真實複雜度
- 教你不只是 happy path 還有 error handling
- 讓你碰到你原本不知道的問題

**「我做過 tutorial 的 todo list」 vs 「我做過一個真的人在用的工具」** — 差 100 倍。

### 動作 6：碰到限制時補基礎

**當你做專案卡在「我不懂為什麼」**：

- 這是學底層原理的時機
- 回去讀相關的基礎（OS、網路、資料庫原理）
- **這次你有具體的錨點**（你的卡點）

這是 Project-First 的深化版。**從具體卡點倒推基礎**。

## 技術自學的建議資源

### 經典書（值得買、值得讀兩遍以上）

**基礎**：
- *Computer Systems: A Programmer's Perspective*（CS:APP）— OS + 組譯 + C
- *Designing Data-Intensive Applications* — 分散式系統
- *The Pragmatic Programmer* — 軟體工程心法
- *Clean Code* — 寫好程式碼

**特定語言**：
- Python：《Fluent Python》
- JavaScript：《You Don't Know JS》系列
- C：《The C Programming Language》（K&R）
- Rust：官方 *The Rust Programming Language* book

**演算法**：
- 《Algorithms》Sedgewick
- CLRS（厚，但權威）

### 課程資源（多數免費）

- **MIT OpenCourseWare**：6.004、6.006、6.033、6.824
- **Stanford CS**：CS106、CS161、CS229（ML）
- **Coursera / edX**：Algorithm (Princeton)
- **Harvard CS50**：入門經典

### 實戰平台

- **LeetCode**：演算法
- **HackerRank**：多樣
- **Project Euler**：數學 + 程式
- **GitHub**：做開源貢獻
- **Kaggle**：資料科學

### 持續追蹤

- **Hacker News**：技術新聞（品質高但要篩）
- **技術 Substack / blog**：依你的領域選
- **官方文件**：你用的技術的官方文件（比 blog 可靠）

## 技術自學的陷阱

### 陷阱 1：新技術追逐症

看到 Twitter 上有人談新框架 → 想學 → 學到一半下一個又來

**解法**：**每年只花 10% 時間追新**。90% 時間在基礎與已深的領域。

### 陷阱 2：Tutorial Hell（Ch 15）

一直看教學、一直不做。

**解法**：**每看 15 分鐘就停下來寫 30 分鐘 code**。

### 陷阱 3：過度設計

剛開始學就追求「乾淨的架構」「testable code」。

**解法**：**先 work，後 refactor**。初學寫爛 code 是正常的。先讓它能動。

### 陷阱 4：只跟簡單的專案

**永遠停在 tutorial 級別的專案**。

**解法**：**定期挑戰** 你覺得有點難的。

### 陷阱 5：不碰底層

**永遠只用 framework，不理解底層**。

**解法**：**每年花時間**讀底層（OS、網路、資料庫的原理）。

### 陷阱 6：孤軍奮戰

**自學者沒有同儕，沒有人挑戰你**。

**解法**：
- **加入社群**（Reddit、Discord、本地 meetup）
- **開源貢獻**（被 maintainer review）
- **找 mentor**（付費或朋友）
- **教別人**（費曼）

## 一個技術自學者的 3 年計畫範例

假設你從零開始學成為 Backend engineer：

### Year 1：基礎

- Q1：選一個語言（Python / Go），學到流利
- Q2：演算法 + 資料結構（LeetCode 100+ easy/medium）
- Q3：OS + 網路基礎（CS:APP 第一半）
- Q4：第一個端到端專案（一個簡單的 API + DB）

### Year 2：深化

- Q1：SQL + 關聯式資料庫 + NoSQL
- Q2：一個 Web framework 深入（Flask / Gin / Express）
- Q3：System design 基礎（讀 DDIA）
- Q4：一個有挑戰的專案（可放到 GitHub 炫耀）

### Year 3：進階

- Q1：分散式系統概念（讀 Designing Data-Intensive Applications）
- Q2：Cloud 基礎（AWS / GCP）
- Q3：深度優化（performance、security）
- Q4：開源貢獻或寫技術部落格

**3 年後**：你是一個**真正會做事**的後端工程師。

**這個計畫慢**嗎？比 bootcamp 的 3 個月慢。
**這個計畫深**嗎？遠超 bootcamp 的深度。

**真實世界**用人不看你多快學，看你**多深**。

## 技術自學的一個激勵

**好消息**：技術領域**對自學者非常友善**。

- 大公司不一定要學位（Google、Meta、Amazon 都雇過自學者）
- 開源貢獻是可見的履歷
- 技能比文憑重要

**如果你 2–3 年認真自學**，你能進入這個行業、甚至成為優秀的工程師。

**沒有速成**。但路徑是**真實的**。
