# 營運工作流程：把它跑成一個會自我迭代的系統

> **這份接在 [QUICKSTART](./QUICKSTART.md) 之後**：QUICKSTART 帶你發出前 10 篇；這份講「**長期怎麼運轉**」——發文節奏、A/B 測試、定期挖新爆文複製、用數據自我迭代。
>
> 想**一鍵照著跑**，用 [`shopee-threads-ops` 技能](../../.claude/skills/shopee-threads-ops/SKILL.md)（在 Claude Code 裡輸入 `/shopee-threads-ops`）——它會用本檔的流程驅動每天/每週的循環、呼叫腳本、幫你拆解與產文。本檔是「流程的規格」，技能是「跑流程的人」。

## 0. 心智模型：這是一個 hill-climb 迴圈（呼應 harness 課）

把整個營運當成一個會自我改進的 agent harness（見 [harness_engineering](../../ai/harness_engineering/README.md)）：

```
  挖題/拆解 ─▶ 形成假設 ─▶ 產內容(變體) ─▶ QA 閘 ─▶ 發佈 ─▶ 量測 ─▶ 升級贏家/淘汰輸家 ─┐
   trend-mine    hypothesis    variants       verifier  publish  measure   promote / kill      │
       ▲────────────────────────────────────────────────────────────────────────────────────┘
```

對照 harness 課的概念：
- **QA 閘（`post_qa.py`）= 不可繞過的 verifier**：草稿一律過閘再發（Ch 30）。
- **A/B + tracker = 用數據（而非感覺）決定升級**，且要有「held-out 再驗」避免過擬合到一次運氣（Ch 34 §七）。
- **trend-mine = discovery**：持續找新訊號當迭代燃料。
- **別對指標作弊（Goodhart）**：別灌假互動刷數據——騙得過一時，騙不過長期分發，還違規。

## 1. 發文工作流程（每天）

- **節奏**：一天 **1–3 篇**，別洗版（洗版傷觸及也傷粉）。固定在你受眾在線的時段（用 `tracker` 數據回頭找你的黃金時段）。
- **內容配比**：別整天都在導購。建議**價值/互動貼文 : 導購貼文 ≈ 3 : 1**——多數貼文養互動與信任（觀點、清單、提問、開箱心得），少數才直接帶選品。全導購會被埋、也會掉粉。
- **每篇的標準流程**（就是 QUICKSTART 的 Day 4–7 循環）：
  1. `hook_generator.py` 產鉤子變體 → 挑一個、改成你的口吻、補真實心得。
  2. `post_qa.py body.txt --comment comment.txt` 過閘，沒過先改。
  3. 發主貼文 → 立刻用第一則留言放連結＋揭露。
  4. `tracker.py add` 記下（含這篇用的鉤子/選品，之後才分得出誰有效）。

## 2. A/B 測試（怎麼測、測什麼、別踩什麼線）

**先講合規紅線**（這節最重要）：
- **預設用「單帳號序列 A/B」**：同一個帳號，這批貼文用鉤子 A、下一批用鉤子 B，比 `tracker` 數據。最安全、零帳號風險。缺點是時間序會混入其他變因，所以要**多累積幾篇再比**。
- **多帳號 A/B 要非常小心**：只有當每個帳號是**真實、獨立、不同利基/人設**的經營體（例如你真的同時經營「3C」和「居家」兩個帳號）才合理。**絕對不要開一堆分身、互追互按來操弄演算法**——那是 Meta 明文禁止的**操弄性不實行為（coordinated inauthentic behavior）**，會被砍號。多帳號之間也不要互相假互動。

**怎麼測**：
- **一次只變一個變數**：鉤子類型 / 連結位置（內文 vs 留言）/ 發文時段 / 選品角度 / 開頭句型。同時改多個就分不出是誰的功勞。
- **主指標看「留言連結點擊 + 分潤」，不是讚**（`tracker.py report`；比兩個變體用 `python scripts/tracker.py ab --by hook`（或 `--by product` / `--by topic`），它會在樣本<5 時警告）。讚 ≠ 錢。
- **樣本要夠**：單篇噪音很大（見 [case_studies](./case_studies.md) 的「樣本太小別下結論」）。每個變體至少累積 **5–10 篇**再比，別用一篇定生死。
- **held-out 再驗（借 Ch 34 §七）**：某鉤子在你已發的幾篇上贏，別馬上 all-in；拿它去**新的選品/新的一批**再驗一次，贏了才推廣——避免「剛好那次運氣好」被當成規律。

## 3. 定期挖新爆文並複製（trend-mining 節奏）

- **為什麼要定期**：演算法與熱點會變、鉤子會疲乏。**持續補新鉤子是迭代的燃料**，不挖就會慢慢沉。
- **頻率**：每週固定一個 **30–60 分鐘的「拆解時段」**，滑你的利基＋鄰近利基的高互動貼文，填 [`collection_sheet.csv`](./templates/collection_sheet.csv)，挑 3–5 篇丟 `post_teardown.py`；平常每天順手存 1–2 篇。
- **找三種東西**：
  1. **你利基裡最近爆的** → 複製它的結構。
  2. **跨利基的新鉤子形態** → 移植到你的選品。
  3. **蝦皮活動檔期**（雙 11、年中慶、節慶、蝦皮各種展） → 選品與急迫鉤子跟著調。
- **複製的紅線**：複製**結構／鉤子／形態**，**絕不複製文字、圖片、影片**（盜內容＝分潤蟑螂，侵權、會被檢舉下架，見 [case_studies 案例 6](./case_studies.md)）。永遠用自己的選品、自己的話、自己的素材重做。
- **可半自動**：你滑到不錯的貼文，貼 URL 給 [`shopee-threads-ops` 技能](../../.claude/skills/shopee-threads-ops/SKILL.md)，它會（用公開頁面 WebFetch）幫你拆解、歸納可複製的點、寫進蒐集表。

## 4. 自我迭代（每週／每月）

- **每週復盤**：`tracker.py report` →
  - 哪種「鉤子 × 選品 × 時段」的點擊＋分潤最好 → 下週**加碼贏家**。
  - 哪些連續多篇高觸及卻零連結點擊 → **換鉤子**；哪個選品零轉換 → **換品**。
  - 定下「**本週要測的那 1 個變數**」（接第 2 節）。
- **每月檢視**：帳號整體（粉絲/觸及趨勢）、利基要不要微調、選品池換血（用 `product_scorer.py` 重評候選、季節/活動）、有沒有鉤子用到疲乏。用 `funnel_calc.py` 拿這個月的真實數據（觸及/點擊率/轉換）回頭校正期待與下月目標。
- **把失敗回灌（借 Ch 34/38 的閉環）**：哪篇被檢舉/被埋/掉觸及 → 記下原因（太業配？連結放內文？鉤子疲乏？），把它變成
  - `post_qa.py` 的一條**新檢查**（例如新增一個你常犯的 salesy 詞），或
  - `collection_sheet` 裡的一個**反例**。
  下次同款坑就被擋下。

## 5. 營運行事曆（範本）

| 頻率 | 做什麼 | 用到 |
|---|---|---|
| **每天** | 發 1–3 篇（每篇過閘）、拆 1 篇存進蒐集表、回填昨天的數據 | `post_qa`、`collection_sheet`、`tracker` |
| **每週** | 拆解時段（挖 5–10 篇新爆文）、`tracker report` 復盤、定本週要測的 1 個變數 | `post_teardown`、`tracker report` |
| **每月** | 整體檢視、選品換血、淘汰疲乏鉤子、微調利基、回顧 A/B 累積結論 | `tracker`、重新選品 |
| **活動檔期** | 提前備好檔期選品與急迫鉤子 | `hook_generator` |

## 6. 踩雷集錦（這份特有）

1. **多帳號分身互追互按／買假互動**：操弄性不實行為，會被砍號——最大的雷。
2. **一次測太多變數**：學不到任何東西，等於沒測。
3. **複製到文字/圖片/影片**：盜內容、侵權、被檢舉（分潤蟑螂）。只複製結構。
4. **全導購、不養互動**：被埋又掉粉。守住 3:1 的價值/導購配比。
5. **看讚不看連結點擊/分潤**：自我感覺良好但沒錢。盯轉換漏斗。
6. **同一個鉤子用到爛**：會疲乏、觸及下滑。持續從 trend-mine 補新鉤子。
7. **用單篇成績下結論**：噪音太大。看趨勢、看分群、累積樣本。
