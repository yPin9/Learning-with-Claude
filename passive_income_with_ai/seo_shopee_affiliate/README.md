# SEO × 蝦皮分潤：用 AI agent 做一個會持續分潤的內容資產

> **這份是什麼**：一份**可操作的 playbook ＋ 一組腳本**，教你把「SEO 內容站 → 蝦皮分潤」這條流程做成一個半自動的 AI pipeline。不是課程、不是理論，是「照著做、把腳本接起來就能跑」的作業手冊。

## 先把醜話講在前面（請務必讀完這段再決定要不要做）

1. **它不是「被動收入」，是「會累積的資產」。** 前期（建站、寫前 20–50 篇、等 Google 收錄與排名）是純付出、零回報，通常要 **3–6 個月**才看得到自然流量。長尾文章排上去之後才相對省力，但仍要維護（資訊過期、連結失效、排名波動）。把它想成「種果樹」，不是「印鈔機」。
2. **三件事任何一件做錯，整個資產直接歸零，而且 AI 讓你更容易踩：**
   - **Google 反垃圾政策**：Google 的 *scaled content abuse* 政策（2024 起）**明確針對「大量生產、主要為操弄排名、對使用者沒有額外價值」的內容**——不管是不是 AI 寫的。純丟給 AI 量產的薄內容，不只排不上，還可能整站被降權。**唯一能長久的做法是內容真的有用**（真實比較、實測觀點、把分散資訊整理到位）。這份 playbook 從頭到尾都在逼你做「有價值的 AI 輔助內容」，不是「AI 內容農場」。
   - **蝦皮分潤計畫條款**：自買套利、誤導點擊、用不實宣稱、亂用品牌關鍵字等通常都會被停權收回分潤。**規則以你實際加入的計畫（蝦皮官方分潤計畫 / 或 Involve Asia 等聯盟）當期條款為準**，做之前一定要讀過。
   - **揭露義務**：聯盟行銷在台灣受公平交易法／相關規範約束，**文章必須揭露「內含分潤連結」**；蝦皮計畫條款通常也要求揭露。這不是建議，是底線。
3. **沒有保證數字。** 收入 = 流量 × 點擊率 × 轉換率 × 客單價 × 分潤費率，每一項都浮動，**分潤費率還常有類別差異、上限與排除類別**。任何跟你保證「月入 X 萬」的教學都在唬你。這份 playbook 給你的是**把每一項做到位的方法與工具**，數字得你自己用真實數據算（見 `tracker.py`）。

如果這三點你能接受，往下走。

## 一、商業模式：錢從哪來

```
  你寫的內容   →  Google 自然搜尋  →  讀者點文章內的   →  讀者在蝦皮   →  你拿到
  （評測/比較/                          蝦皮分潤連結         下單              分潤
    選購指南）
   └─────────── AI agent 主要幫你做這一段 ───────────┘     └─ 這兩段你只能靠「內容夠好＋選品夠準」間接影響 ─┘
```

關鍵認知：**你能直接控制的只有「內容」與「選品」**，後面的點擊、下單都是間接影響。所以 AI 的價值不在「狂產文章」，而在**用更低成本把選題、選品、內容品質做得比人工快又穩**——同時守住品質，不然就是在生產會被 Google 埋掉的垃圾。

收入漏斗，逐關拆給你看 AI 能幫什麼：

| 漏斗環節 | 決定因素 | AI agent 的角色 | 對應腳本 |
|---|---|---|---|
| **自然流量** | 選對「有人搜、競爭低、有購買意圖」的關鍵字 | 大量產生候選關鍵字、初步打分排序 | `keyword_scorer.py` |
| **選品** | 選「需求高、分潤合理、和關鍵字相關」的商品 | 整理你提供的商品資料、比對關鍵字相關性 | （手動選品 + `tracker.py` 記錄） |
| **點擊率** | 內容是否真的幫讀者做決定（比較表、優缺點、適合誰） | 產出結構化、有決策價值的草稿 | `brief_and_draft.py` |
| **內容能不能上架** | 是否通過品質與合規門檻 | — | `content_qa.py`（**閘門**） |
| **轉換／分潤** | 連結正確、可追蹤 | 正規化連結、掛追蹤標記、維護對應表 | `shopee_link.py` |
| **持續優化** | 知道哪篇賺錢、哪篇該砍 | — | `tracker.py` |

## 二、把整條流程當成一個 agent harness

如果你讀過本 repo 的 [harness_engineering](../../ai/harness_engineering/README.md)，這條 pipeline 其實就是一個 agent harness：

```
  選題 ──▶ 選品 ──▶ 產內容(LLM) ──▶ ┌─ QA 閘 ─┐ ──▶ 發佈 ──▶ 追蹤 ──▶ 回饋
  關鍵字   蝦皮後台   brief_and_draft   content_qa   通過才     上站      tracker   （數據回頭
  scorer  （人工選）                    沒過退回改      上架                        修選題/選品）
```

兩個從 harness 課程搬過來、**這裡一定要遵守**的原則：

- **QA 閘是「不可繞過的閘」**（對應 harness 課 Ch 30 / Ch 34 §七）：`content_qa.py` 不過就不准發。AI 草稿**永遠**先過閘再上站，沒有「這篇趕時間先發再說」。閘擋的就是那些會害你整站被 Google 降權的薄內容。
- **別對自己的品質指標作弊**（Goodhart，harness 課 Ch 34 §七）：`content_qa.py` 的檢查（字數、揭露、原創價值訊號…）是**幫你守底線的代理指標，不是要刷的分數**。如果你開始為了過閘而塞字數、灌關鍵字，你就是在對自己作弊——Google 的演算法比你的 QA 腳本嚴得多，最後是它替你打分。**閘是地板，不是天花板。**

## 三、Runbook：一篇文章從 0 到上線

> 前置：Python 3.11；要用 `brief_and_draft.py` 需 `pip install anthropic` 並設 `ANTHROPIC_API_KEY`。`cp templates/config.example.yaml config.yaml` 填你的利基與分潤 ID（**目前腳本不會自動讀 config.yaml，純粹給你集中記錄**）。產文前也 `cp templates/products.example.json products.json` 改成你的選品。

### Step 1 — 選題（關鍵字）
先用你慣用的工具（Google Keyword Planner、Ahrefs/SE Ranking 的免費額度、Google 搜尋下拉與「相關搜尋」、蝦皮站內熱搜）收集**候選關鍵字**，整理成一個 CSV，再用腳本打分排序：

```bash
python scripts/keyword_scorer.py candidates.csv
```

它用「購買意圖 × 競爭度 × 分潤潛力 × 流量」打分，並用**硬門檻**剔掉「純資訊查詢（沒人會在這頁買東西）」「競爭過高（你排不上）」「該類別分潤趨近零」的題目。**先挑高分、低競爭、買家意圖明確的長尾關鍵字**（例如「__ 推薦 ptt」「__ 平價 比較」「__ 新手 該買哪支」），別一開始就打「藍牙耳機推薦」這種紅海大字。

### Step 2 — 選品（手動，不要爬蟲）
到你加入的**蝦皮分潤後台 / 聯盟平台**，依關鍵字挑 3–8 個要在文章裡比較的商品。**不要寫爬蟲抓蝦皮**——違反 ToS、會被封、頁面結構又常變。把每個商品的事實（名稱、價格區間、規格重點、優缺點、你的分潤連結）**手動填進一份 product facts 檔**（給下一步當素材）。內容要可信，這些事實必須是真的。

### Step 3 — 產內容（AI 在這裡上場）
```bash
python scripts/brief_and_draft.py --keyword "藍牙耳機 平價 推薦" --products products.json --dry-run   # 先看它要送什麼 prompt
python scripts/brief_and_draft.py --keyword "藍牙耳機 平價 推薦" --products products.json > draft.md
```
它會產出：搜尋意圖分析 → 文章大綱（H2/H3）→ zh-TW 草稿，內含**比較表、各商品優缺點、適合誰、FAQ**，以及**強制的分潤揭露區塊**與分潤連結佔位符。**這是草稿不是成品**——你要補上「只有真人有的東西」：實際使用心得、你的取捨判斷、第一手照片。這正是 Google E-E-A-T（經驗/專業/權威/可信）要的，也是純 AI 內容給不出的。

### Step 4 — QA 閘（不過不准發）
```bash
python scripts/content_qa.py draft.md
```
檢查：揭露聲明在不在、字數夠不夠、關鍵字有沒有堆砌、有沒有原創價值訊號（比較表／優缺點／規格／實測語句）、分潤連結數有沒有超過上限（過多連結 = 廣告農場訊號）。**回非零就是不准發**，照它列的 blocker 改完再過。

### Step 5 — 連結
官方短連結要從**分潤後台產生**（本工具不替你產官方連結，也不該）。`shopee_link.py` 負責：正規化商品 URL、（若你的計畫支援）掛上你控制的 `sub_id` 追蹤標記、並維護一份「連結 ↔ 文章 ↔ 商品」對應表，讓 `tracker.py` 之後對得起來。
```bash
python scripts/shopee_link.py add --article "bt-earphone-budget" --product "Sony WF-C510" --url "https://shopee.tw/..." --subid "bt-earphone-budget"
```

### Step 6 — 發佈
平台選擇：**WordPress**（外掛生態完整、適合長期，自架成本最低）或**靜態站**（Hugo/Astro + Cloudflare Pages，免費、快、好維護）。最低限度要做：標題與 meta description、URL slug、標題層級（H1/H2/H3）、內部連結、圖片 alt、結構化資料（FAQ schema 對 SEO 友善）、**頁面顯眼處放分潤揭露**。

### Step 7 — 追蹤
```bash
python scripts/tracker.py add --article "bt-earphone-budget" --keyword "藍牙耳機 平價 推薦" --url "https://yoursite/..."
# 一段時間後從分潤後台＋GSC 回填數據：
python scripts/tracker.py update --article "bt-earphone-budget" --clicks 320 --orders 7 --commission 210
python scripts/tracker.py report
```

## 四、合規與揭露（這節不能跳）

- **揭露分潤關係**：每篇含分潤連結的文章，在**顯眼處**（建議開頭與連結附近）寫明「本文包含蝦皮分潤連結，透過連結購買我可能獲得分潤，不影響你的價格」。`content_qa.py` 會擋掉沒有揭露的草稿。
- **Google 政策（決定你活不活得下去）**：
  - *Scaled content abuse*：大量、低價值、主要為操弄排名的內容會被處置——**這是 AI 內容站最大的死因**。對策：每篇都要有「為什麼讀者該看你這篇而不是商品頁」的理由。
  - *E-E-A-T*：尤其商品推薦屬於會影響消費決定的內容，Google 看重第一手經驗與可信度。**補上真人實測、明確的作者身分與聯絡方式、真實的優缺點（包含缺點）。**
- **蝦皮 / 聯盟條款**：不得自買套利、不得誤導、連結與品牌字使用有規範；分潤費率、歸因視窗、**哪些不給分潤（私人賣場、排除類別、不支援的商品）都以分潤後台當期公告為準**。**做之前讀條款，做之後定期回看（條款會改）。**
- **不要爬蟲**：抓蝦皮違反 ToS 且技術上脆弱。商品資料用官方提供的工具/資料或手動整理。

## 五、KPI、放大與淘汰

`tracker.py report` 給你每篇與整站的：點擊 → 下單 → 分潤、以及粗略 ROI（`(分潤 − 成本) ÷ 成本`）。（曝光數看 Google Search Console，這個 tracker 不存曝光欄位。）判讀原則：

- **看分群、看長尾**：賺錢的通常是少數幾篇長尾文，別被總數騙。
- **淘汰標準**：上線 **6 個月**仍無自然流量、或長期有流量但零轉換的文章 → 重寫（換角度/補實測）或砍掉（避免拉低整站品質訊號）。
- **放大的正確方式**：把「已驗證會賺」的關鍵字群，複製方法到鄰近主題——但**品質閘不准放鬆**。放大的是「經過驗證的流程」，不是「降低標準狂發」。一旦為了量而犧牲質，就回到第零節那個會歸零的死因。

## 六、成本與模型選擇

- **API 成本**：基石文章（要長期排名的主力）用 **Opus**（`claude-opus-4-8`）把品質做滿；量產次要草稿可用較便宜的模型（如 Haiku）控成本。`brief_and_draft.py` 可切換模型。實際花費取決於文章長度與篇數，用 `tracker.py` 把它算進 ROI。
- **站台成本**：靜態站 + Cloudflare Pages 幾乎零成本；WordPress 需主機（每月數美元起）。
- **最大的成本其實是時間**：選品、補實測、發佈、維護。AI 砍掉的是「從零打字」與「整理資訊」的時間，砍不掉「提供真實價值」這件事。

---

## 七、踩雷集錦

1. **把 AI 草稿直接發**：薄內容被 Google 埋，還可能拖累整站。草稿一定要補真人價值 + 過 QA 閘。
2. **對 QA 閘放水**：為了過閘灌字數/塞關鍵字——你在對自己作弊，演算法會替你打真分數（Goodhart）。
3. **關鍵字堆砌**：2010 年的招式，現在是負分。`content_qa.py` 會抓密度過高。
4. **沒揭露**：違反規範＋蝦皮條款，可能停權，也傷讀者信任。
5. **寫爬蟲抓蝦皮**：違反 ToS、會被封、又脆弱。
6. **自買套利**：幾乎所有計畫都禁止，被抓就收回分潤甚至停權。
7. **把雞蛋放一個關鍵字**：排名會波動、演算法會更新。用一群長尾分散風險。
8. **打紅海大字**：「__推薦」這種大字被權威站佔滿，新站排不上。從長尾、低競爭、明確購買意圖切入。

## 檔案總覽

```
seo_shopee_affiliate/
  README.md                      ← 你正在讀的 playbook
  scripts/
    keyword_scorer.py            選題打分（購買意圖×競爭×分潤×流量 + 硬門檻）
    brief_and_draft.py           關鍵字+商品 → SEO 大綱與 zh-TW 草稿（Claude API，含 --dry-run）
    content_qa.py                上線前品質/合規閘（揭露/字數/堆砌/價值訊號/連結上限）
    shopee_link.py               連結正規化 + sub_id 追蹤標記 + 連結↔文章對應表
    tracker.py                   CSV 成效追蹤與 ROI 報表
  templates/
    config.example.yaml          利基、分潤 ID、門檻設定（腳本不自動讀取，集中記錄用）
    products.example.json        brief_and_draft 的商品事實檔範例（cp 成 products.json 改你的選品）
    article_template.md          zh-TW 評測文骨架（含揭露區塊、比較表、FAQ；也是 content_qa 的測試範例）
    tracker.csv                  追蹤表種子欄位
  # 執行後會在你的工作目錄產生：links.csv（shopee_link）、tracker.csv（tracker）
```

從 **Step 1 選題** 開始跑，一篇一篇做。記住第零節：**這是種樹，不是印鈔；品質閘是地板不是天花板。**
