# Ch 2 — 正則表達式與 DFA 直覺

> 目標：理解 flex 為什麼能用「一份規則 + 一遍掃描」搞定詞法分析。不會手算狀態機，但要看懂它的行為。

## 為什麼這章重要？

當你寫了一條看似合理的 flex 規則卻得到奇怪結果，比如：

- 為什麼 `if` 被吃成 `IDENT` 而不是關鍵字？
- 為什麼 `==` 被切成兩個 `=`？
- 規則的順序到底重不重要？

這些都跟 flex 背後的「正則 → NFA → DFA」轉換有關。

## 三層概念

```
正則表達式 (regex)
    ↓ Thompson 構造法
NFA (非確定有限狀態機)
    ↓ 子集構造法
DFA (確定有限狀態機)
    ↓ 直接編成 C
flex 產生的 yylex()
```

你不需要會手做這些轉換（編譯原理課會教），但要知道：

- **正則表達式** 是給人寫的描述語言。
- **DFA** 是機器執行的東西，每一步只看一個字元，狀態唯一。
- flex 的工作就是幫你把正則編成 DFA。

## DFA 直覺：用一個例子

考慮這個正則：`if|int|[a-z]+`

它對應的 DFA 大概長這樣（簡化）：

```
       i              f
 [s0] ───▶ [s1: i] ───▶ [s2: if 接受]
            │
            │ n        t
            ▼          ▼
          [s3: in] ─▶ [s4: int 接受]
            │
            │ 其他字母
            ▼
          [s5: 一般 ident，接受]

 其他字母（非 i 開頭）
 [s0] ──────────▶ [s5: 一般 ident，接受]
```

當輸入是 `int`：
1. 起始狀態 `s0`，讀 `i` → `s1`
2. 讀 `n` → `s3`
3. 讀 `t` → `s4`，這是接受狀態
4. 繼續讀，沒有更多輸入，匹配成功，token 是 `int`

當輸入是 `index`：
1. `i` → `s1` → `n` → `s3` → 但下一個是 `d` 不是 `t`
2. 切回「一般 ident」分支，繼續吃 `e` `x`
3. 結束，匹配成功，token 是 `index`

## flex 的兩個關鍵原則

flex 在面對多條規則時，永遠遵守：

### 1. 最長匹配 (longest match)

flex 會盡可能多吃字元，直到再吃下去就無法匹配任何規則為止。

範例：
```lex
"=="    { return EQ; }
"="     { return ASSIGN; }
```

輸入 `==` 時，flex 不會貪小便宜先匹配 `=` 然後再匹配第二個 `=`。它會發現「再多吃一個 `=` 還能匹配 `==`」，於是吃兩個，回傳 `EQ`。

這就是為什麼 `==` 不會被切成兩個 `ASSIGN`。

### 2. 規則順序決定平手 (first-match wins)

當有兩條規則匹配長度相同時，**寫在前面的優先**。

範例：
```lex
"if"          { return IF; }
[a-zA-Z_]+    { return IDENT; }
```

輸入 `if`：
- 規則 1 匹配 2 個字元
- 規則 2 也匹配 2 個字元
- 平手 → 規則 1 在前 → 回傳 `IF`

如果你**反過來寫**：
```lex
[a-zA-Z_]+    { return IDENT; }
"if"          { return IF; }
```

那 `if` 會永遠被當成 `IDENT`，因為平手時規則 1 贏。**這是新手最常踩的坑。**

## 黃金規則

> 寫 flex 規則時：**關鍵字寫在識別字之前。**

或者用更通用的講法：**特化的規則寫在一般化規則之前。**

## 正則語法速查

flex 支援的正則大致是 POSIX ERE 的超集，常用的有：

| 寫法 | 意思 |
|---|---|
| `x` | 字元 x |
| `.` | 除了換行的任意字元 |
| `[abc]` | a 或 b 或 c |
| `[a-z]` | 範圍 |
| `[^abc]` | 否定，不是 a/b/c 的字元 |
| `x*` | 0 個以上 x |
| `x+` | 1 個以上 x |
| `x?` | 0 或 1 個 x |
| `x{n,m}` | n 到 m 個 x |
| `xy` | x 後接 y |
| `x\|y` | x 或 y |
| `(xy)+` | 群組 |
| `"if"` | 字面字串（雙引號內所有特殊字元都是字面） |
| `\n` `\t` | 跳脫 |
| `^x` | 行首的 x |
| `x$` | 行尾的 x |
| `x/y` | trailing context：匹配 x 但只當後面跟著 y |

注意 flex **不支援**反向引用（`\1`）和 Perl 那一堆延伸。它的正則語法等價於「正則語言」，這是它能編譯成 DFA 的前提。

## 為什麼 flex 不能用反向引用？

數學上，「正則語言」的能力等同於 DFA。一旦加入反向引用，就會超出正則的範圍（變成上下文相關），無法用 DFA 表達。

這也是為什麼 Perl/PCRE 那種正則引擎在最壞情況下會有指數爆炸（catastrophic backtracking），而 flex 不會：flex 一律是線性時間。

## 起始狀態：簡單預告

flex 還支援一個叫 **start condition**（起始狀態）的機制，讓你在不同情境下啟用不同規則集。比如解析字串字面量、解析註解時。Ch 5 會詳細講。

預告一下，它長這樣：

```lex
%x STRING

%%
\"           { BEGIN(STRING); }
<STRING>\"   { BEGIN(INITIAL); }
<STRING>.    { /* string body */ }
```

## 動手實驗

寫個小 flex 檔測試「最長匹配」與「順序」：

```lex
%option noyywrap

%%
"if"        { printf("[KEYWORD if]\n"); }
"ifdef"     { printf("[KEYWORD ifdef]\n"); }
[a-z]+      { printf("[IDENT %s]\n", yytext); }
.           { /* skip */ }
\n          { /* skip */ }
%%

int main(void) { yylex(); return 0; }
```

預測一下，輸入 `if ifdef ifoo` 會印什麼？

跑跑看：
```bash
flex test.l && gcc lex.yy.c -o test
echo "if ifdef ifoo" | ./test
```

預期輸出：
```
[KEYWORD if]
[KEYWORD ifdef]
[IDENT ifoo]
```

理解每一個輸出怎麼來的：
- `if`：兩條規則都能匹配 2 字元，第 1 條在前，贏。
- `ifdef`：規則 1 只能吃 2 字元，規則 2 能吃 5 字元，最長匹配勝。
- `ifoo`：前兩條都不能匹配 4 字元，規則 3 可以，匹配 4 字元 ident。
