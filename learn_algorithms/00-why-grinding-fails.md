# Ch 0 — 為什麼刷 500 題還是不會

> 目標:破除 pattern-memorizing 的幻覺,建立「從訊號倒推演算法」的思考習慣。

你認識的那個刷了 500 題的朋友,進了面試,拿到一題看起來眼熟、但就是想不出來,然後跪了。為什麼?

## 病:把演算法當「招式」背

LeetCode pattern 系列文章、Neetcode 150、Blind 75——它們**不是沒用,而是只對已經會思考的人有用**。如果你沒建立思考框架,它們給你的是「這題用 sliding window」這種事後的答案,而不是「為什麼是 sliding window」的推論過程。

結果是:**你會做你背過的題,不會做你沒背過的題**。

面試會給你沒背過的題。原創題比例不高,但變形率極高——A 題的核心套在 B 的外衣上,你需要的是脫掉外衣看骨架的能力,不是背更多外衣。

## 真正在發生的事

好的解題者腦中有個映射:

```
題目的結構性訊號  →  演算法範式  →  模板
```

舉幾個例子:

| 訊號 | 候選演算法 |
|---|---|
| 「subarray / substring 連續」 | 雙指針 / sliding window / 前綴和 |
| 「k 個最大 / 最小」 | heap / quickselect |
| 「最短路徑」+「邊權相同」 | BFS |
| 「最短路徑」+「邊權正數」 | Dijkstra |
| 「最短路徑」+「可能負邊」 | Bellman-Ford |
| 「組合 / 排列 / 所有可能」 | backtracking |
| 「最優子結構 + 重疊子問題」 | DP |
| 「字典序下一個 / 上一個」 | 單調 stack |
| 「區間合併 / 重疊」 | sort + 一次掃描 |

這些映射**不是硬背的**,是從「每個演算法的設計動機」倒推出來的。當你知道 Dijkstra 為什麼是貪婪、為什麼邊權不能為負,看到負邊就會自動排除它。

## 這門課怎麼建你的映射

每一個演算法章節會先問三件事:

1. **解決什麼問題?**(問題的結構長什麼樣)
2. **為什麼這樣設計?**(動機 + invariant)
3. **何時不適用?**(邊界條件、反例)

第三點是最多書避開的,也是最關鍵的——**知道「什麼時候不能用」比知道「什麼時候能用」更能在面試時救你**。

## 刷題 vs 讀書的配比

兩個都重要,但比例取決於你在哪個階段。

| 階段 | 症狀 | 建議配比 |
|---|---|---|
| 完全新手 | 看到 Easy 就卡 | 讀 80% / 刷 20% |
| 會寫但慢 | Easy 過,Medium 一半 | 讀 50% / 刷 50% |
| 能做但不穩 | Medium 看情況,Hard 看運氣 | 讀 30% / 刷 70% |
| 穩了要複習 | 看到就知道大致路線 | 讀 10% / 刷 90%(含 mock) |

**多數人在第二階段,自以為在第三階段**,所以刷再多也沒進步。如果你 Medium 題要搜解才會寫,那你是第二階段。

## 面試官在看什麼

面試不只看「你寫對沒」。典型的 signal 清單:

- **能不能 clarify**:不 clarify 直接寫 code 的人被打負分。
- **能不能給 brute force**:想不出 brute force 多半是沒讀懂題。
- **能不能分析複雜度**:寫完不主動分析,面試官會失望。
- **能不能 test**:寫完跑個 example、找邊界(空輸入、只有一個元素、重複、負數),是基本禮儀。
- **卡住時的反應**:卡住很正常,但卡住後是僵住還是開始列 invariant,差很多。

> **寫 code 只佔 40%,剩下 60% 是思考流程的可見性(visibility of thought)。**

## 常見的三個誤會

**誤會一:「我只要多刷就好」**

刷題數量跟能力只在第一階段線性相關。過了那點之後,多刷 100 題不如搞懂 10 題的本質。

**誤會二:「我看解答就懂了」**

看解答看懂的是「這解法可以 work」。你沒建立的是「為什麼會想到這解法」。蓋掉解答,逼自己從題意推到解法,這個過程才是學習。

**誤會三:「Hard 題才重要」**

面試 90% 是 Medium 題。Medium 穩過比 Hard 偶爾通過更能過 onsite。把 Easy 的時間複雜度寫到最優、把 Medium 的邊界全考慮到,比硬啃 Hard 有效。
