# Ch 31 — Greedy 思維：何時能用？反例在哪裡？

> 目標：建立「什麼時候 Greedy 正確、什麼時候需要 DP」的判斷框架，能用交換論證驗證 Greedy 的正確性。

## Greedy 的本質

Greedy（貪心）：每一步都做「當下看起來最好的選擇」，不考慮後果。

它不是 DP 的簡化版，而是一種獨立的策略。當 Greedy 可行時，它通常比 DP 更快、更簡單。

**問題**：Greedy 並非永遠正確。判斷一個問題能不能用 Greedy，是這章的核心。

## 反例：硬幣問題

用最少硬幣湊出 target。若硬幣面值是 `[1, 5, 6]`，target = 11。

Greedy（每次選最大面值）：`6 + 5 = 2 枚`。
DP（最佳解）：`6 + 5 = 2 枚`。這次 Greedy 對了。

但若 target = 10：
Greedy：`6 + 1 + 1 + 1 + 1 = 5 枚`。
DP：`5 + 5 = 2 枚`。Greedy 錯了！

**結論**：硬幣問題在一般情況下要用 DP，除非面值是特定結構（如 `[1, 5, 10, 25]`，每個都是前一個的倍數）。

## 什麼時候 Greedy 正確？

Greedy 正確的充要條件是：問題具有**Greedy 選擇性質**（greedy choice property）。

直覺說法：「局部最優選擇，不會讓全局最優解變得不可達。」

嚴格驗證：**交換論證（Exchange Argument）**。

### 交換論證

假設最優解 OPT 做了某個「不貪心」的選擇，而 Greedy 解做了「貪心」的選擇。
證明：把 OPT 的那個選擇替換成 Greedy 的選擇，OPT 不會變差。

這樣就證明了 Greedy 解和最優解一樣好。

## 範例：Assign Cookies（LeetCode 455）

**題目**：小孩有「胃口值」，餅乾有「大小」，每個小孩最多分一塊能滿足他的餅乾（餅乾大小 ≥ 胃口），最大化滿足的小孩數。

**Greedy 策略**：把最小的能滿足孩子的餅乾給胃口最小的孩子。

**為什麼正確？**（交換論證）

若最優解把大餅乾給胃口小的孩子、小餅乾給胃口大的孩子（或不給），把它們交換後：
- 胃口小的孩子改用小餅乾，一樣能滿足
- 大餅乾留給胃口大的孩子，可能多滿足一個孩子

所以 Greedy 選擇不會讓答案變差。

```cpp
int findContentChildren(vector<int>& g, vector<int>& s) {
    sort(g.begin(), g.end());
    sort(s.begin(), s.end());
    int i = 0, j = 0;
    while (i < g.size() && j < s.size()) {
        if (s[j] >= g[i]) i++;  // 滿足這個孩子
        j++;                     // 無論如何用掉這塊餅乾
    }
    return i;
}
```

## Greedy 的辨識線索

**可能用 Greedy**：
- 「最大化數量」（滿足盡量多的 X）
- 按某種標準排序後，貪心地選取
- 問題有明顯的「局部最優 = 全局最優」結構

**不能用 Greedy，要用 DP**：
- 選擇之間有複雜的相互影響
- 局部最優不等於全局最優（如硬幣問題反例）
- 題目問「所有可能方案的最大 / 最小值」且需要比較多種路徑

## 一個快速判斷法

能不能找到一個反例讓 Greedy 失敗？

- 能找到反例 → 不能用 Greedy，考慮 DP
- 找不到反例（且能給出交換論證的直覺）→ 可以試試 Greedy

面試中不需要嚴格數學證明，能給出「為什麼局部最優不影響全局」的直覺就夠了。
