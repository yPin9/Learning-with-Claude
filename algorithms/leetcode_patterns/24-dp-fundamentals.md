# Ch 24 — DP 核心思維：記憶化遞迴 → 遞推

> 目標：建立 DP 的思維框架，能從「暴力遞迴 → 記憶化 → 遞推表」三步推導出任何 DP 解。

## DP 是什麼？

Dynamic Programming（動態規劃）的核心是：

> **把大問題拆成子問題，子問題的結果存起來，不重複計算。**

它不是什麼神秘技巧，而是「遞迴 + 記憶化」的系統化應用。

## 四個要素

寫任何 DP 之前先回答這四個問題：

```
1. 狀態（State）：    dp[i] 代表什麼？
2. 轉移（Transition）：dp[i] 怎麼從 dp[i-1]（或其他更小狀態）推導？
3. 基礎情況（Base case）：最小的狀態是什麼，答案是多少？
4. 答案（Answer）：   最後看 dp 的哪個位置？
```

這四個問題定義清楚了，code 幾乎自己就出來了。

## 三步推導流程

以費波那契數列為例：

### Step 1：暴力遞迴（直接根據定義寫）

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```

時間 O(2ⁿ)，超慢。問題：`fib(3)` 被計算多次。

### Step 2：記憶化（Top-Down DP）

加一個 memo 陣列，算過就不再算：

```cpp
vector<int> memo;

int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fib(n-1) + fib(n-2);
}

// 呼叫前：memo.assign(n+1, -1);
```

時間 O(N)，空間 O(N)。

### Step 3：遞推表（Bottom-Up DP）

從小到大算，不用遞迴：

```cpp
int fib(int n) {
    if (n <= 1) return n;
    vector<int> dp(n + 1);
    dp[0] = 0; dp[1] = 1;
    for (int i = 2; i <= n; i++)
        dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}
```

時間 O(N)，空間 O(N)（可進一步優化到 O(1)，Ch 30 說）。

## 如何定義「狀態」？

狀態是 DP 的靈魂，定義錯了整個解法就垮了。

**原則**：狀態必須能**完整描述子問題**，讓你不需要知道其他資訊就能決定答案。

常見狀態模式：
- `dp[i]`：考慮前 i 個元素的最佳解
- `dp[i][j]`：考慮從 i 到 j 的子問題
- `dp[i][j]`：考慮前 i 個元素、容量為 j 的最佳解
- `dp[state]`：狀態壓縮（用 bitmask 表示多維狀態）

## 識別 DP 題型

面試中看到這些就往 DP 想：

- 最大值 / 最小值（最長、最短、最多、最少）
- 計數類（有幾種方法）
- 可行性（能否達到某個目標）
- 子序列 / 子陣列問題（通常需要 DP）
- 存在重疊子問題（暴力遞迴很慢）

## 記憶化 vs 遞推表，選哪個？

| | 記憶化（Top-Down） | 遞推表（Bottom-Up） |
|---|---|---|
| 寫法 | 更自然，直接改遞迴 | 需要想清楚遍歷順序 |
| 空間 | 有遞迴 stack | 無遞迴 stack |
| 速度 | 只算「需要的」子問題 | 算「所有」子問題 |
| 空間優化 | 較難 | 容易（Ch 30） |

**建議**：先用記憶化想清楚，再改寫成遞推表（更快、更穩定）。

## 常見錯誤

- 狀態定義不完整（漏掉某個維度）→ 轉移方程有歧義
- Base case 沒設好 → 陣列越界或答案錯
- 遞推的遍歷順序錯（大狀態用了還沒算到的小狀態）
