# Ch 39 — OSED 考試作戰：時間分配、報告、常見失分

> **目標**：把前面 38 章學到的技術，組織成一套能在限時考試裡穩定拿分的作戰方式。你會知道怎麼分配時間、先打哪題、邊做邊記什麼、報告怎麼寫、以及哪些「技術明明會了卻拿不到分」的坑怎麼避開。

> **環境**：本章是方法論，不綁工具。考試細節（時數、題數、分數線）**以你報名當下的 OffSec 官方 Exam Guide 為準**——OffSec 會調整考試結構，本章不把數字當成不變的事實。

## 為什麼技術會了還需要「考試作戰」？

OSED 和 CTF、和平時練習最大的不同：**它不只考你會不會，還考你能不能在壓力與時限下，把會的東西穩定地交付出來，並證明給別人看。**

考過的人常說，掛在 OSED 的人裡，很少是「某個技術完全不會」，多半是：
- 時間分配失控，卡在一題鑽牛角尖，其他題沒時間碰。
- exploit 在自己機器跑得動，但不穩定/不可重現，截圖拿不齊，報告寫不出完整步驟。
- 明明打到 shell 了，卻因為報告沒把「怎麼打到的」講清楚而失分。

所以這章講的不是新技術，是**把技術變成分數**的工程。這和真實漏洞研究的工作方式一致：能打進去只是一半，能讓別人複現、能寫成報告，才是完整的交付。

## 先建立直覺：考試是一條「交付管線」

把整場考試想成一條管線，技術只是中段，兩端的「選題」和「交付」同樣會決定成敗：

```
┌─────────┐   ┌──────────┐   ┌─────────┐   ┌──────────┐   ┌─────────┐
│ 選題排序 │ → │ 逆向找洞 │ → │ 寫 exploit│ → │ 穩定+重現 │ → │ 截圖+報告│
└─────────┘   └──────────┘   └─────────┘   └──────────┘   └─────────┘
  時間管理      Part 4         Part 2-9       工程紀律       證據鏈
  (本章)        (技術)         (技術)         (本章)         (本章)
```

你前面 38 章練的是中間兩格。這章補的是頭尾兩格——而掛掉的人通常就掛在頭尾。

## 核心一：時間分配與選題

**開場先全部掃一遍，不要看到第一題就埋頭打。** 花最初的時間把每一題都讀過、各跑一次初步 recon，對「哪題我最有把握、哪題看起來最硬」有個排序。

選題原則：

1. **先打最有把握的，拿到手的分最實在。** 不是先打最難的證明自己。先把穩的分收進口袋，心理壓力會小非常多，後面鑽難題時才有本錢。
2. **設停損。** 給每一題一個「卡到這個時間還沒進展就先跳走」的硬上限。卡在一題三小時沒進度，不如先去把另一題收掉，回頭再戰往往有新想法。
3. **留足報告時間。** 很多人把技術時間用好用滿，結果報告草草了事而失分。報告不是附錄，是評分的一部分——預留的時間要當成硬性預算，不是「有剩再寫」。

> 具體時數怎麼切，取決於當屆考試是幾題、幾小時。原則不變：**先穩後難、設停損、報告時間神聖不可侵犯。**

## 核心二：做題的 SOP

每一題，照同一套流程走，不要臨場即興：

```
1. recon      這是什麼服務？什麼協定？用 IDA 看 imports/strings（Ch 15）
2. 找洞        逆向定位 unsafe copy / 可控輸入（Ch 16-18）；別急著 fuzz 到死
3. 控制        量 offset、確認控 EIP 或 SEH（Ch 7-8, 11）
4. 壞字元      完整掃一遍壞字元（Ch 8）—— 這步偷懶，後面全盤皆錯
5. 繞緩解      看有沒有 DEP/ASLR，決定要不要 ROP / leak（Ch 27-33）
6. 落地        shellcode（手寫或 msfvenom -b），egghunter 若空間不足（Ch 19-26）
7. 穩定        多跑幾次確認可重現；處理一次性/需重啟服務的情況
```

> **第 4 步（壞字元）是最常被跳過、最致命的一步。** 你會很想在剛控到 EIP 的興奮中直接塞 shellcode，但一個沒排掉的壞字元會讓 shellcode 悄悄變形、exploit 時好時壞。花時間把壞字元掃乾淨，是整場考試投報率最高的紀律。

## 核心三：邊做邊建「證據鏈」

報告寫不出來，九成是因為當下沒留紀錄，事後回想不起來。正確做法是**邊打邊記**，把每一步的證據當場收好：

**要截的圖**（最低限度）：
- 觸發 crash 的 payload / exploit 腳本片段
- WinDbg 裡 `EIP` 被控的畫面（`eip=42424242` 那一刻）
- 關鍵的 offset / jmp 位址 / ROP gadget 來源（mona 輸出）
- 最終拿到 shell 後的 **`whoami` + `ipconfig`**，而且要能看出是**目標機**的身分與 IP
- 證明是「你的 exploit 打的」——例如同畫面同時可見你的攻擊端與目標端

**要記的字**：
- 每個魔術數字的來源：offset 是怎麼量的、跳板位址在哪個模組的哪個偏移、壞字元清單是什麼
- exploit 的完整最終版本（存檔，別只留在記憶裡）

> **為什麼 `whoami`+`ipconfig` 要同框？** 評分者要能確認你真的在目標機上執行了命令，而不是在自己機器上。截圖要能自證「這是目標、這是我打進去的」。這是 OffSec 系列考試（OSCP 起）一貫的證據要求。

## 核心四：報告

報告結構通常長這樣（**以官方當屆模板為準**，這裡給通用骨架）：

```
1. 高階摘要（High-Level Summary）
   - 每題一段：這是什麼漏洞、你怎麼打下來的（給非技術讀者也看得懂）

2. 每題的詳細章節：
   2.1 漏洞描述        哪個函式、哪種漏洞（stack overflow / SEH / format string）
   2.2 逆向過程        你怎麼找到它的（IDA 截圖、關鍵反組譯）
   2.3 利用步驟        offset → 跳板 → 壞字元 → 繞緩解 → shellcode，每步可複現
   2.4 證明            EIP 被控截圖、最終 shell 的 whoami/ipconfig
   2.5 完整 exploit    可直接執行的最終腳本（含註解）
   2.6 修補建議        開發者該怎麼修（長度檢查、/GS、ASLR、DEP…）
```

報告的黃金標準是：**一個沒看過你解題的人，照著你的報告能重現整個 exploit。** 寫的時候假想讀者會照著做——offset 怎麼來、位址在哪個模組、為什麼選這個 gadget，都要交代。

> 修補建議不是可有可無的客套。它證明你理解漏洞的「為什麼」，而不只是會按步驟打。寫得具體（「在 `recv` 後對長度做上限檢查」勝過「加強輸入驗證」）。

## 對比與取捨：常見失分 vs 正確做法

| 失分情境 | 為什麼失分 | 正確做法 |
|---|---|---|
| 卡一題三小時，別題沒碰 | 時間失控 | 設停損，先收穩的分 |
| exploit 只在自己機器穩 | 不可重現 | 多次重跑、處理服務重啟、清楚記環境 |
| 截圖缺 whoami/ipconfig | 無法自證 | 每題都截，目標身分+IP 同框 |
| 跳過壞字元測試 | shellcode 時好時壞 | 每題完整掃壞字元 |
| 報告只貼最終腳本 | 無法複現過程 | 寫出 offset/位址/gadget 的由來 |
| 沒留逆向截圖 | 說不清怎麼找到洞 | 邊逆向邊截 IDA 關鍵畫面 |
| 報告時間不夠草草收尾 | 技術分拿不全 | 報告時間列硬預算 |

## 踩雷集錦

1. **「先打最難的那題證明實力」**：錯誤直覺是難題分高先打。正確認識：先收穩分降壓力，難題留後面用剩餘時間攻；手裡有分，鑽難題時心態完全不同。
2. **「打到 shell 就等於拿到分」**：錯。沒有證據鏈（截圖+可重現步驟+完整腳本），評分者無法確認，形同沒打。交付 ≠ 打進去。
3. **「報告可以考完憑記憶補」**：限時考試下記憶極不可靠，位址、offset、順序很快就糊了。必須當場記。事後補等於重做一遍。
4. **「exploit 跑一次成功就收工」**：一次成功可能是運氣（某次記憶體佈局剛好）。至少重跑數次、必要時重啟服務再打，確認穩定——考試環境可能和你開發時的狀態不同。
5. **「修補建議隨便寫兩句」**：它是實打實的配分項，也最能展現你懂漏洞本質。具體到「哪個函式、加什麼檢查、開哪個編譯旗標」。

## 進階：再往深一層

- **自動化你的重複動作**：把常用的 mona 命令做成 `.cmdtree`（Ch 4），把 exploit 腳本寫成參數化模板（改 IP/port/offset 即可重用）。考試時省下的每一分鐘都是別題的機會。
- **建一個你自己的「卡關 checklist」**：把你練習時每次卡住的原因記下來（壞字元沒排乾淨？模組選到開 ASLR 的？offset 算錯 4 bytes？），考試卡住時逐條過。多數卡關都是老問題重演。
- **模擬考**：本課的 [Final Project](./final-project-osed-mock-exam.md) 就是讓你在接近實戰的壓力下，把這章的作戰方式跑一遍。別只練技術，要練「限時+要交報告」的完整體驗。
- **考前環境確認**：確保你的 WinDbg、mona、IDA、攻擊腳本模板都就緒且你用得順手——考試時跟工具打架是最浪費的失分。

## 本章重點整理

- 考試是一條管線：選題→找洞→exploit→穩定→報告。頭尾兩格（時間管理、交付）和技術一樣決定成敗。
- 選題：先穩後難、設停損、報告時間神聖。
- 做題照固定 SOP 走，尤其別跳過壞字元測試。
- 邊打邊建證據鏈：關鍵截圖（EIP 被控、whoami+ipconfig 同框）+ 記下每個魔術數字的由來。
- 報告的標準是「別人照著能重現」；修補建議要具體。
- 多數失分不是不會技術，是時間失控、不可重現、證據不全。
