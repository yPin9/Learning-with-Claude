# Ch 14 — IDA Pro 入門：graph view、xref、工作流

> **目標**：建立 IDA 的基本操作肌肉記憶——載入 binary、看懂 Functions/Imports/Exports/Strings 視窗、在 graph view 與 text view 間切換、用 xref（交叉引用）追「誰呼叫誰」、用 rename 和註解把逆向過程留下痕跡。這是 Part 4 剩下四章的操作基礎，不會這章，後面每章都會卡手。

> **環境**：Win10 x64 + IDA Free 9.x / IDA Pro（Hex-Rays 反編譯器限 Pro）。本章所有介面步驟、快捷鍵行為標注**未實測，理論預期**——以官方文件與穩定公開版本行為為準，請在你自己環境逐步核對（見文末延伸閱讀與自我驗證法）。

## 為什麼需要 IDA

Part 2、3 的漏洞（vulnserver 的 `TRUN`、SEH overflow）是**已知**的：別人告訴你哪個指令有洞，你直接去 fuzz 就能撞到。OSED 考試的某些題目不會這麼善良——給你一支陌生的 32-bit Windows 服務，不告訴你哪裡有洞，你要自己從零逆向出：它聽哪個 port、收什麼格式的指令、哪個指令的處理函式（handler）裡藏著 unsafe copy。

這件事脫離偵錯器幹不了。WinDbg 很擅長「這一刻記憶體長什麼樣」，但它不擅長「這支程式的邏輯結構是什麼」——你不會對著即時執行的程式一行一行跳,效率太低而且危險操作容易讓它跑飛。IDA 做的是**靜態**逆向：binary 不需要跑起來,IDA 直接解析 PE 檔案、反組譯每個函式、建出呼叫關係圖,讓你在不執行程式的情況下讀懂它的邏輯。Ch 17 會把這個靜態視角和 WinDbg 的動態視角接起來,但接之前,你要先能在 IDA 裡站穩。

## 先建立心智模型：IDA 到底在做什麼

把 IDA 想成「幫你把機器碼翻譯回結構」的工具,分三層:

```
PE 檔案 (.exe/.dll，一堆 bytes)
        │  IDA 載入時解析
        ▼
反組譯 (disassembly)：bytes → 組語指令 (mov, call, cmp, jnz...)
        │  IDA 自動分析
        ▼
函式邊界 + 呼叫圖 (call graph) + 交叉引用 (xref)
        │  你在這層閱讀、標註、推理
        ▼
你的理解：這支程式收什麼輸入、怎麼處理、哪裡可能出錯
```

IDA 的分析是**啟發式**的：它猜函式從哪開始、哪結束，猜哪些 bytes 是程式碼哪些是資料，大部分時候準，但不是絕對正確——尤其是手寫組語、混淆過、或被最佳化得奇怪的程式碼，IDA 可能切錯函式邊界。這是為什麼逆向需要人的判斷,不是按個按鈕就出答案。

IDA 把分析結果存進一個**資料庫檔案**：舊版是 `.idb`（32-bit 目標）/`.i64`（64-bit 目標），新版 IDA（9.x 系列）統一用 `.i64` 副檔名承載分析資料库，無論目標位元數——這點各版本行為可能有差異，**以你實際開啟時 IDA 產生的副檔名為準**。重點是：你在 IDA 裡做的所有 rename、comment、分析修正都存在這個資料庫裡，不是改動原始 binary。你可以放心重命名函式、加註解，原始 `.exe` 一個 byte 都不會變。

## 載入 binary 的流程

未實測，理論預期，流程如下：

1. 開啟 IDA（Free 或 Pro），選 **New** 或直接把 `.exe`/`.dll` 拖進去。
2. IDA 跳出 "Load a new file" 對話框，讓你選載入器（loader）——通常自動偵測出 "Portable executable" 並選對的處理器（x86）。32-bit 目標確認處理器類型是 **metapc**（IDA 對 x86/x64 系列的通稱），位元數會依 PE header 自動判斷。
3. 勾選項目通常保留預設即可（例如是否載入除錯資訊）。按 OK。
4. IDA 開始**自動分析**（auto-analysis）：反組譯每個區段、找函式邊界、解析字串、建交叉引用。小檔案幾秒內完成，大檔案可能跑好一陣子，底部狀態列會顯示進度。
5. 分析跑完，游標通常停在 **entry point**（程式入口，不一定是 `main`，x86 PE 常是 CRT 的 startup 函式）。

存檔用 `Ctrl+S` 或 File → Save，會存成資料庫檔（依版本為 `.idb` 或 `.i64`），放在和原始 binary 相鄰的位置。下次開啟直接開這個資料庫檔，不用重新載入原始檔重跑分析。

## 核心視窗：你會活在這五個裡

IDA 預設版面（layout）會打開幾個子視窗，這些是你逆向時主要停留的地方：

- **Functions window**（函式清單）：左側列出 IDA 辨識出的所有函式，雙擊跳過去。這是你的「地圖目錄」。
- **IDA View**（反組譯主視窗）：中央主畫面，顯示目前函式的組語，可在 graph view 和 text view 間切換。
- **Imports**：這個 binary 從哪些 DLL 匯入哪些函式（例如 `ws2_32.dll` 的 `recv`、`send`）——Ch 15 找網路輸入點會重度依賴這個視窗。
- **Exports**：這個 binary（如果是 DLL）對外匯出什麼函式。單一 `.exe` 通常沒什麼內容。
- **Strings window**（`Shift+F12` 開啟）：binary 裡所有辨識出的字串常數。逆向協定時極有用——指令關鍵字（像 `"TRUN "`、`"HELP"`）往往以明文字串存在，從 Strings 窗直接找到,再用 xref 回溯誰用了它。
- **Hex view**：記憶體的原始 bytes（十六進位+ASCII），用來核對反組譯是否正確，或看資料區段的原始內容。

> **未實測**：視窗確切名稱、預設排版、`Shift+F12` 這個 Strings 快捷鍵在不同 IDA 版本可能微調。找不到某個視窗時，用選單 **View → Open subviews** 裡面都能手動開。

## Graph view vs text view：`Space` 切換

IDA 的反組譯主視窗有兩種呈現同一份組語的方式：

- **Text view**：線性列出每一條組語指令，像看一份原始碼。適合快速掃過一長串直線邏輯（沒有分支的區段）。
- **Graph view**：把函式拆成**基本區塊**（basic block，一段沒有分支進出的連續指令），畫成方塊，用箭頭連接條件跳轉（`jnz`/`jz`/`jmp` 等）。綠色箭頭通常代表「條件成立走這邊」，紅色代表「不成立走那邊」（顏色依主題可能不同）。

```
             ┌─────────────────┐
             │  cmp eax, 10     │
             │  jnz  loc_4015A0 │
             └────────┬─────────┘
               ┌───────┴────────┐
          (相等) ▼            ▼ (不相等)
      ┌──────────────┐   ┌──────────────┐
      │ ...處理 A...   │   │ ...處理 B...   │
      └──────────────┘   └──────────────┘
```

Graph view 對「這個函式的整體控制流長什麼樣」直覺得多——一眼看出有幾條分支、哪裡是迴圈（箭頭繞回上面的方塊）。但方塊一多（函式很大、分支很複雜），graph view 會變得又寬又亂，這時切回 text view 線性讀，搭配往下講的 xref 跳轉，反而更有效率。

**切換鍵是 `Space`**（未實測，理論預期，以你 IDA 版本的 Options → Keyboard 設定為準）。兩種視圖顯示的是同一份反組譯，切換不會丟失任何資訊,純粹是呈現方式不同。逆向時常見節奏：graph view 抓整體形狀 → 切 text view 細讀可疑段落 → 需要看更大範圍的分支關係再切回 graph view。

## 核心操作：交叉引用 xref（`X`）

交叉引用（cross-reference，簡稱 xref）是 IDA 最重要的導航工具,答的問題是「這個東西（函式/變數/字串）在哪裡被用到」和「這個函式呼叫了什麼」。

- 把游標停在一個函式名、變數、或字串上，按 **`X`**，彈出一個清單：**誰呼叫/引用了這個東西**（to this）。
- 在函式內部，直接看反組譯裡的 `call` 指令就是「這裡呼叫了什麼」（from this，不需要額外操作，`call` 指令本身就寫明目標）。

舉例（未實測，理論預期的典型場景）：你在 Strings window 找到字串 `"TRUN "`，游標停在它上面按 `X`，IDA 列出「這個字串被哪個函式引用」——通常就是指令分派（command dispatch）那段比較字串的程式碼，循線點進去就找到處理 `TRUN` 指令的 handler 在哪裡被叫到。這條路徑（字串 → xref → 呼叫處 → 往上找 handler 本體）是 Ch 15 逆向協定的核心招式。

反過來，你在一個函式上按 `X`，想知道「這個函式被誰呼叫」，一樣適用——例如你懷疑某個 `strcpy` 可疑，想知道它在哪些地方被呼叫、呼叫者傳了什麼參數進來，就對這個 `call strcpy` 或對 `strcpy` 本身按 `X` 往上追。

## 核心操作：重命名 `N` 與註解 `;`

IDA 自動分析給函式的預設名字長得像 `sub_401230`（位址當名字），變數叫 `var_20`，完全無法閱讀。逆向的進度感很大一部分來自**把這些名字換成你理解的意思**：

- 游標停在名字上按 **`N`**（rename），輸入有意義的名字，例如把 `sub_401230` 改成 `handle_TRUN_command`。這個改動會**全局生效**——這個函式在所有呼叫處都會顯示新名字，大幅提升可讀性。
- 按 **`;`**（分號）在目前這一行加註解，寫下你當下的推理，例如 `; eax = 使用者輸入長度，這裡沒檢查上限`。

這兩個操作看起來瑣碎，但是逆向大型函式時**唯一能對抗遺忘**的手段——你花十分鐘搞懂一段邏輯，沒留名字沒留註解，隔天回來等於重新逆向一次。養成「懂一點就留一點痕跡」的習慣，是逆向效率的分水嶺。

## 導航：雙擊跳轉、`Esc` 返回

- 雙擊任何函式名、變數名、位址，IDA 跳到那個定義處。
- **`Esc`** 回到上一個游標位置（類似瀏覽器的上一頁）——逆向時你會不斷「點進去看一下、`Esc` 跳回來」，這個鍵按到變反射動作為止。
- `Ctrl+Enter`（或類似組合，依版本）可能是「前進」，對應 `Esc` 的「後退」。

## IDA Free 9.x vs IDA Pro：差在哪

| 項目 | IDA Free 9.x | IDA Pro |
|---|---|---|
| 反組譯（disassembly） | 有，完整 | 有，完整 |
| Graph view / xref / rename | 有 | 有 |
| Hex-Rays 反編譯器（`F5`） | **無本地反編譯**（新版可能有限制性的雲端反編譯功能，依官方公告為準） | **有**，把組語變成類 C 的虛擬碼 |
| 授權/用途限制 | 免費，供學習/非商業用途（條款以官方現行版為準） | 付費 |

`F5`（啟動 Hex-Rays 反編譯）**只在 IDA Pro 可用**（未實測，以你版本的授權狀態為準）。反編譯出的虛擬碼大幅降低閱讀門檻——`strcpy(buf, user_input)` 這種呼叫直接以類 C 語法呈現，不用在組語裡自己拼湊參數。

因為不是每個人都有 Pro，本課 Part 4 的逆向示範會**刻意雙軌**：同一段邏輯先給「只讀組語」的分析方式（寄存器怎麼傳參數、`call` 前堆疊怎麼佈置），再補一段「如果你有 `F5`，會看到的虛擬碼大概長這樣」。兩種讀法都要會——考場環境不保證有 Pro，組語閱讀力才是底座。

> **免費替代**：[Ghidra](https://ghidra-sre.org/)（NSA 開源）同時有反組譯和反編譯，完全免費。OSED 官方教材以 IDA 為準，考場慣例也是 IDA，建議練習時主力用 IDA 熟悉快捷鍵，但本課的逆向**觀念**不綁死工具,Ghidra 使用者可自行對應操作。

## 自我驗證法：如何在你自己環境核對本章

本章所有快捷鍵與介面敘述標了未實測。驗證方式：

1. 找任意一支簽過名的系統 `.exe`（例如 `C:\Windows\System32\notepad.exe` 的舊版，或任意你有權分析的 32-bit binary）丟進 IDA。
2. 跟著上面流程走一次載入、存檔、開 Functions/Imports/Strings 視窗。
3. 在任意函式名上試 `X`、`N`、`;`、`Space`、`Esc`，確認你的 IDA 版本的實際鍵位（Options → Keyboard 可查/改所有快捷鍵對應）。
4. 把結果記在你自己的筆記裡——版本間的細節差異不影響本課教的**操作邏輯**，只影響按鍵對不對。

## 踩雷集錦

1. **錯誤直覺：IDA 分析出的函式邊界一定正確** → **正確**：IDA 是啟發式分析，手寫組語、位置無關跳轉表、混淆過的程式碼都可能讓 IDA 切錯函式起止，需要人工核對（看函式開頭有沒有正常的 prologue，結尾有沒有正常的 `ret`）。
2. **錯誤直覺：graph view 永遠比 text view 好用** → **正確**：函式一大，graph view 會變得又寬又難讀，這時切 text view 配合 xref 跳轉效率更高。兩種視圖是工具,不是信仰。
3. **錯誤直覺：`F5` 反編譯出來的虛擬碼可以完全取代讀組語** → **正確**：反編譯器對複雜控制流、手寫最佳化、或某些字串/結構操作可能呈現得不準確或過度簡化，遇到可疑段落還是要回去對組語，尤其在判斷「這裡到底溢位了幾個 byte」這種精確問題上。
4. **錯誤直覺：在 IDA 裡改名、加註解會動到原始 binary** → **正確**：這些改動只存在你的資料庫檔（`.idb`/`.i64`）裡，原始 `.exe`/`.dll` 一個 byte 不變，可以放心大膽重命名。
5. **錯誤直覺：沒有 IDA Pro 就做不了 OSED 逆向** → **正確**：Free 版 + 扎實的組語閱讀力完全能完成 OSED 要求的逆向深度，Pro 的 `F5` 是加速器不是必需品；本課示範會兩種都練。

## 進階：再往深一層

- **FLIRT signatures**：IDA 能用函式簽名庫辨識出靜態連結的已知函式（例如某版本的 CRT 函式），省去手動辨認。遇到奇怪的 `sub_xxx` 其實是標準函式時會用到。
- **IDAPython**：用 Python 腳本操作 IDA 資料庫——批次重命名、自動標記所有 `call` 到危險函式的地方。逆向大型 binary 時能省大量手工。本課不深入，有興趣可查 Hex-Rays 官方 IDAPython 文件。

## 本章重點整理

- IDA 做**靜態**逆向：不執行程式,直接解析 PE 並反組譯,分析結果存進資料庫檔（.idb/.i64），原始 binary 不變。
- 五個核心視窗：Functions、IDA View（主反組譯）、Imports/Exports、Strings（`Shift+F12`）、Hex view。
- Graph view（控制流圖,`Space` 切換）vs text view（線性）：各有適用場景。
- `X`（xref，誰呼叫/引用這個）、`N`（rename，全局改名）、`;`（加註解）是逆向效率的三大支柱。
- IDA Pro 的 `F5` Hex-Rays 反編譯器把組語變虛擬碼，Free 版沒有；本課雙軌示範兩種讀法。
