# Ch 33 — 打造你的逆向 SOP

> **目標**：把全課三十幾章收斂成一套**可複製的攻堅流程**——拿到一個 strip binary，前 15 分鐘做什麼、怎麼建地圖、怎麼決定靜態還是動態切入、假設驅動循環怎麼跑、怎麼收斂到目標、怎麼外化與驗證、最後怎麼費曼確認真懂。給你一張「冷啟動逆向 checklist」直接拿去用。這是 [`reading_code` Ch 38 讀碼 SOP](../../soft_skills/reading_code/README.md) 的鏡像——那份是攻 source 的流程，這份是攻 binary 的流程，骨架同構、工具不同。

## 為什麼要有 SOP？

你已經有一堆技巧（認控制流、gdb、假設驅動、對拍），也知道一堆反模式（Ch 32）。但真實逆向的難處不是「缺技巧」，是**在對的時機用對的技巧**——什麼時候該偵察、什麼時候該切動態、什麼時候該收手。沒有流程，你會憑當下情緒亂抓工具：焦慮就狂 dump asm，卡住就繼續瞪，覺得懂了就收工（其實沒驗證）。

SOP 的價值是把「該做什麼」變成不用思考的預設動作，讓你的腦力全部花在真正難的地方——**推理這個 binary 在做什麼**，而不是「我下一步該幹嘛」。老手看起來快，不是每條指令讀得比你快，是他有一套內化的流程，從不在「下一步做什麼」上猶豫。

這份 SOP 不是聖經，是**起點**。跑過幾個 binary 後你該按自己的弱項、常攻的目標類型客製它（本章最後講怎麼演進）。

## 先建立直覺：逆向 SOP 的骨架

整套流程是一個「先發散、再收斂、最後外化成產物」的漏斗：

```
  拿到 strip binary
        │
   ┌────▼─────┐  前 15 分鐘：撿滿免費線索
   │  偵察     │  file/readelf/strings/import → 這是什麼、用了什麼
   └────┬─────┘
   ┌────▼─────┐  建地圖：找 main / 目標函式，畫控制流骨架
   │  定位     │  「真正的邏輯在哪個位址？」
   └────┬─────┘
   ┌────▼─────┐  決策：靜態切入 or 動態切入？（見決策樹）
   │  切入     │
   └────┬─────┘
   ┌────▼─────┐  ◄─┐ 假設驅動循環：靜態建假設 → 動態釘死 → 修正
   │  攻堅     │   │  收斂到目標，無關的當黑盒
   └────┬─────┘ ──┘
   ┌────▼─────┐  外化成產物：命名/筆記/等價實作/對拍
   │  驗證     │  「逆對了嗎？」——對拍是鐵證
   └────┬─────┘
   ┌────▼─────┐  費曼複述：講給沒逆過的人聽，每句有真跑撐
   │  確認     │
   └──────────┘
```

**注意漏斗形狀**：上寬（偵察撒網、看全貌）、中窄（收斂到一小塊核心邏輯）、下轉為外化（把「讀懂」變成「寫得出等價品 + 講得清楚」）。Ch 31 的攻堅就是走這個漏斗——你已經看過一次活的，這章是把它抽象成任何 binary 都適用的模板。

## 階段 0：界定任務（30 秒，但別跳過）

動手前寫三欄。這 30 秒決定你會不會逆整個 binary（反模式 7）：

```
本次任務：______（一句話，具體的問題）
成功標準：(1) ______  (2) ______  (3) ______（可驗證的）
不需要懂：______（明確宣告不追的 rabbit-hole：libc 內部、ELF 載入…）
```

「不需要懂」那欄是對抗完美主義的預先聲明。目標明確（逆一條授權檢查）的偵察可以砍很短；目標模糊（onboarding 整個 binary）就得多花偵察。

---

## 階段 1：偵察——前 15 分鐘做什麼

**這 15 分鐘的產出，決定你後面省不省一小時。** 一律先撿免費線索再進 asm（反模式 1、8）。固定順序：

```bash
# 1) 骨架：這是什麼？
file <bin>                       # 架構/PIE/是否 strip/靜態還動態連結
readelf -h <bin> | grep -E 'Type|Machine|Entry'
readelf -SW <bin> | grep -E 'text|rodata|data'   # section 大小（.text 異常小 = 可能加殼）

# 2) 是否 strip？殘留符號是免費地圖
nm <bin> 2>&1 | head            # "no symbols" = strip 了

# 3) 字串：最便宜的線索
strings -a <bin> | less         # usage/格式字串/錯誤訊息/URL/檔名/版本
                                # 反查：某字串在哪被引用 → 定位到相關函式

# 4) import 表：它會用哪些能力（strip 也拿不掉動態符號）
readelf -W --dyn-syms <bin> | awk '{print $8}' | grep -v '^$'
# 讀法：有 crypto? 網路(socket)? 檔案(fopen)? 自訂邏輯(只有 printf/strlen)?

# 5) entropy（懷疑加殼時）：高熵 .text = 壓縮/加密
# ent / binwalk -E，或看 .text 大小 vs 檔案大小比例
```

15 分鐘結束時你該答得出：**這是什麼程式、跑在什麼架構、strip 了沒、加殼了沒、它用了哪些能力、有哪些人類可讀的線索。** 這張情報卡讓你知道往哪裡挖。Ch 31 裡這一步的產出（「PIE、strip、無 crypto、`%02x` 輸出、per-byte 迴圈」）直接定調了整場攻堅。

> **entropy 快篩**：`.text` 熵接近 8.0（隨機上限）通常代表壓縮/加密 → 加殼，該切動態 unpack（反模式 9）。正常編譯的 `.text` 熵約 6 左右。

**這 15 分鐘實際長什麼樣**（以 Ch 31 的 `enc` 為例，濃縮版）：`file` → 「PIE、strip」（0:30）；`nm` → 「no symbols」，確認要從無名世界起步（0:45）；`strings` → 撈到 `usage: %s <string>` 和 `%02x`，馬上知道「吃一個命列參數、byte-wise 印 hex」（2:00）；`readelf --dyn-syms` → 看到 `strlen`/`printf`/`putchar`、**沒有任何 crypto**，定調「自訂 per-byte 編碼，邏輯在 .text」（4:00）。四分鐘，我已經有一張情報卡：這是什麼、輸出長怎樣、演算法是自寫的、該去哪找。**剩下的偵察時間拿去定位 main、畫骨架。** 這張卡讓後面每一步都有方向，而不是對著幾千條指令發呆。跳過這四分鐘，你省下的是四分鐘，賠上的是後面一小時的瞎逛。

## 階段 2：定位——找到真正的邏輯在哪

偵察給了「這是什麼」，定位給「邏輯在哪個位址」。核心是**找 main / 找目標函式**：

- **找 main（strip 了沒符號）**：`_start` 裡 `lea ...,%rdi` 載入的位址就是 main（新 glibc 當 `__libc_start_main` 首參），或反查誰呼叫關鍵 import（呼叫 `strlen`/`printf`/`socket` 的那個函式體多半是你要的）。Ch 31 兩招都用了。
- **從使用者可見的東西反推**：有 `usage:` 字串？反查它在哪被 load（`objdump -d | grep <字串位址>`），那附近就是參數處理。有錯誤訊息 `"Access denied"`？反查它 → 授權檢查就在旁邊。**這是定位的黃金策略**（Ch 11），鏡像 reading_code 的「從命令字串反推實作」。
- **建控制流骨架**：不用逐行，先畫「main → 幾個主要函式」的呼叫骨架（反編譯器的 function graph、或 `objdump` 掃 `call` 目標）。有骨架才知道目標在哪個枝節。

定位結束時你該指得出：**我要逆的邏輯，在位址 0x???? 的那個函式**。

## 階段 3：決定靜態還是動態切入

不是「先靜態全讀再動態」，是**按 binary 的特性選切入點**。決策樹：

```
這個 binary / 目標函式……
├─ 加殼 / 高熵 .text / 自修改 code？
│    → 動態切入：先跑起來 unpack / dump 記憶體真面目（Ch 15,23）
├─ 混淆嚴重（間接跳轉密集 / 控制流平坦化）？
│    → 動態為主：DBI 記錄實際走過的路徑，靜態填不出跳轉目標（Ch 15,23）
├─ 邏輯清晰、-O0/-O2 正常編譯、目標函式看得出結構？
│    → 靜態切入：objdump/反編譯器建假設，動態只用來釘死疑點（Ch 31 就這型）
├─ 輸入依賴強（不同輸入走不同路徑）、狀態機？
│    → 靜動並用：靜態看全貌、動態餵不同輸入看實際走向（Ch 17）
└─ 目標是「某個值怎麼算出來的」（演算法/協定）？
     → 靜態讀邏輯 + 動態看中間值 + 對拍驗證（Ch 18,19）
```

**預設是靜態建假設、動態釘死**（正常 binary 最高效）。但看到加殼/混淆的指紋，動態切入才是對的——別用擊敗靜態的東西的剋星（靜態）去硬瞪它（反模式 9）。

## 階段 4：假設驅動循環——攻堅的引擎

這是核心迴圈，跑到收斂為止：

```
   ┌─────────────────────────────────────────┐
   │ 1. 靜態讀一段 → 認 idiom → 生一個假設      │
   │    「這條迴圈在做 加→XOR→旋轉？」          │
   │ 2. 假設寫下來（外化！反模式 6）            │
   │ 3. 能靜態確定就確定；不確定 → gdb 釘死     │
   │    「rol 方向？prev 餵哪個值？」→ 斷點看    │
   │ 4. 觀測結果 vs 假設：對 → 前進；錯 → 修正   │
   │ 5. 收斂檢查：這在目標路徑上嗎？            │
   │    否 → 當黑盒退回主線（反模式 7）          │
   └─────────────────────────────────────────┘
              ↑ 重複，直到目標邏輯完全還原
```

三條紀律貫穿這個循環：

- **靜態產生假設、動態釘死假設**（Ch 17）：靜態卡 10 分鐘沒進展就上動態（反模式 5）。
- **全程外化**（Ch 25）：暫存器命名（`%r12d` → `keystream`）、假設列清單、複雜控制流畫圖。strip 拿走名字，你一個個補回去——這就是重建意圖。
- **收斂不發散**（反模式 7）：每碰一個函式問「在目標路徑上嗎」，不在就當黑盒。

## 階段 5：驗證——逆對了嗎

**「我覺得對」不算數，對拍才算數**（反模式 4、Ch 0 的靈魂）。驗證的強度階梯：

1. **手算對照**：拿一組輸入手動跑一遍你逆出的邏輯，對照 binary 的真實輸出。快，但只覆蓋一個 case。
2. **動態單點驗證**：gdb 斷點看關鍵中間值符不符合假設（Ch 31 的 `prev=0x81`）。
3. **等價實作對拍**（最強）：把逆出的邏輯寫成獨立實作，餵**大量隨機輸入**逐一比對原 binary。Ch 31 用 500 組隨機輸入 0 不合——這是逆對了的鐵證。任何一組不合就是某處逆錯，回階段 4 修。

**練功階段一定有 ground-truth 兜底**：自己寫 C、編、strip、逆、對拍、再對照原 source。真實無答案目標上，等價實作對拍就是你的 ground-truth 替代品——你的實作跟原 binary 同輸入同輸出，即使沒有原 source，也證明你逆對了行為。

---

## 階段 6：費曼——確認真懂

最後一關：**用大白話講給一個沒逆過這 binary 的人聽**，講到他能複述（Ch 31 沒單列但貫穿全課、鏡像 reading_code 的費曼測試）。要求：

- 不用「rol」「XOR chain」這種黑話，或用了當場解釋。
- **每個關鍵斷言背後有真跑撐著**——「它每輪 keystream 加 7」→ 因為 gdb 看到 `0x5a → 0x61`；不是「我猜」。
- 講到某句心虛 = 那裡還沒真懂，回去 gdb 跑一次。心虛是誠實的訊號，別粉飾。

費曼摘要寫得出、對拍過得了，才叫逆完。

## 對比與取捨：這份 SOP 什麼時候該變形

| 目標類型 | SOP 怎麼調 |
|---|---|
| 小 crackme（幾百行） | 偵察砍到 5 分鐘，靜態為主，可能不用畫骨架 |
| 大靜態連結 binary | 偵察後**先用指紋庫排除 libc**（反模式 10），再定位程式邏輯（Ch 22,28） |
| 加殼 / 混淆 | 階段 3 直接選動態切入，先 unpack/DBI，再回靜態（Ch 23） |
| 演算法/協定還原 | 階段 5 的「等價實作對拍」是重點，靜態讀邏輯 + 動態看中間值（Ch 18,19） |
| patch-diff 找 n-day | 兩版 binary diff 找改動點，收斂到那幾個函式（Ch 27）——偵察/定位換成 bindiff |
| 惡意程式 | 動態在**受控沙箱**、加反反調試對抗，SOP 骨架不變（接 malware_analysis 課） |

## 踩雷集錦

1. **錯誤直覺**：「有 SOP 就照 1→6 死板走完。」→ **正確**：SOP 是骨架不是枷鎖。小 crackme 偵察 5 分鐘就夠、加殼的階段 3 就得跳去動態。**按目標調 SOP**，死板照跑反而慢。

2. **錯誤直覺**：「階段 1 偵察 15 分鐘太久，直接看 asm 比較快。」→ **正確**：那 15 分鐘常常直接省掉後面一小時瞎逛。import 表告訴你「沒 crypto」、字串告訴你輸出結構——這些讓你直奔目標。跳過偵察是省小虧大（反模式 1,8）。

3. **錯誤直覺**：「費曼是收尾儀式，講不清也沒差，反正對拍過了。」→ **正確**：對拍證明「行為對」，費曼證明「你懂為什麼」。有時對拍過了但你其實不懂機制（湊對了），費曼講不清會逼出這個。兩者驗的是不同東西。

4. **錯誤直覺**：「這份 SOP 是標準答案，照抄就好。」→ **正確**：它是**起點**。你跑三五個 binary 後會發現自己的弱項（可能總在階段 4 發散、或總跳過驗證），那時該按自己的坑客製它——見下節。

## 進階：讓你的 SOP 持續長大

這份 SOP 和你的能力都不是靜態的，要持續精進：

- **字典持續長大**（接 Ch 30）：每認出一個新 idiom（某編譯器的 memcpy 樣板、某 crypto 常數、某個混淆器的指紋）就記一張卡。你的 idiom 字典越厚，階段 4 的「認 idiom → 生假設」越快——老手快就快在這裡。
- **patch-diff 練 n-day**（接 Ch 27）：拿一個公開 CVE 的補丁前後兩版 binary，diff 找改動點、逆出漏洞。這是把逆向接回安全研究天梯的實戰練法（→ `browser_pwn` 的 patch-diff）。
- **刷 CTF RE 題**：CTF 的 reversing 題是**濃縮的、有明確目標、有答案（flag）驗證**的 target，最適合練 SOP。從 pico CTF 之類入門級開始。
- **crackmes.one**：一整站分難度的 crackme，無限題庫。從一星開始，把每題當一次完整 SOP 演練。**它們有社群 writeup 可對答案**——這是無標準答案世界裡的 ground-truth 替代。
- **回顧與客製**：每攻完一個 target，回看哪個階段浪費了時間、踩了哪條反模式。那就是你該補強的環節、該加進 SOP 的個人化備註。跑幾十個之後，那份客製 SOP 就是你的畢業證書。

> 這是 [`reading_code` Ch 38](../../soft_skills/reading_code/README.md) 「收斂你的個人 SOP」的鏡像：那邊你按讀 source 的踩坑客製流程，這邊按逆 binary 的踩坑客製。骨架同構——界定任務、偵察、定位、假設循環、驗證、費曼——差別只在工具（`rg`/`cscope`/`gdb` vs `objdump`/`radare2`/`gdb`）和介質（有名字的 source vs 無名字的機器碼）。兩門一起練，你的「攻堅陌生系統」能力在光譜兩端都補齊了。

## 本章重點整理

- SOP 的價值：把「該做什麼」變成不用思考的預設，讓腦力全花在真正難的「這 binary 在做什麼」上。老手快在有內化流程、從不猶豫下一步。
- 漏斗骨架：界定任務 → 偵察（前 15 分鐘撿滿線索）→ 定位（邏輯在哪）→ 切入決策（靜態/動態）→ 假設驅動循環（收斂）→ 驗證（對拍是鐵證）→ 費曼（確認真懂）。
- 三條貫穿紀律：靜態建假設動態釘死、全程外化、收斂不發散。
- **等價實作對拍**是無標準答案世界的 ground-truth 替代——你的實作跟原 binary 同輸入同輸出，就證明逆對了行為。
- SOP 是起點不是聖經：按目標類型變形，按自己的踩坑客製，跟 idiom 字典一起持續長大（patch-diff / CTF RE / crackmes.one）。
