# Ch 12 — 動態逆向心法：觀察勝於推理

> **目標**：從「瞪著反組譯推理」切換到「讓 binary 自己招」的心智模式。認清靜態逆向的天花板在哪、為什麼有些東西跑一次比推十分鐘快，並建立可觀察性的三支柱——斷點、trace、插樁——當作 Part 2 之後所有章節的地圖。

Part 1 你學的是**靜態逆向**（static reversing）：不執行 binary，光讀 `objdump` 的反組譯、讀反編譯器的 pseudocode，用眼睛和腦重建意圖。這一路你已經能認出 if/loop/switch、struct/array、函式邊界、compiler idiom。靜態很強大——它涵蓋整份 code、可重複、不用怕跑到危險路徑。

但靜態有一道天花板。這一章講清楚那道天花板長什麼樣，以及為什麼越過它的辦法不是「更用力地讀」，而是**換一種觀測方式**：跑它，然後看。

## 為什麼需要這個？

回想 Ch 0 那個殘酷的不對稱：逆向時，作者的意圖全被編譯器丟掉了，你得自己重建。靜態逆向重建意圖靠的是**推理**——「這個 `and $0x1; test; jne` 應該是 `x%2==0`」「這串 `imul` 大概是某種 hash」。推理有個致命弱點：**它會自信地錯**（Ch 0 踩雷第 1 條）。你腦補一條邏輯，看起來很合理，但根本不是原意，而靜態的 binary 不會糾正你。

動態逆向給你一個靜態永遠給不了的東西：**真實值**。與其推理「rdi 這時候應該是那個密碼字串」，你下個斷點，`x/s $rdi`，binary 當場把真實的字串吐給你看。與其推理「這個 hash 算出來大概是多少」，你斷在比較那一刻，`p $eax`，答案就在暫存器裡。

這就是這門課學習方式建議第 3 條的展開：**靜態卡住就跑它，觀察一次勝過瞪 asm 十分鐘。** 這章把「什麼時候該跑、跑了要看什麼」講成一套方法。

## 先建立直覺：兩種逆向者

想像兩個人在逆同一個 strip binary 裡的一段密碼檢查。

**推理派**打開 `objdump`，順著指令一行一行讀：這裡把 argv[1] 載進 rdi，這裡進一個迴圈，迴圈裡有 `movzbl`、`imul $0x1000193`、`xor`……他在腦裡跑一台虛擬 CPU，手算每個暫存器的值，試圖重建整個演算法。混淆一上、間接跳轉一多，他的虛擬 CPU 就當機了。

**觀察派**也打開 `objdump`，但他只讀到「喔這裡有個 `cmp` 對某個常數，然後 `jne` 跳走」就停手。他不手算 hash——他 `gdb` 斷在那個 `cmp`，跑一次，直接讀出「你輸入算出來是 0xc9e9bd32，它要的是 0x45a7a3ce」。他甚至不在乎那個 hash 怎麼算的：他把記憶體裡的值改成 0x45a7a3ce，或把 `jne` nop 掉，binary 就招了。

```
   推理派：source? ─X─►  在腦裡模擬 CPU  ──►  重建演算法  ──►（混淆一上就崩）
                          瞪、算、腦補

   觀察派：source? ─X─►  下斷點 / trace   ──►  讀真實的值   ──►  改值驗證假設
                          讓 CPU 幫你算              binary 當場招供
```

兩派不是對立，是**分工**：靜態幫你定位「該看哪裡」，動態幫你確認「那裡真的是什麼」。老手兩手都用，而且很清楚何時該從一手切到另一手。這一章教你長出那個「切換的直覺」。

## 靜態的天花板：五種靜態推不動的情況

不是所有 binary 都值得動態。但下面五種，靜態會撞牆，跑它幾乎一定比推它快。

**1. 間接跳轉 / 函式指標。** 靜態看到 `call *%rax` 或 `jmp *0x8(%rax)`——它跳去哪？rax 在執行期才知道。C++ 的 vtable 呼叫（Ch 20）、switch 的 jump table、callback、plugin 分派全長這樣。靜態你得反推 rax 的來源，可能追一大圈；動態你斷在那條 `call`，`x/i $rax` 一看就知道實際跳去哪個函式。

**2. 混淆的控制流。** control-flow flattening（Ch 23）把原本線性的邏輯打散成一個大 switch + 狀態機，靜態讀起來每個 block 都跳去一個由變數決定的位置，人腦幾乎無法重建執行順序。動態你不管它怎麼跳，`stepi` 跟著跑，真實的執行軌跡自己浮現。

**3. 加密 / 打包的字串與 code。** packed binary（UPX 等）或自解密的字串，靜態看到的是一團亂數——`strings` 抽不到東西。但程式跑起來一定得把它解開才能用。動態你讓它跑到解密之後，直接 dump 記憶體，明文就在那（Ch 16）。這是「靜態看不到、動態必然現形」的經典。

**4. 龐大到推不動。** 一個幾 MB 的 strip binary，靜態要找「密碼在哪比對」像大海撈針。動態你 `strace` 一下看它 `read` 了哪個檔、`ltrace` 看它 `strcmp` 了什麼，或對可疑 libc 函式下斷點，讓 binary 帶你到熱點，省掉通讀全部 asm。

**5. 依賴外部狀態。** 行為取決於環境變數、檔案內容、網路回應、時間、亂數。靜態你只能假設；動態你給它真實環境跑，看它真的怎麼反應。

| 情況 | 靜態的困境 | 動態怎麼破 |
|---|---|---|
| 間接跳轉 `call *%rax` | rax 執行期才定 | 斷在 call，讀 rax 實值 |
| 控制流混淆 | 人腦重建不出執行順序 | stepi 跟著跑，軌跡自現 |
| 加密字串 / packed | strings 抽不到、asm 是亂數 | 跑到解密後 dump 記憶體 |
| binary 太大 | 通讀 asm 成本爆炸 | strace/ltrace 定位熱點 |
| 依賴外部狀態 | 只能假設 | 給真實環境跑，看真反應 |

## 動態 vs 靜態：完整取捨

反過來，動態也有靜態沒有的短處。逆向老手心裡有這張表：

| 維度 | 靜態逆向 | 動態逆向 |
|---|---|---|
| 覆蓋率 | 涵蓋所有 code path（含沒被跑到的） | 只看到**這次執行**走過的路 |
| 真實性 | 靠推理，可能腦補錯 | 拿到真實值，不會腦補 |
| 安全性 | 不執行，安全 | **執行 code——跑惡意 binary 有風險** |
| 混淆 / 加密 | 常被擋 | 常能穿透（自解密後現形） |
| 環境依賴 | 難處理 | 給真實環境即可 |
| 反調試 | 不觸發（沒跑） | 可能觸發 anti-debug（Ch 23） |
| 成本 | 讀 asm 慢但零 setup | 要架執行環境、給對輸入 |

最關鍵的一格是「覆蓋率」：**動態只能看到你這次餵的輸入所走過的那條路**。你餵錯密碼，就只看到失敗分支；成功分支裡的邏輯，這次執行根本沒碰到。所以「找出正確密碼」這種題，動態的價值常不是「看成功路徑」，而是「在**比較的那一刻**攔截，讀出它拿你的輸入跟什麼比」——把成功條件從比較點反推出來，而不是等你猜對才看得到。這個思路 Ch 13、Ch 17 和練習 B 會反覆用。

## 核心心法：與其推理，不如觀察

把這章的心法濃縮成一句可以貼在螢幕上的話：

> **與其瞪著 asp 手算暫存器，不如下個斷點，讓真實的值告訴你答案。**

具體展開成三條操作準則：

1. **靜態定位，動態確認。** 用靜態找到「關鍵地點」——那條 `cmp`、那個 `call *%rax`、那個迴圈——但不要在腦裡把值算出來。到了關鍵地點，下斷點跑一次，讓 CPU 把值算給你。
2. **懷疑就驗證，別腦補。** 你對某段 code 有假設（「這好像在檢查長度」），不要說服自己它一定對。斷點看真實資料，當場證實或推翻（這是 Ch 17 假設驅動逆向的核心，也是 `reading_code` SOP 的鏡像）。
3. **能改就改，用干預確認理解。** 你以為某個 `jne` 是「密碼錯就跳走」？把它 nop 掉，看是不是真的變成無條件通過。能用「改一下看行為變化」驗證的理解，才是真的懂——這也是 Ch 15 動態插樁的思想源頭。

## 可觀察性三支柱

Part 2 剩下的章節，本質是把「觀察 binary」這件事拆成三種能力。先在這裡把地圖立起來，你就知道每一章在補哪一塊。

```
                     讓 binary 自己招
        ┌────────────────┼────────────────┐
     斷點             trace              插樁
   （停下來看）      （記錄流過什麼）    （改寫觀測）
        │                │                  │
   gdb: break/          strace(syscall)   Frida/Pin/DynamoRIO
   watch/x/p/           ltrace(libcall)   注入 JS/C 到執行中
   改暫存器記憶體        自寫 ptrace        hook 函式看/改參數
        │                │                  │
     Ch 13            Ch 14              Ch 15
              Ch 16 資料流追蹤 = 斷點+watch 的深用
              Ch 17 靜動結合 = 三支柱 + 假設驅動收斂
```

**支柱一：斷點——停下來看（Ch 13）。** 讓程式在你指定的地點停住，凍結整個世界，然後你慢慢看：暫存器、記憶體、stack、參數、回傳值。這是動態逆向的主力。核心工具是 gdb（接你的 [`gdb`](../gdb/README.md) 課，但這裡是**逆向應用視角**，聚焦 strip binary 無符號時怎麼用位址下斷、怎麼讀無名記憶體，不重教 gdb 全功能）。

**支柱二：trace——記錄流過什麼（Ch 14）。** 不停下來，而是側錄程式與外界的每一次互動。`strace` 錄它跟作業系統要了什麼（開哪個檔、讀寫什麼、連哪個網路位址）；`ltrace` 錄它呼叫了哪些函式庫函式（`strcmp` 比了什麼、`fopen` 開了什麼）。很多時候你不用讀一行 asm，光看 trace 就知道 binary 在幹嘛。

**支柱三：插樁——改寫觀測（Ch 15）。** 最強也最重的一支。在 binary 執行時**注入你自己的 code**，hook 任意函式印出參數/回傳、或直接改掉它的行為。工具有 Frida、Intel Pin、DynamoRIO。這是把「觀察」升級成「觀察 + 干預」，也是心法第 3 條「能改就改」的工業級實現。

Ch 16 把斷點 + watchpoint 深用成「追一個值/一段輸入怎麼流過程式」；Ch 17 把三支柱和靜態綁在一起，走一遍完整的假設驅動逆向。

## 底層機制：動態逆向憑什麼能停能看能改

這些能力不是魔法。底層是一個作業系統機制：**ptrace**（Linux 的行程追蹤系統呼叫，你的 [`gdb`](../gdb/README.md) 課 Ch 2 深講過）。

一個 tracer（gdb、strace、你自寫的工具）呼叫 `ptrace(PTRACE_TRACEME/ATTACH)` 之後，就取得了對 tracee 的生殺大權：

```
   tracer (gdb/strace)                    tracee (被逆的 binary)
        │  ptrace(ATTACH/TRACEME)                │
        ├───────────────────────────────────────►│  被接管
        │                                         │
        │  下斷點：把目標位址那個 byte             │
        │  改成 0xCC (int3) ────────────────────► │  跑到那 → 觸發 SIGTRAP
        │  ◄─────────────────────────────────────┤  停住，控制權交回 tracer
        │  PTRACE_GETREGS  ──► 讀全部暫存器        │
        │  PEEKDATA/讀 /proc/pid/mem ──► 讀記憶體  │
        │  POKEDATA / SETREGS ──► 改記憶體/暫存器  │
        │  PTRACE_SYSCALL ──► 每次進出 syscall 停  │ ← strace 靠這個
```

三支柱全建在這上面：**斷點** = 把目標位址的 byte 換成 `int3`（0xCC），跑到就 trap；**trace** = `PTRACE_SYSCALL` 讓每次進出系統呼叫都停一下，tracer 讀出 syscall 號和參數（strace 的原理）；**改暫存器/記憶體** = `PTRACE_SETREGS` / `POKEDATA`，這就是我們等下能「把 hash 改成正確值」「把 jne nop 掉」的底層。Ch 14 末尾會帶你用 ptrace 手寫一個 30 行的極簡 tracer，親眼看見這層機制。

## 動態的風險：防禦性提醒

動態逆向要**執行**目標 binary。如果目標是你自己寫的 ground-truth（本課練習全都是），沒問題。但真實世界你可能拿到來路不明、甚至惡意的 binary——**執行它就是在你的機器上跑攻擊者的 code**。

紀律（和 `malware_analysis` 課一致）：

- **未知 binary 一律在隔離環境跑**：專用 VM、容器、或斷網的沙箱。跑完丟掉快照。永遠不要在你日常工作的主機上直接跑不明樣本。
- **斷網或用假網路**：惡意樣本常會回連 C2、下載 payload。用 INetSim/FakeNet 之類把網路請求接住，別讓它真的連出去。
- **假設它會反擊**：樣本可能偵測到自己被 debug（anti-debug，Ch 23）就改變行為或自毀，也可能試圖逃逸 VM。動態環境要當作敵對環境看待。
- **本課的界線**：這門是純學術/教育/防禦研究定位。我們動態逆向的一律是**自己寫、自己編、自己 strip** 的 benign 目標——ground-truth 迴圈天然安全。學會方法後要用在真實惡意樣本上，請補 `malware_analysis` 的沙箱工程。

## 對比與取捨：什麼時候切到動態

一張決策表，之後每次卡住可以回來看：

| 你遇到的狀況 | 先靜態還是先動態 | 理由 |
|---|---|---|
| 想看整體架構、函式怎麼呼叫 | 靜態 | 動態只看得到跑過的路 |
| 遇到間接跳轉 / vtable | 動態 | 目的地執行期才定 |
| 卡在一段 hash/crypto 想知道結果 | 動態 | 讀值 << 手算 |
| 字串是亂碼、疑似加密 | 動態 | 跑到解密後 dump |
| 想找「哪裡在比對密碼」 | 動態（ltrace/斷點）先定位 | trace 帶你到熱點 |
| binary 很小、-O0、想徹底讀懂 | 靜態為主 | 小到值得通讀，動態驗證細節 |
| 目標會反調試 / 是惡意樣本 | 靜態優先，動態進沙箱 | 動態可能觸發防護、有風險 |

## 踩雷集錦

1. **「我先把 asm 全讀懂再跑」**：錯誤直覺是「動態是靜態讀不懂時的最後手段」。正確做法是**兩者交織**：靜態讀個大概定位熱點，馬上跑一次拿真實值校正，再回靜態。一開始就想純靜態讀通整份 `-O2` binary，會浪費大把時間在編譯器產物的細節上。
2. **「動態跑一次就看到全部邏輯了」**：最常見的過度自信。你只看到**這次輸入走的那條路**。密碼錯的執行裡，成功分支的 code 一行都沒跑到。要嘛換輸入覆蓋別的路，要嘛從比較點反推條件——別以為一次執行 = 完整理解。
3. **「在主機上直接跑不明 binary」**：致命。動態逆向 = 執行 = 把控制權交給那個 binary。不明樣本一律進隔離 VM/沙箱、斷網。本課的 ground-truth 目標安全，是因為它們是你自己寫的。
4. **「反調試擋住我，動態就沒用了」**：反調試（`ptrace` 偵測、時間差、int3 掃描）確實會擋，但它不是牆是門——Ch 23 教你繞。而且反調試本身是線索：一個 benign 程式為什麼要防你 debug？值得逆的東西往往就藏在它想藏的地方。
5. **「動態能改值，那我就不用理解演算法了」**：改值/patch 能讓 binary 招（練習 B 會做），但那是**驗證**手段，不是理解的替代。要真正逆出「正確密碼是什麼」而非只是「繞過檢查」，你還是得從觀察到的值反推演算法。改值是逆向的加速器，不是免除思考的按鈕。

## 進階：再往深一層

- **record-replay（時間旅行除錯）**：動態的「只看到這次執行」痛點，`rr`（你的 [`gdb`](../gdb/README.md) 課 Ch 35）用錄製-重播解決——錄一次執行，之後能來回倒帶、反向單步。逆向一個難重現的 bug 或想反覆看同一次執行的不同片段時，這是神器。
- **模擬執行 vs 真實執行**：不想真的在自己 CPU 上跑（怕惡意、或跨架構）時，可用 `qemu-user` 模擬跑，或用符號執行（`angr`，接 `symex_taint` 課）在不給具體輸入的情況下「符號地」探索所有路徑——那是動態覆蓋率問題的另一種解法。
- **coverage-guided 觀測**：DBI（Ch 15）能記錄「這次執行碰到哪些 basic block」，把覆蓋率量化。這是 fuzzing（`afl_plus_plus` 課）的核心觀測機制，也是把動態逆向工程化的一步。

## 本章重點整理

- 靜態逆向靠**推理**，天花板在五種情況：間接跳轉、控制流混淆、加密/packed、太大、依賴外部狀態。越過天花板的辦法是換觀測方式——**跑它然後看**，不是更用力地讀。
- 動態的獨門優勢是**真實值**（不腦補）與**穿透混淆/加密**；獨門短處是**只看得到這次執行走的路**，以及**執行有風險**。
- 核心心法：靜態定位、動態確認、能改就改。與其瞪 asm 手算暫存器，不如下斷點讓真實值說話。
- 可觀察性三支柱：**斷點**（Ch 13，停下來看）、**trace**（Ch 14，記錄流過什麼）、**插樁**（Ch 15，改寫觀測）。全建在 ptrace 這個 OS 機制上。
- 動態要執行目標——不明/惡意 binary 一律進隔離沙箱、斷網。本課的 ground-truth 目標天然安全。

## 延伸閱讀

### 書籍

- **《Practical Binary Analysis》** — Dennis Andriesse（No Starch, 2019）
  - **讀哪幾章**：Ch 9（binary instrumentation 概念，對應本課 Ch 15）、Ch 10–11（動態污點分析 / 符號執行，對應 Ch 16 與 `symex_taint` 課）
  - **前提**：讀完本課 Part 1，手上有 Linux/gdb 環境
- **《The Art of Mac Malware / Practical Malware Analysis》** — Sikorski & Honig（No Starch, 2012）
  - **定位**：動態分析「執行有風險的目標」的沙箱工程權威；本課只點到防禦提醒，要真上惡意樣本讀它的沙箱/監控章
  - **讀哪裡**：Ch 3（malware 動態分析基礎環境）、Ch 5–6（gdb/OllyDbg 動態手法）

### 官方文件 / 工具

- **[ptrace(2) man page](https://man7.org/linux/man-pages/man2/ptrace.2.html)**
  - **這是什麼**：本章「底層機制」那節的一手來源。動態逆向所有能力的根。
  - **讀哪裡**：PTRACE_TRACEME / ATTACH / GETREGS / SETREGS / PEEKDATA / SYSCALL 這幾個 request 的說明
- **你自己的 [`gdb`](../gdb/README.md) 課 Ch 1–2**
  - **這是什麼**：「debugger 到底在做什麼」與「ptrace 是根」——本章三支柱的底層在那裡有完整鋪陳，本章只做逆向視角的摘要，細節回去補
