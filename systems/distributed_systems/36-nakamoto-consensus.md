# Ch 36 — Nakamoto 共識

> **目標**：把 Nakamoto 共識（Bitcoin 的「最長鏈 + 算力成本」機制）當作一個分散式共識協定來分析——不談投資、不談幣價，只問「它在解什麼問題、它保證什麼、它的安全假設是什麼、它在哪裡弱」。對比 BFT 協定的確定性 finality，看清「機率性 finality」到底是什麼意思。

## 為什麼需要這個？

Ch 15 定義共識問題時，設定的是許可制（permissioned）場景——節點清單已知、身份固定、節點數可數。Raft 和 PBFT 都在這個框架下工作。

但 Bitcoin 在 2009 年解決的是一個本質上不同的問題：**在完全開放、匿名、任何人都能加入或離開的網路裡，對一本帳冊的所有歷史達成一致**。沒有任何中央機構知道有多少節點，節點隨時加入或蒸發，無法預先建立 PKI，無法假設 2/3 節點誠實（因為不知道有幾個節點）。

傳統共識協定在這個場景下根本無法啟動——Raft 要節點清單，PBFT 要知道 `3f+1` 的邊界。**中本聰的貢獻是在這個約束下找到了一個可行的機制，但這個機制的安全保證和傳統 BFT 是完全不同類型的**。

理解這個差異，你才能真正評估「某個系統用了 blockchain / PoW」到底獲得了什麼、放棄了什麼。

> 若對 Sybil 攻擊和 Eclipse 攻擊為什麼讓開放網路的共識很難不熟，回看 [Ch 35](./35-consensus-attack-surface.md)。對 BFT 協定的確定性 finality 不熟，回看 [Ch 33](./33-pbft.md)。

## 先建立直覺

Nakamoto 共識的核心想法用一句話說：**用算力（或代幣抵押）讓「說話權」有成本，然後用最長鏈規則讓所有節點知道哪個版本的歷史最「重」**。

```
  Raft / PBFT 的做法（許可制，確定性）：
    已知節點集合 {n₁, n₂, n₃, n₄, n₅}
    多數決 quorum → 確定 commit → 永不回頭

  Nakamoto 共識的做法（開放，機率性）：
    未知節點集合（任何人都能參與）
    每個區塊要解一個工作量謎題（PoW）→ 解謎成本 ≈ 投票成本
    最長（最重）鏈 = 背後算力最多 = 共識歷史
    不存在瞬間確定 commit，而是「確認越多，被撤銷機率越低」
```

直覺比喻：想像一場投票，但每張選票要你耗費 10 度電才能製作（PoW）。攻擊者要偽造「多數票」，就必須消耗比誠實參與者多的電力。這個物理成本讓 Sybil 攻擊從「複製一個身份幾乎免費」變成「多一個身份多一份電費」。

## 為什麼傳統共識無法應對開放網路

在理解 Nakamoto 共識前，先弄清楚為什麼 Raft 和 PBFT 在開放網路裡會失效。

**問題一：節點清單未知**

Raft 的 quorum 是「過半數節點 agree」。但「半數」是相對於節點總數的。如果任何人都能加入網路，你根本不知道節點總數，「過半數」就失去定義了。

```
  Raft 選 leader 需要 majority：
    靜態清單 [n0, n1, n2, n3, n4] → majority = 3/5
    動態、未知清單 [n0, n1, ..., n???] → majority = ???/???
```

**問題二：Sybil 讓多數決失去意義**

即使你能統計出「目前有 N 個節點」，開放網路裡任何人都能免費加入無數個 Sybil 節點——攻擊者讓 N 增加到他控制多數為止。多數決的安全假設在開放網路裡根本站不住腳。

**問題三：節點無公鑰體系**

PBFT 要求每個節點有簽名金鑰，且所有節點知道彼此的公鑰（所以訊息可以驗證來源）。開放網路裡沒有 CA 可以簽發這些金鑰，無法建立互信關係。

**Nakamoto 的解法**：不要問「有哪些節點、誰是多數」，改問「誰花了最多功夫（算力）建構這個歷史版本」。把「投票權」和「算力（真實的物理資源）」綁在一起，讓Sybil 攻擊從「免費複製身份」變成「必須購買算力」。

## PoW 如何實現開放網路的共識

### 工作量謎題

PoW（Proof of Work）謎題的結構：找一個 `nonce`，使得：

```
  SHA256(block_header || nonce) < target
```

`target` 是一個閾值，越小 → 謎題越難 → 平均要嘗試越多次才能找到。Bitcoin 每 2016 個區塊調整一次難度，目標是全網平均每 10 分鐘出一個區塊。

```
  Hash 輸出是均勻分佈在 [0, 2²⁵⁶) 的隨機數。
  target = 2²⁵⁶ / difficulty
  每次嘗試成功機率 = target / 2²⁵⁶ = 1 / difficulty

  全網每秒嘗試次數 = hashrate（算力）
  預期出塊時間 = difficulty / hashrate
```

「解謎」不可偽造——SHA256 是單向函數，你不能倒推 nonce，只能暴力嘗試。而且解謎結果可以立即驗證（一次 SHA256）。這個「解難容易驗證」的不對稱性是 PoW 的核心。

### 最長鏈規則（Nakamoto Consensus Rule）

每個節點都保存一條「最長鏈」（嚴格說是累計 PoW 最多的鏈）。當有兩條競爭鏈時，累計 PoW 最多的那條獲勝。

```
  鏈 A: Genesis ─ B₁ ─ B₂ ─ B₃ ─ B₄ ─ B₅    ← 5 個區塊
  鏈 B: Genesis ─ B₁ ─ B₂ ─ B₃' ─ B₄' ─ B₅' ─ B₆'  ← 6 個區塊

  所有誠實節點收到這兩條鏈後：選擇鏈 B（更長）
  鏈 A 上 B₃ 之後的區塊變成「孤塊（orphan block）」
```

**為什麼這能達到共識？** 因為建構鏈需要算力，而誠實節點掌握了大部分算力。只要誠實節點的算力超過攻擊者，最終誠實節點建構的鏈總會比攻擊者的鏈更長。

### 機率性 Finality

這是 Nakamoto 共識和 BFT 最根本的差異：**沒有「這個區塊已 commit、永遠不會回頭」的確定性時刻**。取而代之的是：

```
  區塊被確認的確信度隨「在它之後疊加的區塊數」指數增長：

  區塊 B 之後有 k 個確認：
    攻擊者要讓 B 被撤銷，必須在誠實網路領先 k 個區塊的情況下
    追上並超越誠實鏈。
    
  設攻擊者算力佔比 q < 0.5：
    P(成功撤銷 | 已落後 k 個) ≈ (q/p)^k，其中 p = 1 - q

  實際數字（Bitcoin，q = 0.1 即攻擊者有 10% 算力）：
    k=1:  P ≈ 0.20
    k=6:  P ≈ 0.0010（「6 個確認」的標準是從這來的）
    k=10: P ≈ 0.00009
    k=30: P ≈ 2.2×10⁻¹⁵
```

中本聰在原始論文附錄用泊松分佈和隨機遊走推導了這個公式。推導的直覺：

```
  設攻擊者算力佔比 q，誠實算力佔比 p = 1 - q，q < 0.5。
  攻擊者目前落後誠實鏈 k 個區塊，想追上。
  
  這是一個**帶有偏移的隨機遊走**：
    每個區塊：
      機率 p：誠實找到新塊 → 差距 +1（攻擊者更落後）
      機率 q：攻擊者找到新塊 → 差距 -1（攻擊者追上一步）
    
  q < p 時，隨機遊走有向上的偏移，「差距趨近於 0」的機率隨 k 指數衰減。
  
  P(攻擊者追上 | 落後 k 個) = (q/p)^k
  
  代入 q=0.1, p=0.9：
    k=1:  (0.1/0.9)^1 ≈ 0.111
    k=6:  (0.1/0.9)^6 ≈ 0.0010
    k=10: (0.1/0.9)^10 ≈ 0.000016
```

（這是近似值；中本聰論文附錄用泊松分佈修正了「攻擊者一開始可能超前」的邊界條件，結果類似。）

「6 個確認」這個業界慣例就是在 q=0.1 的假設下讓成功機率低於 0.1%。

**關鍵點**：這個確信度永遠不到 100%，但指數衰減讓它實務上迅速趨近於 1。這和 Raft/PBFT 的「quorum 多數決後確定 commit」是根本不同的保證型別。

## 與傳統共識的根本差異

| 維度 | Raft / Paxos | PBFT | Nakamoto (PoW) |
|---|---|---|---|
| **許可/開放** | 許可制（known membership） | 許可制 | 開放（任何人加入） |
| **Finality** | 確定性（quorum commit 後絕對不回頭） | 確定性 | 機率性（指數衰減） |
| **同步假設** | 非同步可達（GST 後） | 部分同步 | 同步（依賴傳播延遲比出塊時間短） |
| **節點規模** | 幾個到幾十個 | 幾十個（f 小則 3f+1 小） | 幾萬個 |
| **容錯型別** | Crash-fault tolerant | Byzantine-fault tolerant | 算力多數（誠實 > 50%） |
| **Sybil 防禦** | PKI / 靜態成員清單 | PKI / 靜態成員清單 | PoW 謎題成本 |
| **Liveness** | 一旦 partition 修復就恢復 | GST 後保證 | 算力不被 51% 掌控時保證 |
| **Throughput** | 高（幾千到幾萬 TPS） | 中（幾百 TPS） | 低（~7 TPS，Bitcoin） |

最重要的一行是 **Finality**。一個 committed Raft entry 是無法被撤銷的——如果你在 Raft 上 read committed 值，你拿到的就是系統認定的最終值。Nakamoto 共識沒有這個保證；「6 個確認」只是一個工程實務的門檻，不是協定層的終態。

## 底層機制：區塊結構與鏈接

PoW 如何保證歷史不可竄改？靠鏈式 hash 結構：

```
  每個區塊 B 的結構：
  ┌────────────────────────────────────┐
  │ prev_hash = SHA256(上一個區塊)     │ ← 這條鏈讓每個區塊「引用」前一個
  │ merkle_root（所有交易的 Merkle 根）│
  │ timestamp                          │
  │ difficulty_target                  │
  │ nonce  ← 這個找對了才讓 hash < target
  └────────────────────────────────────┘
  block_hash = SHA256(這個區塊的完整內容)

  鏈：
  Genesis ─prev_hash─> B₁ ─prev_hash─> B₂ ─prev_hash─> B₃ ...
```

**為什麼歷史難以竄改**：如果攻擊者想修改 B₂ 裡的某筆交易，B₂ 的 hash 就變了。B₃ 的 `prev_hash` 指向舊的 B₂ hash，就不合法了——攻擊者必須重新找 B₃ 的 nonce。重找 B₃ 之後，B₄ 也不合法……必須重做整條鏈。

**PoW 把「重寫歷史的成本」量化為「重算 k 個區塊的 PoW」**——在誠實算力同時也在延伸鏈的情況下，攻擊者要追上，需要的算力超過誠實網路，才能在時間競賽中勝出。

### Merkle 樹：高效驗證交易

每個區塊裡可能有幾千筆交易。`merkle_root` 是這些交易的 Merkle tree 的根 hash：

```
         merkle_root
        /            \
    hash_01          hash_23
   /       \        /       \
hash_0   hash_1  hash_2   hash_3
  |         |       |        |
 TX₀       TX₁    TX₂      TX₃
```

性質：只要改了任何一筆交易 TX₂，hash_2 變 → hash_23 變 → merkle_root 變 → block_hash 變 → nonce 要重找。而且「某筆 TX 在這個區塊裡」可以用 O(log n) 個 hash 的 proof 驗證，不需要下載所有交易（SPV 驗證的基礎）。

## 51% 攻擊：掌握多數算力能做什麼

### 機制

若攻擊者掌握超過 50% 的全網算力（算力多數），他能做到：

```
  雙花攻擊（Double-spending）：
  
  Step 1: 攻擊者向商家 M 傳送交易 TX₁（「付款給 M 100 BTC」）
           → 商家等 6 個確認後發貨

  Step 2: 攻擊者私下在另一條鏈上建構 TX₂（「把這 100 BTC 付給自己」）
           （這條鏈是秘密的，不廣播）

  Step 3: 商家的鏈確認了 TX₁，發了貨

  Step 4: 攻擊者把私下建構的更長鏈廣播出去
           → 誠實節點遵循最長鏈規則 → 接受新鏈
           → TX₁ 被 TX₂ 取代 → 商家的款項憑空消失
           
         誠實鏈: ... ─ TX₁ ─ B₂ ─ B₃ ─ B₄ ─ B₅ ─ B₆  (6 確認)
         攻擊鏈: ... ─ TX₂ ─ B₂'─ B₃'─ B₄'─ B₅'─ B₆'─ B₇'─ B₈' (更長，勝出)
```

攻擊者還能做的：
- **審查（censorship）**：拒絕把特定交易打包進區塊，實際上讓那些交易永遠無法確認。
- **孤塊攻擊**：故意讓其他礦工的區塊成為孤塊，自己獲得所有區塊獎勵（礦池壟斷）。

攻擊者**不能做**的（即使有 51%）：
- **偽造交易**（沒有對應私鑰就無法建立有效的數位簽章）。
- **憑空創造比特幣**（PoW 只決定誰的鏈被接受，不能覆蓋 coinbase 限制）。
- **修改共識規則**（這需要所有節點軟體升級，不是算力決定的）。

### 為何 51% 攻擊成本高

**現實的護城河**：Bitcoin 的算力已高到 51% 攻擊在實際上代價極高：

```
  2024 年 Bitcoin 全網算力：~600 EH/s（exahash/s）
  51% 需要：~300 EH/s

  現今最高效的 ASIC：~100 TH/s，成本約 3,000 USD
  所需 ASIC 數量：3×10¹⁸ / 10¹⁴ ≈ 3,000,000 台
  僅設備成本：≈ 90 億 USD
  電力成本：≈ 每小時數百萬 USD

  而且：你買這麼多 ASIC 本身就會推高價格、讓全網難度上升
```

對小型 PoW 鏈（算力規模小），51% 攻擊的門檻就低得多——Ethereum Classic、Bitcoin Gold 都曾被成功攻擊過。

## 自私挖礦（Selfish Mining）

這是一個更精妙的攻擊：即使沒有 51% 算力，也能讓誠實礦工的收入降低。

**策略**：找到一個新區塊時，不立即廣播，而是繼續在上面祕密延伸：

```
  誠實礦工：找到 B₅ → 立刻廣播 → 繼續找 B₆

  自私礦工：找到 B₅ → 不廣播 → 繼續找 B₆
            如果找到 B₆ → 同時廣播 B₅ 和 B₆
            → 誠實礦工剛廣播的 B₅' 變成孤塊（因為已有更長鏈）
            → 誠實礦工浪費的 PoW 等比例提高了自私礦工的收益佔比
```

2013 年 Eyal 和 Sirer 的論文分析顯示，一個掌握 33% 算力的礦池若採用自私挖礦，其預期收益率可以超過 33%（透過讓其他礦工的工作成為孤塊）。

**防禦**：協定設計上讓「提前廣播」有更高獲利（例如在 uncle/ommer 機制裡給孤塊也一些獎勵），降低自私挖礦的期望收益。Ethereum 早期就有這種 uncle block 機制。

## Fork 與 Reorg

**Fork（分叉）** 發生的原因：兩個礦工幾乎同時找到不同的合法區塊，廣播到不同的節點群，暫時形成兩條並行的鏈。

```
  正常的短暫 fork：
    ... ─ B₄ ─ B₅a  ← 礦工 A 先找到，廣播到一半網路
         └─ B₅b  ← 礦工 B 同時找到，廣播到另一半網路

    下一個區塊找到（假設在 B₅a 上延伸）：
    ... ─ B₄ ─ B₅a ─ B₆ ← 這條更長，所有節點切換
              B₅b 成為孤塊
```

**Reorg（重組）**：指節點切換到一條更長鏈時，之前認為「確認」的一些區塊被撤回。深度 1-2 的 reorg 在 Bitcoin 裡偶爾發生（短暫 fork 解決），深度 6+ 的 reorg 是攻擊事件的訊號。

## PoS 如何用權益替代算力

PoS（Proof of Stake）的設計動機是：PoW 消耗大量電力，而電力消耗本身沒有「除了讓攻擊昂貴以外」的價值——這是純粹的成本。PoS 試圖用「抵押代幣（stake）」替代算力：

```
  PoW 的安全預算來自：電費 + 硬體折舊（消耗真實物理資源）
  PoS 的安全預算來自：鎖定的代幣（消耗機會成本，但不消耗能源）
```

在 PoS 裡，「投票提出/確認區塊的權重」不是你的算力，而是你抵押的代幣數量：

- 掌握 51% 抵押量 → 等同於 PoW 的 51% 算力，能控制共識。
- 攻擊代價：購買/鎖定大量代幣；攻擊行為被偵測後，代幣被 slashing 沒收，讓攻擊「自我懲罰」。

**PoS 的安全模型差異**：

| | PoW | PoS |
|---|---|---|
| 攻擊成本 | 算力 + 電費（外生資源） | 代幣（內生資源） |
| 51% 攻擊後果 | 攻擊者電費打水漂 | 攻擊者代幣被 slashing |
| Long-range 歷史 | 無（重寫歷史要重算 PoW） | 有（舊金鑰可重建假歷史，需弱主觀性） |
| 能源消耗 | 高 | 低 |
| Finality | 機率性（和 PoW 一樣）或帶 finality gadget（確定性） | 通常帶 finality gadget（Casper FFG → 確定性） |

現代 PoS 系統（Ethereum）通常在 Nakamoto 的「哪條鏈最重」邏輯上，**疊加**一個 BFT 風格的 finality gadget（Casper FFG），讓超過 2/3 質押量投票過的 epoch 變成確定終態。這樣 PoS 就同時有了 PoW 的開放性和 BFT 的確定性 finality——代價是協定複雜度大幅提升。

## 踩雷集錦

1. **「區塊鏈 = 不可竄改」**：不可竄改說的是「攻擊者要竄改歷史、讓全網接受新版本的代價很高」，不是密碼學上的不可能。有足夠算力（51%）就能重寫歷史。「不可竄改」是一個關於攻擊成本的陳述，不是關於不可能性的陳述。

2. **「機率性 finality 比確定性 finality 差」**：不一定。確定性 finality（Raft/PBFT）要求許可制節點清單，節點數規模受限。機率性 finality 允許開放、全球、幾萬個節點的網路——這個尺度下確定性 finality 根本跑不動。這是不同的設計取捨，不是一個優劣的比較。

3. **「6 個確認是絕對安全的」**：錯，「6 個確認」在 q=0.1 的假設下讓攻擊成功率低於 0.1%，但沒有「絕對」。而且 6 個確認的安全性強烈依賴「攻擊者算力確實遠低於 50%」——如果某次攻擊者偷偷累積了 40% 算力，6 個確認就遠不夠。

4. **「PoS 的 slashing 讓 51% 攻擊不可能」**：讓它「更貴」而不是「不可能」。Slashing 必須依賴 slashing 條件的偵測和執行，而大規模協同攻擊（攻擊者同時控制 2/3 質押量）可以通過讓 slashing 交易無法被打包進鏈來阻止自己被 slash。這在 Ch 35 有更細的討論。

5. **「Nakamoto 共識不能用於企業系統」**：在不需要開放性的場景（許可制聯盟鏈），PoW 是一個糟糕的選擇——你已經知道誰是節點，用 BFT 協定效率更高、finality 確定。把 PoW 用在許可制網路是把開放網路的解法強行用在它不適合的場景。

## 進階：再往深一層

**Selfish Mining 的形式分析**：Eyal & Sirer 2013 論文「Majority is not Enough: Bitcoin Mining is Vulnerable」的完整分析，包括「γ = 攻擊者能搶先傳播的機率」對臨界值的影響。完整模型顯示不同 γ 下的攻擊臨界算力可以低到 25%。

**GHOST 協定**：Ethereum 早期用來替代「最長鏈」的「最重子樹（Greedy Heaviest Observed Subtree）」規則，讓 uncle block 也部分貢獻鏈的「重量」，提高出塊頻率（15 秒）卻不因此增加 reorg 脆弱性。

**Selfish Mining 防禦的協定設計**：Bitcoin NG（Pass & Shi）把出塊者（key block）和交易打包者（micro block）分離，降低孤塊率；Ethereum 的 uncle reward 讓孤塊礦工也能獲得部分獎勵，降低自私挖礦的誘因。

## 對比與取捨

Nakamoto 共識和傳統 BFT 是兩個完全不同的共識家族，分別針對不同的使用場景：

| 維度 | Nakamoto PoW | 許可制 BFT（PBFT/Raft） |
|---|---|---|
| **適合節點數** | 幾千到幾萬個 | 幾個到幾十個 |
| **節點加入** | 無需許可，開放 | 需要管理員授權 |
| **Finality 型別** | 機率性（指數衰減） | 確定性（quorum commit 後永久） |
| **Finality 速度** | 幾十分鐘（6 確認） | 幾百毫秒 |
| **Throughput** | 極低（~7 TPS Bitcoin） | 高（幾千到幾萬 TPS） |
| **能源消耗** | 極高（PoW） | 極低（訊息傳遞） |
| **Sybil 防禦** | 算力成本 | PKI 許可制 |
| **51% 攻擊** | 可能（但高成本） | 不適用（節點已知） |
| **liveness 保證** | 算力多數誠實時保證 | f < N/3 時，GST 後保證 |

**選擇 Nakamoto 的場景**：
- 真正需要無需許可的開放參與（任何人能成為礦工/驗證者）
- 節點身份不可信任或難以建立 PKI
- 安全性靠算力規模而非節點信任

**選擇許可制 BFT 的場景**：
- 節點數少、身份已知（企業聯盟鏈、內部分散式系統）
- 需要確定性 finality（金融交易、需要立即結算的場景）
- 需要高吞吐量和低延遲

把 PoW 用在許可制系統（你已經知道有哪些節點）是常見的過度工程——在那個場景下，PBFT 效率更高、finality 更確定，PoW 的算力消耗完全是浪費。

## 踩雷集錦

1. **「區塊鏈 = 不可竄改」**：不可竄改說的是「攻擊者要竄改歷史、讓全網接受新版本的代價很高」，不是密碼學上的不可能。有足夠算力（51%）就能重寫歷史。「不可竄改」是一個關於攻擊成本的陳述，不是關於不可能性的陳述。

2. **「機率性 finality 比確定性 finality 差」**：不一定。確定性 finality（Raft/PBFT）要求許可制節點清單，節點數規模受限。機率性 finality 允許開放、全球、幾萬個節點的網路——這個尺度下確定性 finality 根本跑不動。這是不同的設計取捨，不是一個優劣的比較。

3. **「6 個確認是絕對安全的」**：錯，「6 個確認」在 q=0.1 的假設下讓攻擊成功率低於 0.1%，但沒有「絕對」。而且 6 個確認的安全性強烈依賴「攻擊者算力確實遠低於 50%」——如果某次攻擊者偷偷累積了 40% 算力，6 個確認就遠不夠。不同價值的交易應設不同的確認數門檻。

4. **「PoS 的 slashing 完全解決了 nothing-at-stake」**：大幅緩解但沒有「完全解決」。Slashing 的偵測有視窗限制，極端情況（大量驗證者共謀、長時間分區後的重組）仍有邊界案例。現代 PoS 設計要求對 slashing 的情境有深入分析，不能假設一個 slashing 條件就護身。

5. **「Nakamoto 共識不能用於企業系統」**：在不需要開放性的場景（許可制聯盟鏈），PoW 是一個糟糕的選擇——你已經知道誰是節點，用 BFT 協定效率更高、finality 確定。把 PoW 用在許可制網路是把開放網路的解法強行用在它不適合的場景。

6. **「最長鏈就是正確鏈」**：最長鏈是 Nakamoto 共識下最「重」的歷史，也是誠實多數遵循的那條鏈。但如果攻擊者短暫掌握 51% 算力，他可以讓一條含有雙花的鏈變成「最長鏈」。「最長鏈」是共識機制，不是真理保證。

## 本章重點整理

- Nakamoto 共識解決的是「開放、匿名、任意節點數的網路裡的拜占庭共識」——傳統 BFT 根本無法在這個設定下啟動。
- 機制：PoW 讓「說話權」有物理成本（算力）；最長鏈規則讓所有節點知道哪個歷史最「重」。
- 機率性 finality：確認越多、被撤銷機率以指數級衰減；「6 個確認」是在 10% 攻擊算力假設下，成功撤銷機率降到 0.1% 以下的經驗門檻。
- 51% 攻擊能做：雙花、審查、孤塊攻擊。不能做：偽造簽章、憑空創造幣、修改協定規則。
- 自私挖礦：算力 33% 以上就能在不正式 51% 的情況下獲得超比例收益，透過讓誠實礦工工作成為孤塊實現。
- PoS 用代幣抵押替代算力，配合 slashing 自我懲罰機制；現代 PoS 加 finality gadget 後可以獲得確定性 finality，但協定複雜度大幅提升。
