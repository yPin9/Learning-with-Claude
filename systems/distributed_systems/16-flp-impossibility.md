# Ch 16 — FLP 不可能定理

> **目標**：讀懂分散式理論裡最重要的負面結果——FLP（Fischer-Lynch-Paterson）不可能定理。搞清楚它到底陳述了什麼、證明的骨架怎麼走（configuration / bivalent / univalent、初始 bivalent 的存在性、把 bivalent 「拖」到下一個 bivalent 的 critical step 論證），以及它**沒有**說什麼。這是純理論章：沒有程式碼，但有嚴謹的推導和 ASCII 圖。完整的形式化證明細節我會給骨架與直覺，並明確指向原論文哪一節去讀——**這是誠實的理論標注，我不會假裝把一個 1985 年的形式化證明逐字重寫給你**。

## 為什麼需要這個？

Ch 15 我們把共識定義成三個性質：Agreement、Validity、Termination。前兩個是 safety，第三個是 liveness。當時我埋了一句話：**在完全非同步的世界裡，只要有一個節點可能 crash，你就沒辦法同時保住 safety 和 liveness。** 這一章就是把那句話證明出來。

為什麼要在乎一個「不可能」的結果？因為它**劃定了所有人努力的邊界**。在 FLP 之前（1985 年之前），無數工程師和研究者試圖設計「完美的非同步共識協定」——保證正確、保證在任何情況下都終止。他們全都失敗了，但沒人知道是自己不夠聰明，還是這件事根本做不到。

FLP 給了答案，而且是最壞的那種答案：**做不到，不是你的問題，是宇宙的問題。** 一旦你知道「非同步 + 一個 crash」下不存在保證終止的確定性共識，你就不再浪費生命去追那個不存在的東西，而是轉向問對的問題：「我要放寬哪個假設，才能繞過它？」（這就是下一章 Ch 17 的全部內容）。

負面結果的價值就在這裡。它跟停機問題（halting problem）、Gödel 不完備定理是同一類東西——不是告訴你怎麼做，而是告訴你**哪些方向注定是死路**，讓你不要撞牆。

## 定理的精確陳述

先把定理一字不差地立起來，因為 FLP 極其容易被誤引。

> **FLP 定理（1985）**：在一個**非同步（asynchronous）**訊息傳遞系統中，若允許**至多一個節點發生 crash 失敗**，則**不存在**一個能同時滿足 agreement、validity 與 termination 的**確定性（deterministic）**共識演算法。

每個限定詞都是承重牆，逐個拆開：

- **非同步**：訊息延遲沒有已知上界，節點處理速度沒有已知下界，沒有全域時鐘。關鍵後果——**你無法區分「一個節點當機了」和「它只是很慢 / 它的訊息還在路上」**。這個「無法區分」是整個不可能結果的心臟。
- **至多一個 crash**：注意是**一個**。不是拜占庭（不說謊），不是很多個。只要**可能**有一個節點會停下來，就足以讓共識不可能。這是定理最驚人的地方——連最溫和的失敗、最少的數量，都足以擊垮它。
- **確定性**：演算法沒有隨機性。給定相同的狀態和相同的訊息序列，它每次做完全相同的事。（這個限定詞是 Ch 17 隨機化路線的突破口——放棄確定性就能繞過。）
- **不存在**：這是「對所有可能的演算法」的全稱否定。不是「現有的演算法都不行」，是「任何演算法都不行，包括還沒被發明的」。要證明這種全稱否定，只能用歸謬 + 構造：假設有一個正確演算法，然後**構造出一條讓它永遠決定不了的執行路徑**。

### 它「沒有」說什麼——這比它說了什麼更常被搞錯

- **FLP 不是說「非同步共識永遠做不到」**。你每天在用的 etcd、ZooKeeper、Spanner 全都在非同步的真實網路上跑共識，而且好好的。FLP 說的是「不能**保證**在**所有**情況下終止」——它允許有一條（機率為 0 但存在的）永不終止的執行路徑。
- **FLP 卡的是 liveness（termination），不是 safety**。真實系統的做法是：**永遠不違反 safety**（絕不腦裂、絕不丟已提交的值），但**在極端網路條件下可能暫時無法終止**（卡住、選不出 leader、無法 commit）。這正是所有實用共識協定的共同選擇——寧可卡住，也不出錯。
- **那條「永不終止」的路徑在實務上機率為 0**。FLP 構造的是一個對抗性的（adversarial）、無限精準地卡在臨界點的訊息排程。真實網路不會這麼壞心地永遠精準卡點，所以實務上系統總會終止。FLP 是理論邊界，不是實務障礙——但它逼你誠實地承認「我的系統理論上可能卡住」，這份誠實在設計時是無價的。

## 先建立直覺：整個證明在幹嘛

在鑽進形式化之前，先給你一張全景。整個 FLP 證明是一個歸謬法，三步：

```
  假設：存在一個正確的確定性共識演算法 A（它一定終止、一定不腦裂）

  第 1 步：證明 A 一定有一個「bivalent」的初始狀態
           （bivalent = 未來還可能決定 0，也還可能決定 1——命運未定）

  第 2 步：證明從任何 bivalent 狀態，永遠能走一步、走到「下一個」bivalent 狀態
           （關鍵引理：你能一直維持「命運未定」）

  第 3 步：把第 2 步無限套用 → 構造出一條永遠停在 bivalent 的執行
           → A 永遠決定不了 → 違反 termination → 矛盾

  結論：這樣的 A 不存在。□
```

整個證明的靈魂是一個對抗性的排程器（adversary scheduler）：它看得到系統的完整狀態，並且**故意挑訊息的送達順序**，讓系統永遠停在「還沒決定」的臨界狀態。它的武器只有一個——**延遲訊息**（非同步允許任意延遲）。它從不丟訊息、從不讓節點說謊，甚至只需要讓一個節點看起來「很慢」。就靠這一招，它能讓任何確定性演算法永遠決定不了。

## 核心概念一：configuration（配置）

**configuration（配置）** 是整個系統在某一瞬間的完整快照：每個節點的內部狀態 + 網路中所有「已送出但還沒送達」的訊息（in-flight messages，論文稱 message buffer）。

一個 configuration `C` 加上「送達某一則訊息 m」這個**事件（step / event）**，會轉移到一個新的 configuration `C' = e(C)`。因為演算法是確定性的，`C` 和 `e`（送達哪則訊息）一旦定了，`C'` 就唯一確定。

```
   configuration C                    configuration C'
  ┌──────────────────┐   送達訊息 m   ┌──────────────────┐
  │ 各節點狀態         │  ───────────► │ 各節點狀態（更新）  │
  │ in-flight: {m,...}│    (step e)    │ in-flight: {...}   │
  └──────────────────┘               │  可能多了新訊息      │
                                      └──────────────────┘
```

一條**執行（run / schedule）** 就是從初始 configuration 開始，一連串 step 串起來的序列。非同步的力量在於：排程器可以**任意選下一個要送達哪則 in-flight 訊息**（只要求每則訊息最終會被送達——公平性，否則太容易作弊）。

一個關鍵的技術引理（論文 Lemma 1，本章不展開證明）：**互不干擾的兩個 step 可交換（commutativity）**。如果訊息 m1 送給節點 p、m2 送給另一個節點 q，那先送 m1 再送 m2，和先送 m2 再送 m1，到達的是**同一個** configuration。這個「菱形交換」性質是後面 critical step 論證的骨架。

## 核心概念二：bivalent vs univalent（雙價 vs 單價）

這是整個證明最核心的定義。給定一個 configuration `C`，看**從它出發、所有可能的執行**最終會 decide 出什麼：

- **0-valent**：從 C 出發的每一條執行，最終都只會 decide `0`。命運已定為 0。
- **1-valent**：從 C 出發的每一條執行，最終都只會 decide `1`。命運已定為 1。
- **univalent（單價）**：0-valent 或 1-valent，統稱——**命運已定**，不管排程器怎麼排，結果都一樣。
- **bivalent（雙價）**：存在一條執行會 decide 0，也存在**另一條**會 decide 1。**命運未定**——結果還取決於接下來訊息怎麼排。

```
              configuration C
                     │
        ┌────────────┼────────────┐
        │            │            │       所有從 C 出發的執行……
    某執行→0     某執行→0      某執行→1

     如果全部都 →0   ⇒ C 是 0-valent（univalent）
     如果有的→0 有的→1 ⇒ C 是 bivalent（命運未定，危險！）
```

**為什麼 bivalent 是致命的？** 因為只要系統停在一個 bivalent configuration，它就**還沒決定**——它此刻的命運未定，不能宣告 decide（一旦宣告 decide v，那 configuration 就必須是 v-valent，否則違反 agreement：另一條執行會 decide 出不同的值，腦裂）。所以：

> **停在 bivalent = 還沒 decide。如果排程器能讓系統永遠停在 bivalent，系統就永遠不 decide → 違反 termination。**

整個證明的目標就變成：**證明排程器能永遠維持 bivalent。** 這要兩步：先證明起點就是 bivalent（下一節），再證明能從 bivalent 走到 bivalent（再下一節）。

**一個微型例子幫你抓住 bivalent 的手感**。設想三節點、輸入分別是 `(1, 0, 0)`，正在跑某協定。此刻網路裡有兩則 in-flight 訊息 `m1`（要送給 P0）、`m2`（要送給 P1）：

```
   當前 configuration C：
     · 若排程器先送 m1、拖住 m2，且之後 P1 一直很慢
         → 系統可能沿著「多數是 0」的路徑走 → decide 0
     · 若排程器先送 m2、拖住 m1，且之後 P0 一直很慢
         → 系統可能沿著「P0 的 1 被看見」的路徑走 → decide 1

   兩條路徑都合法（都只是延遲訊息，沒丟沒說謊）
     → C 同時能通向 0 也能通向 1 → C 是 bivalent（命運未定）
```

注意排程器**沒有做任何非法的事**——它只是選了不同的訊息送達順序，就把系統推向不同的命運。這正是 FLP 的核心威脅：**在非同步下，「訊息送達順序」這個排程器完全掌控的東西，足以決定最終結果**。證明要做的，就是說明排程器永遠能保住這種「兩條路都還開著」的狀態。

## 證明骨架第 1 步：初始 configuration 必存在 bivalent

**引理**：任何正確的共識演算法，都存在一個 bivalent 的初始 configuration。

**直覺論證**（論文 Lemma 2）：初始 configuration 由每個節點的輸入值（0 或 1）決定。考慮這一排初始 configuration，第 i 個是「前 i 個節點提議 1、其餘提議 0」：

```
  C0 = (0,0,0,...,0)  ← 全 0，由 validity 這是 0-valent
  C1 = (1,0,0,...,0)
  C2 = (1,1,0,...,0)
   ...
  Cn = (1,1,1,...,1)  ← 全 1，由 validity 這是 1-valent
```

兩端由 **validity** 定死：全 0 只能 decide 0（0-valent），全 1 只能 decide 1（1-valent）。這一排從 0-valent 走到 1-valent，中間**必然存在相鄰的兩個** `Ci`、`Ci+1`，它們只差一個節點的輸入值。

現在關鍵：假設**沒有任何**初始 configuration 是 bivalent（歸謬），那每個 Ci 不是 0-valent 就是 1-valent。那上面那排裡，必有相鄰的 `Ci`（0-valent）和 `Ci+1`（1-valent），兩者只差節點 p 的輸入。但如果節點 p **一開始就 crash**（FLP 允許一個 crash），那其他節點根本分不出自己在 Ci 還是 Ci+1（唯一的差別是 p，而 p 死了不出聲）——它們必須在兩個 configuration 裡做出**相同**的決定。可是 Ci 要 decide 0、Ci+1 要 decide 1，矛盾。

所以「沒有 bivalent 初始 configuration」的假設不成立。**必存在一個 bivalent 的初始 configuration。** 起點就命運未定。□（骨架）

> 這一步就已經用到了 FLP 的核心武器：**「一個節點可能 crash」讓其他節點無法區分兩個只差那個節點的 configuration。** 「無法區分」是貫穿全證明的關鍵——非同步 + 一個 crash，合起來製造出「你永遠不確定對方是死了還是慢了」的模糊地帶。

## 證明骨架第 2 步：critical step——從 bivalent 拖到 bivalent

這是全證明的技術核心，也是最難的一步（論文 Lemma 3）。

**引理**：設 `C` 是 bivalent configuration，`m` 是某則 in-flight 訊息。那麼**存在一種排程**，先送達其他一些訊息、最後才送達 `m`，使得送達 `m` 之後到達的 configuration `C'` **仍然是 bivalent**。

換句話說：**排程器總能找到一步走法，讓系統從 bivalent 走到下一個 bivalent，同時不失去對任何一則訊息「最終要送達」的承諾。** 它靠的就是「延後某則訊息」這一招。

**論證骨架（歸謬 + 菱形交換）**：假設從 bivalent `C` 出發，送達 `m` 之後**所有**能到的 configuration 都變成 univalent（也就是排程器被逼著非決定不可）。定義 `D = {送達 m 後可達的 configuration}`。因為 `C` 是 bivalent，`D` 裡必然**同時有** 0-valent 的（叫它 `E0`）和 1-valent 的（叫它 `E1`）——否則 C 早就 univalent 了。

接下來用「兩個相鄰配置只差一個 step」和前面說的**菱形交換性質**，可以推出：存在一個「臨界步驟（critical step）」——就是送達 `m` 這一步——它把命運從未定逼成已定，而且 `E0` 和 `E1` 之間只差**一個 step**（送達某則訊息 `m'` 給某個節點 `p`）。

於是矛盾這樣爆出來：

```
        C（bivalent）
        │  先送 m'（給 p），再送 m ──► 得到某 univalent 配置 X
        │  先送 m（critical），再送 m' ──► 得到另一 univalent 配置 Y
        │
   由菱形交換：若 m、m' 送給不同節點，X 和 Y 應該相同
                → 但一個是 0-valent、一個是 1-valent → 不可能相同 → 矛盾！

   若 m、m' 都送給同一個節點 p：
        讓 p 在收到 m'/m 之前「crash」（延遲它，非同步允許）
        → 其他節點分不出到底發生了哪個順序
        → 它們得對兩種都做相同決定，但一邊該 0 一邊該 1 → 矛盾！
```

無論 `m` 和 `m'` 是送給不同節點（用菱形交換打臉）還是同一個節點（用「讓 p 慢一步 / crash 一下，其他人分不出」打臉），都推出矛盾。所以「送達 m 後全變 univalent」的假設錯了——**必然存在一種送法，讓送達 m 後仍是 bivalent。** □（骨架）

這一步再次用到那把萬能鑰匙：**「一個節點可能 crash / 任意慢」讓你能製造出兩個外界無法區分、卻該有不同命運的情境，從而逼出矛盾。**

## 證明骨架第 3 步：無限拖延，構造永不終止的執行

有了前兩步，收尾很直接：

1. 由第 1 步，從一個 **bivalent 初始 configuration** 出發。
2. 由第 2 步，總能走一步到**下一個 bivalent configuration**，而且這一步可以是「送達那則被拖最久的訊息」——所以我們能保證**每則訊息最終都會被送達**（公平性 / no message lost forever），同時**永遠停在 bivalent**。
3. 把第 2 步無限套用，得到一條**無限長、每則訊息都終會送達、卻永遠停在 bivalent** 的執行。
4. 永遠 bivalent = 永遠沒 decide（decide 需要 univalent）。這條執行違反 **termination**。

於是我們構造出了一條合法的（訊息公平送達、至多一個節點慢/crash）執行，讓假設中「正確」的演算法 A 永遠不終止。與 A 的正確性矛盾。**所以這樣的 A 不存在。** 定理得證。□

```
  bivalent ──step──► bivalent ──step──► bivalent ──step──► bivalent ──► ...
  （初始）           （拖一步）          （再拖一步）         （永遠拖下去）
                                                            ▲
                          排程器只用「延後某則訊息」這一招，   │
                          就讓系統永遠決定不了                 └─ 永不 decide
```

**這條執行的本質**：排程器每次都在「快要決定」的臨界點，把那則會敲定命運的訊息**再延後一點**，並先塞別的訊息進去把命運重新攪成未定。真實網路不會這麼精準地永遠卡點，但**理論上這條路徑存在**，這就足以否證「保證終止」。

## 對比與取捨：FLP 在整片不可能結果地圖裡

FLP 不是孤例。把它和相鄰的結果並排，才看得清它的位置：

| 結果 | 模型 | 結論 | 和 FLP 的關係 |
|---|---|---|---|
| **FLP（1985）** | 非同步，1 crash，確定性 | 共識不可能保證終止 | 本體 |
| **兩軍問題（Two Generals）** | 非同步，訊息會丟 | 對「同時進攻」不可能達成確定性一致 | FLP 的更古老、更弱的親戚 |
| **CAP（2000, 2002）** | 網路分區 | C、A、P 三選二 | 分區下 FLP 的工程化陳述 |
| **Dolev-Strong 下界** | 同步，f crash | 至少需 f+1 輪 | 同步下有解，但有輪數下界 |
| **拜占庭下界** | 同步/部分同步 | 需 3f+1 節點 | 換更惡的失敗模型 |

看出來了嗎？**只要把「非同步」換成「同步」，共識就有解**（Dolev-Strong）——因為同步下你能靠 timeout 可靠地偵測 crash（「等超過已知上界還沒回，它一定死了」），那個「分不出死了還是慢了」的模糊地帶就消失了，FLP 的武器失效。這直接指向了 Ch 17 的第一條繞路：**假裝網路最終會變同步**。

## 踩雷集錦

1. **「FLP 說共識做不到，所以 Paxos / Raft 是錯的 / 不可能正確」**：完全誤解。Paxos / Raft **從不違反 safety**（它們永遠不腦裂），它們只是**在理論上可能不終止**（極端網路下選不出 leader）。FLP 和它們的正確性毫無衝突——它們正是「犧牲保證終止、換取永不出錯」的教科書範例。

2. **「FLP 需要很多節點當機 / 需要拜占庭失敗才成立」**：恰恰相反，這是 FLP 最震撼的地方——只要**一個**節點**可能**（不是一定）crash，而且是最溫和的 crash（不說謊、只是停下來），就夠了。失敗越少、越溫和，結果越可怕。

3. **「那條永不終止的執行在真實系統裡會發生，所以我的系統會卡死」**：那條執行需要一個**無限精準、對抗性地永遠卡在臨界點**的排程器。真實網路是隨機的、不對抗的，機率上總會「不小心」讓某則關鍵訊息及時送達，把系統推過臨界點。所以實務上系統會終止。FLP 是理論天花板，不是你今晚會遇到的 bug。

4. **「用 timeout 就繞過 FLP 了，所以 FLP 沒意義」**：timeout 確實能繞（它引入了同步假設，見 Ch 17），但**用 timeout 不代表 FLP「錯了」或「沒意義」**。FLP 的意義正是告訴你：**你繞過它的代價，是引入了一個「網路會及時」的假設**——而這個假設在真實世界會被違反（GC 暫停、網路抖動、時鐘跳變），那時你的 timeout 就會誤判，系統就可能出問題。FLP 逼你看清這筆帳。

5. **「bivalent 就是『系統還沒收到夠多票』」**：不是。bivalent 是一個關於**未來所有可能執行**的性質——「存在一條路通向 0、也存在一條路通向 1」。它跟「收了幾票」無關，是關於命運是否已被鎖定。一個收了一大堆訊息的 configuration 仍可能是 bivalent，一個剛開始的也可能已經 univalent。

## 進階：再往深一層

- **讀原論文**：Fischer, Lynch, Paterson,《Impossibility of Distributed Consensus with One Faulty Process》, JACM 1985。它只有 **9 頁**，是分散式領域最短也最重要的論文之一。**Lemma 1**（step 可交換 / commutativity）、**Lemma 2**（初始 bivalent 存在）、**Lemma 3**（critical step，從 bivalent 到 bivalent）是三根支柱。本章給的是骨架與直覺；真正把每個 case 的菱形交換補齊，去讀 Lemma 3 的原文——它比你想像的好讀，證明只有兩三頁。

- **FLP 和「弱化 termination」**：如果把 termination 從「一定終止」弱化成「機率 1 終止」，FLP 就不再適用——這是 Ben-Or 隨機化共識（Ch 17）的突破口。FLP 卡的是**確定性**協定的**保證**終止；一旦引入隨機，那個對抗性排程器就沒法「預測」你下一步、也就沒法永遠精準卡點。

- **failure detector 的角度**：Chandra-Toueg（Ch 17）換了個問法——「要繞過 FLP，我最少需要多強的『偵測誰死了』的能力？」他們證明了 `◇W`（eventually weak，最終弱失敗偵測器）是**能解共識的最弱失敗偵測器**。這把 FLP 從「不可能」翻轉成「可能性的精確條件」，是把負面結果轉成正面工具的漂亮一手。

- **和 halting problem 的類比**：FLP 之於分散式，如同 halting problem 之於可計算性。兩者都是「對所有可能演算法的全稱否定」，都用「假設有解 → 構造反例 → 矛盾」的對角線 / 歸謬手法。理解 FLP 的證明結構，會加深你對「不可能性證明長什麼樣」的直覺。

## 本章重點整理

- **FLP**：非同步系統 + 至多一個 crash + 確定性 → **不存在**保證滿足 agreement/validity/termination 的共識演算法。
- 每個限定詞都是承重牆：**非同步**（分不出死了還是慢了）、**一個 crash**（最溫和最少也夠）、**確定性**（隨機化是突破口）。
- 它卡的是 **liveness（termination），不是 safety**。真實系統的選擇：永不腦裂，但極端下可能不終止。
- 證明三步骨架：**初始必有 bivalent → 能從 bivalent 拖到 bivalent（critical step）→ 無限拖延構造永不終止的執行**。
- 全證明的萬能鑰匙：**「一個節點可能 crash / 任意慢」讓外界無法區分兩個該有不同命運的情境**，由此逼出矛盾。
- 意義不是「共識沒救」，而是「劃定邊界」——想繞過，就得放寬某個假設（下一章）。這份對邊界的誠實，是設計容錯系統時最值錢的東西。
