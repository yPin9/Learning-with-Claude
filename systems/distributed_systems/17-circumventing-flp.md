# Ch 17 — 繞過 FLP

> **目標**：FLP（Ch 16）證明了非同步 + 一個 crash + 確定性下共識不可能保證終止。這一章看真實世界怎麼從那三根柱子的縫隙鑽出去。三條主流路線：**部分同步（partial synchrony / DLS）**、**失敗偵測器（failure detector / Chandra-Toueg）**、**隨機化（randomization / Ben-Or）**。每條路我們都精確指出它**放寬了 FLP 的哪個假設**，以及代價是什麼。搞清楚這三條路，你就理解了 Paxos、Raft、乃至所有實用共識協定「憑什麼能動」的底層授權。

## 為什麼需要這個？

上一章結束在一個尷尬的地方：我們證明了共識在非同步下不可能保證終止，但你明明每天在用 etcd、ZooKeeper、Spanner——它們都在跑共識，而且好好的。這不是矛盾嗎？

不是。FLP 是一個**條件式**的不可能：它說「**在這三個假設同時成立時**不可能」。三個假設——非同步、確定性、可能 crash——只要**鬆動任何一個**，天花板就破了。真實系統做的就是這件事：偷偷放寬一個假設，換回可終止的共識。

關鍵在於**誠實地知道你放寬了哪個**。因為每一條繞路都有代價，而代價往往在「假設被違反」的那一刻找上門。用 timeout 的系統，在 GC 暫停或網路抖動時 timeout 會誤判；用隨機化的系統，終止只是機率上的。**沒有免費的午餐**——FLP 保證了這一點。這一章就是把三張帳單攤開給你看。

先回顧 FLP 的三根柱子，這一章就是在拆它們：

```
   FLP 的三根承重柱（同時成立才有不可能）
   ┌──────────────┬──────────────┬──────────────┐
   │  非同步       │  確定性       │  可能 crash   │
   │ 延遲無上界    │ 無隨機       │ 分不出死/慢   │
   └──────┬───────┴──────┬───────┴──────────────┘
          │              │
     路線 A：部分同步  路線 C：隨機化
     路線 B：失敗偵測器（抽象掉「分不出死/慢」）
          │
     鬆動任何一根 → 天花板破
```

## 先建立直覺：三條路各自在鬆哪根柱子

在細講之前，先一句話把三條路的本質釘死，後面就是展開：

| 路線 | 鬆動哪根柱子 | 核心點子 | 代價 |
|---|---|---|---|
| **A. 部分同步（DLS）** | 非同步 | 假設網路「最終」會變同步（GST 之後延遲有上界） | GST 之前可能不終止 |
| **B. 失敗偵測器** | 非同步（把「偵測死活」抽象成一個模組） | 給協定一個「誰死了」的神諭，就算它偶爾出錯 | 需要一個至少 `◇W` 強度的偵測器 |
| **C. 隨機化（Ben-Or）** | 確定性 | 節點擲硬幣打破對稱，排程器沒法預測你 | 終止只是**機率 1**，可能跑很多輪 |

三條路都不碰「可能 crash」那根柱子——因為 crash 是真實世界的既定事實，你不可能假設節點不會壞。能動的只有「非同步」和「確定性」這兩根。記住這個，後面就不會迷路。

## 路線 A：部分同步（Partial Synchrony / DLS）

這是**實務上最主流**的一條路，Paxos、Raft、PBFT 全走這條。

> 若對同步 / 非同步 / 部分同步的區分不熟，回看 [Ch 2 失敗與網路模型](./02-failure-and-network-models.md)。

### 點子：假設網路「最終」會變好

FLP 假設完全非同步——延遲**永遠**沒有上界。這太悲觀了。真實網路大多數時候是好的，只是偶爾抖一下。Dwork、Lynch、Stockmeyer 1988 年的論文（DLS）把這個「大多數時候好」形式化成**部分同步**：

> 存在一個未知的時刻 **GST（Global Stabilization Time，全域穩定時刻）**，以及一個未知但固定的延遲上界 Δ。在 GST 之前，網路可以任意壞（延遲無上界，跟 FLP 一樣）；但 **GST 之後**，所有訊息都在 Δ 內送達。

```
  時間軸：
  ├────────────── GST 之前 ──────────────┤────── GST 之後 ──────►
  │  網路任意壞（延遲無上界，可能永遠拖）    │  延遲 ≤ Δ（同步了）  │
  │  → 這段期間可能選不出 leader、不終止     │  → 一定終止          │
  │  → 但 safety 全程保住（絕不腦裂）        │                    │
                                          ▲
                                    GST 是「未知」的——
                                    你不知道它何時到，只知道它終會到
```

**GST 是未知的**——這點極其重要。如果 GST 已知，那 GST 之後就是純同步系統，共識當然可解。難的是「你不知道現在到底過了 GST 沒有」。DLS 的巧妙在於：協定的設計讓它**在 GST 之前絕不違反 safety**（絕不腦裂、絕不決定兩個值），只是可能不終止；**一旦過了 GST，它保證終止**。

### 這放寬了 FLP 的哪個假設？

放寬了**非同步**。FLP 的對抗性排程器靠「永遠能再延後一則關鍵訊息」來永遠卡點。但在部分同步下，GST 之後排程器**不能再無限延後**了——所有訊息 Δ 內必達。那個「無限拖延」的武器失效，系統就能被推過臨界點、終止。

### 工程實現：就是 timeout + leader

DLS 的理論怎麼落到工程？答案樸素到你可能失望：**timeout**。

- 節點用一個 timeout 來「猜」leader 是不是死了。GST 之前，網路很慢，timeout 可能誤判（把慢的 leader 當成死的），觸發不必要的重選——這對應「GST 之前不終止」。
- GST 之後，網路穩定，timeout 不再誤判，選出的 leader 能穩定工作，共識終止。
- 為了應付「GST 遲遲不來 / timeout 設太短一直誤判」，實務上用**指數退避（exponential backoff）** 逐步加長 timeout——反正 GST 終會到，timeout 終會夠長。Raft 的 randomized election timeout（Ch 20）就是這套的體現。

**這就是為什麼所有教科書共識協定都有 timeout、都有 leader、都有「選舉逾時」**。它們不是隨便加的——它們是「假設部分同步」這個決定在程式碼裡的化身。timeout 的本質是「我賭網路現在夠好，等這麼久還沒回就當你死了」——這個賭注在 GST 前會輸（誤判），GST 後會贏（正確偵測）。

### 這個賭注真的會輸：一個實戰畫面

「timeout 誤判」不是理論上的可能性，是每個生產系統都吃過的虧。最經典的畫面是 **stop-the-world GC 暫停害死 lease**：

```
   leader L 持有一個「我是 leader，租約到 t=100」的 lease，正常服務中。
   t=50：L 觸發一次 full GC，整個 process 凍結 15 秒（JVM/Go 都可能）。
         L 沒死，只是被 OS 凍住了，發不出心跳。
   t=60：follower 們 timeout（等不到心跳），判定 L 死了，選出新 leader L'。
   t=65：L 的 GC 結束，L 「醒來」，它不知道自己睡了 15 秒，
         以為自己還是 leader（它記得的 lease 到 t=100 還沒過），
         繼續處理寫請求 → 這時 L 和 L' 同時自認 leader！
```

如果協定的 safety 只靠「lease 沒過期就相信自己是 leader」，這裡就腦裂了。真實系統靠 **fencing token**（遞增的世代編號）防這個：L' 當選時世代 +1，後端儲存只接受「世代 ≥ 目前最大」的寫入，L 醒來後帶著舊世代的寫入會被後端拒絕。**這就是 FLP 代價的具體長相**——你用 timeout 繞過了 FLP（換到可終止），但「timeout 可能誤判」這筆帳，在 GC 暫停 / 時鐘跳變 / 網路抖動時就會來討，你得再花力氣（fencing、更保守的 lease）去補。Paxos/Raft 的 safety 骨架（quorum + 已提交不覆蓋）之所以珍貴，正因為它**不依賴 timeout 正確**——timeout 誤判最多害 liveness（多選幾次 leader），永遠不害 safety。

## 路線 B：失敗偵測器（Failure Detector / Chandra-Toueg）

這是**理論上最漂亮**的一條路，它把「繞過 FLP」變成一個可以精確量化的問題。

### 點子：把「偵測死活」抽象成一個獨立模組

FLP 的核心痛點是「你分不出一個節點是死了還是只是慢」。Chandra 和 Toueg（1996）的想法是：**別在共識協定裡糾結這件事，把它抽出來成一個獨立的黑盒子模組——失敗偵測器（failure detector）。** 共識協定去查詢這個黑盒子：「誰死了？」黑盒子回一個「我懷疑死了的節點」清單。

關鍵是這個黑盒子**允許出錯**——它可以誤判（把活的當死的）、可以漏判（沒發現真死的），但要滿足某種**最終正確**的性質。用兩個維度描述一個失敗偵測器：

- **Completeness（完整性）**：死掉的節點最終會被懷疑。
  - Strong：每個死節點最終被**所有**活節點懷疑。
  - Weak：每個死節點最終被**某個**活節點懷疑。
- **Accuracy（準確性）**：活著的節點不被冤枉。
  - Perfect（P）：活節點**從不**被懷疑。
  - Eventually（◇）：**最終**（某時刻後）活節點不再被懷疑——之前可以亂冤枉。

組合出幾個著名的偵測器：

| 偵測器 | Completeness | Accuracy | 白話 |
|---|---|---|---|
| **P**（perfect） | Strong | Perfect | 神級：死的都抓到、活的絕不冤枉 |
| **◇P**（eventually perfect） | Strong | Eventually | 一段混亂後變神級 |
| **S**（strong） | Strong | Weak | 至少一個活節點永不被冤枉 |
| **◇S**（eventually strong） | Strong | Eventually weak | 最終至少一個活節點不再被冤枉 |
| **◇W**（eventually weak） | Weak | Eventually weak | 最弱能解共識的偵測器 |

### 這放寬了 FLP 的哪個假設？

也是**非同步**，但方式不同於部分同步。失敗偵測器把「偵測死活」的能力**當成一個外部給定的抽象**，不管它底層怎麼實現（實務上就是靠 timeout + 部分同步實現）。它的價值是**把問題模組化**：共識協定只要拿到一個夠強的失敗偵測器，就能解共識，而不用管偵測是怎麼做到的。

### 最重要的結果：◇W 是最弱可解共識的偵測器

Chandra-Toueg-Hadzilacos 證明了一個漂亮到不像話的結果：

> **`◇W`（等價於 `◇S`）是能解共識的最弱失敗偵測器。** 任何能解共識的失敗偵測器，都至少和 `◇W` 一樣強。

這把 FLP 從「不可能」翻轉成「可能性的精確條件」：共識不是絕對不可能，而是「**需要且只需要 `◇W` 這麼多的失敗偵測能力**」。`◇W` 的要求極弱——只要求「最終，至少有一個活節點不再被冤枉」。它允許系統前期瘋狂誤判所有人，只要最終安定下來、有一個活節點被大家信任即可。

**注意 `◇W` 和部分同步的關係**：你要怎麼實現一個 `◇W`？靠 timeout + 部分同步。GST 之前 timeout 亂誤判（accuracy 還沒 eventually 到），GST 之後 timeout 準了（活節點不再被冤枉）。所以**失敗偵測器路線和部分同步路線骨子裡是同一件事的兩種說法**——一個從「抽象能力」切入，一個從「網路時序」切入。Chandra-Toueg 的 `◇S`-based 共識協定，長得跟 Paxos 驚人地像（rotating coordinator + quorum），這不是巧合。

## 路線 C：隨機化（Randomization / Ben-Or）

這條路最反直覺，也最漂亮地正面擊穿 FLP 的另一根柱子。

### 點子：擲硬幣，讓排程器沒法預測你

FLP 的對抗性排程器之所以能永遠卡點，是因為協定是**確定性**的——排程器看得到系統狀態，能算出你下一步要幹嘛，於是能精準地把那則關鍵訊息延後。

那如果節點**擲硬幣**呢？當節點陷入僵局（票數分裂、無法決定），它不再確定性地做決定，而是**隨機**選一個值。排程器再聰明也**沒法預測擲硬幣的結果**——它沒法提前算好怎麼卡你。只要給足夠多輪，總有一輪所有節點「碰巧」擲出一致的硬幣，僵局就打破了。

Ben-Or（1983）是第一個這麼做的。它的共識協定（crash 版）大致長這樣，每一輪兩階段：

```
  一輪（round r）：
  ┌─ 階段 1（report）─────────────────────────────┐
  │ 廣播我目前的值 v；收集多數節點的值               │
  │ 若多數都是同一個值 w → 進階段 2 提議 w           │
  │ 否則 → 進階段 2 提議「?」（我沒意見）            │
  └───────────────────────────────────────────────┘
  ┌─ 階段 2（decide/propose）──────────────────────┐
  │ 收集多數的提議：                                 │
  │  · 若「夠多」節點都提議 w → decide w（完成！）    │
  │  · 若「有一些」提議 w → 下一輪就採用 w           │
  │  · 若大家都「?」→ 擲硬幣隨機選 0 或 1，下輪帶著它 │  ← 打破對稱的關鍵
  └───────────────────────────────────────────────┘
```

擲硬幣那一步是靈魂：當系統對稱地卡住（一半想 0 一半想 1，誰也湊不出多數），確定性協定會永遠卡著；隨機協定則靠擲硬幣，讓所有節點**有機率碰巧擲出同一面**，一旦碰巧一致，下一輪就能形成多數而 decide。

### 這放寬了 FLP 的哪個假設？

放寬了**確定性**。這是三條路裡唯一動「確定性」那根柱子的。代價是 termination 從「保證終止」降級為「**機率 1 終止**（with probability 1）」——意思是「永不終止」這個事件的機率是 0，但理論上仍可能發生（無限次都擲出最壞的硬幣序列，機率為 0）。實務上它可能跑很多輪才收斂，尤其 Ben-Or 原版在對抗性排程下期望輪數是**指數級**的（後來的 common coin 技術把它改進到常數期望輪數）。

### 隨機化在哪裡真的被用？

純 Ben-Or 因為輪數問題，很少直接用於一般叢集。但這條路線在**拜占庭 / 區塊鏈**場景大放異彩：

- **共享硬幣（common coin）**：讓所有節點「擲出同一個隨機值」的密碼學技巧（threshold signature），把 Ben-Or 的期望輪數從指數降到常數。現代非同步 BFT（HoneyBadgerBFT）的核心。
- **Nakamoto consensus**（Ch 36）：比特幣的 PoW 本質上也是一種隨機化——靠「誰先算出 hash」這個隨機事件來打破對稱、選出下一個出塊者。它繞過 FLP 的方式正是隨機化 + 經濟誘因。

## 底層機制：三條路怎麼各自讓對抗性排程器失效

把三條路放回 FLP 的證明脈絡看，最能理解它們「憑什麼有效」。FLP 的排程器靠**無限延後關鍵訊息**永遠維持 bivalent。三條路各自堵死這一招：

```
  FLP 排程器的武器：無限延後那則會敲定命運的訊息

  路線 A（部分同步）：GST 後訊息 Δ 內必達
                     → 排程器「無限延後」的能力被沒收 → 被推過臨界點

  路線 B（失敗偵測器）：給協定一個「誰死了」的神諭
                     → 協定不再需要靠「等訊息」來判斷死活
                     → 「延後訊息 = 製造死活模糊」這招失效

  路線 C（隨機化）：節點擲硬幣
                   → 排程器算不出你下一步（沒法預測硬幣）
                   → 沒法精準卡在臨界點 → 機率 1 逃出 bivalent
```

看清楚了嗎？A 和 B 是從「非同步」下手（沒收延後能力 / 抽象掉死活判斷），C 是從「確定性」下手（讓排程器算不出你）。這就是為什麼三條路是「三條」——它們對應 FLP 那三根柱子裡**可以被鬆動的兩根**（非同步、確定性），而部分同步和失敗偵測器其實是「鬆動非同步」的一體兩面。

## 對比與取捨

| 路線 | 放寬假設 | 終止保證 | 代價 / 弱點 | 誰在用 |
|---|---|---|---|---|
| **部分同步（DLS）** | 非同步 | GST 後保證終止 | GST 前可能不終止；timeout 誤判 | **Paxos, Raft, PBFT**（主流） |
| **失敗偵測器（◇S/◇W）** | 非同步（抽象化） | 有 ◇W 即可終止 | 需實現偵測器（仍靠 timeout） | 理論框架；Chandra-Toueg 協定 |
| **隨機化（Ben-Or）** | 確定性 | 機率 1 終止 | 可能跑很多輪（原版指數） | HoneyBadgerBFT, PoW 區塊鏈 |

**主流工程選擇是部分同步**，原因很實際：timeout 好實現、好理解、大多數時候網路真的夠好，GST 前的「不終止」在真實網路裡是短暫的抖動而非永久。失敗偵測器是理解「為什麼 timeout 夠用」的理論外殼，隨機化則在「網路壞到部分同步都不成立（真非同步）」或「有拜占庭對手」的極端場景才不得不出動。

## 踩雷集錦

1. **「用了 timeout 就等於解決了 FLP」**：timeout 沒有「解決」FLP，它**放寬了假設**（引入部分同步）。代價藏在假設被違反時：一次 stop-the-world GC 暫停、一次網路抖動，都會讓 timeout 誤判——把活著的 leader 當死的，觸發不必要的重選，甚至短暫的可用性中斷。你沒消滅 FLP，你只是把它的代價挪到了「假設失效」的時刻。

2. **「GST 是一個你能知道 / 設定的時刻」**：GST 是**未知**的，這是部分同步模型的靈魂。你永遠不知道「現在過了 GST 沒有」。協定的正確性不能依賴知道 GST——它只能依賴「GST 終會到」。把 GST 當成一個可查詢的常數，你就誤解了整個模型。

3. **「隨機化共識比確定性快 / 好」**：不一定。Ben-Or 原版在對抗性排程下期望輪數是**指數級**的，慢到不實用。隨機化的價值不是「快」，是「在確定性不可能的地方（真非同步、對抗性環境）仍能終止」。要它實用，得配 common coin 這類密碼學技巧把輪數壓下來。

4. **「失敗偵測器是一個真實存在的元件」**：`◇S`、`◇W` 是**理論抽象**，不是你 `apt install` 得到的東西。真實系統裡，失敗偵測器就是「timeout + 心跳」的另一種說法。它的價值是理論分析（讓你能精確講「解共識最少需要多強的偵測能力」），不是一個獨立產品。

5. **「這三條路互斥，選一條就好」**：實務上常常混用。Raft 主走部分同步（timeout + leader），但它的 **randomized election timeout** 借了一點隨機化來打破「兩個 candidate 同時逾時、反覆分票」的對稱僵局——這正是 Ben-Or「用隨機打破對稱」的縮小版。工程裡三條路的邊界是模糊的。

## 進階：再往深一層

- **DLS 論文的三個模型**：Dwork-Lynch-Stockmeyer 其實定義了不只一種部分同步——(1) Δ 存在但未知、(2) Δ 已知但只在未知的 GST 後生效、(3) 各種組合。不同組合下容錯上界不同（例如某些變體下 crash 容錯需要 `2f+1`、拜占庭需要 `3f+1`）。去讀它的 Table，會理解「同步程度」和「容錯能力」之間的精確兌換率。

- **failure detector 的化簡（reduction）**：Chandra-Toueg 證明 `◇W` 和 `◇S` **等價**——你能用一個實現另一個。這種「偵測器之間的化簡」構成一個完整的格（lattice），是分散式理論裡很優雅的一塊。`◇P → ◇S → ◇W` 的強弱鏈，對應著「你願意花多少偵測能力換終止」。

- **common coin 與非同步 BFT**：Ben-Or 的指數輪數問題，靠「所有節點擲出同一個隨機值」的 common coin 解決。實現 common coin 需要 threshold signature（門檻簽章）——一種密碼學原語。這條線通向 HoneyBadgerBFT、Dumbo 等現代非同步 BFT 協定，它們在**真非同步**（連部分同步都不假設）下仍能共識。若你之後走區塊鏈 / BFT 方向（Ch 33–36），這是關鍵伏筆。

- **「eventual synchrony 是不是作弊」**：有人質疑部分同步是不是偷偷把同步假設塞回來了。嚴格說沒有——它在 GST 前是**完全非同步**（FLP 全程適用，可能不終止），只是承諾 GST 終會到。這個「終會到但不知何時」的縫隙，恰好足夠繞過 FLP 而不至於退化成純同步。這個模型的精妙之處值得細品。

## 本章重點整理

- FLP 是**條件式**不可能：鬆動「非同步 / 確定性」任一根柱子（crash 那根動不了），天花板就破。
- **三條路**：部分同步（DLS，鬆非同步）、失敗偵測器（Chandra-Toueg，把死活偵測抽象化，仍是鬆非同步）、隨機化（Ben-Or，鬆確定性）。
- **部分同步是主流**：假設存在未知的 GST，之後延遲有上界。工程化身就是 **timeout + leader + 指數退避**——這就是所有教科書共識協定都有 timeout 的原因。GST 前保 safety、可能不終止，GST 後保證終止。
- **失敗偵測器**把繞過 FLP 變成精確問題：`◇W` 是**最弱能解共識的偵測器**。它和部分同步是一體兩面（`◇W` 靠 timeout + 部分同步實現）。
- **隨機化**靠擲硬幣讓排程器沒法預測你，代價是終止降級為**機率 1**、可能跑很多輪。在真非同步 / 拜占庭場景才不得不用。
- 天下沒有免費午餐：每條路的代價都在「假設被違反」時（GC 暫停、網路抖動）找上門。繞過 FLP 不是消滅它，是把它的帳單挪個地方。
