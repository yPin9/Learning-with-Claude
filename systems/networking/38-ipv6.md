# Ch 38 — IPv6

> 目標：知道 IPv6 跟 IPv4 差別、為什麼還沒普及、怎麼跟 IPv4 共存。

## IPv6 基本

128 bit 位址（vs IPv4 32 bit）：

- IPv4：~43 億位址
- IPv6：3.4 × 10^38 位址（**地球每平方公分都能分到 6.5 × 10^23 個**）

寫法：8 組 16-bit hex，用 `:` 分：

```
 2001:0db8:0000:0000:0000:ff00:0042:8329
```

簡寫規則：

- 連續 0 用 `::`（**只能用一次**）
- 一組內前置 0 可省

```
 2001:0db8:0000:0000:0000:ff00:0042:8329
 2001:db8::ff00:42:8329                   ← 簡寫
```

```
 ::1                       ← localhost (= 127.0.0.1)
 ::                        ← 全 0 (= 0.0.0.0)
 fe80::1                   ← link-local
```

## 跟 IPv4 主要差別

| 項目 | IPv4 | IPv6 |
|---|---|---|
| 位址長度 | 32 bit | 128 bit |
| Header 大小 | 20+ byte | 40 byte（固定） |
| Fragmentation | router 做 | only sender 做 |
| Broadcast | 有 | 沒（用 multicast） |
| ARP | 有 | 沒（用 NDP） |
| 加密 | 可選（IPSec） | 內建（理論上） |
| NAT | 普遍 | **理論上不需** |
| DHCP | 必要 | SLAAC（autoconfig）|
| Subnet | CIDR /N | 同 |

## IPv6 位址類型

```
 2001:db8::/32      文件用範例
 fc00::/7           Unique Local（類比 RFC 1918，私有）
 fe80::/10          Link-Local（同網段，自動產生）
 ::1                Loopback
 ff00::/8           Multicast
```

每個 IPv6 設備自動有：

- **link-local**（fe80::...，自動產生 by MAC）
- **global unicast**（一般可路由位址，從 router 拿）

```bash
ip a
# 2: eth0:
#     inet 192.168.1.10/24 ...
#     inet6 fe80::abcd:1234:5678:9012/64 scope link
#     inet6 2001:db8::abcd:1234/64 scope global
```

## SLAAC（StateLess Address Auto-Configuration）

IPv6 設備不需要 DHCP server，**自己根據 router prefix + MAC 產生 IP**：

1. 設備啟動 → 自動 fe80::（link-local）
2. 廣播 router solicitation
3. router 回 router advertisement（含 prefix）
4. 設備自己組 global IP（prefix + interface ID）

「**自動 IPv6**」是 v6 設計亮點。

## NDP（Neighbor Discovery Protocol）

取代 IPv4 的 ARP：

- 找 IPv6 → MAC
- router discovery
- duplicate address detection

```bash
ip -6 neigh    # IPv6 neighbor table（類比 ARP table）
```

## IPv6 路由

跟 IPv4 概念同：

```bash
ip -6 route
# default via fe80::1 dev eth0
# 2001:db8::/64 dev eth0 proto kernel metric 256
```

## IPv4 / IPv6 共存

雙 stack（**dual stack**）：設備同時跑 IPv4 + IPv6。

DNS 同時回 A + AAAA：

```bash
dig example.com
# 93.184.216.34 (A)
dig example.com AAAA
# 2606:2800:220:1:248:1893:25c8:1946 (AAAA)
```

App 通常**先試 IPv6 → 失敗再 IPv4**（happy eyeballs algorithm）。

## 為什麼 IPv6 普及這麼慢

1. **NAT 太成功** — IPv4 不夠的痛被 NAT 緩解
2. **設備老** — 老 router / OS / 應用不支援
3. **ISP 沒動力** — 部署 v6 投資大
4. **教學少** — 多數工程師只學 IPv4
5. **複雜性** — v6 概念多（NDP / SLAAC / 多種 address type）
6. **firewall 等工具** — v4 規則寫了一堆，遷移累

但 2025 年情況：

- Google 統計：~40% 用戶用 IPv6 訪問 Google
- 行動網路（4G/5G）很多 v6 only + NAT64
- 雲端 service 普遍支援 v6

「**IPv6 慢慢普及，但不會革命性切換**」。

## IPv6 對 NAT

理論上不需要 NAT — 每設備都有公網 IPv6。

但實務上：

- ISP 給 user `/64` prefix（足夠 18 quintillion 設備）
- 還是有 firewall（不是 NAT 但功能類似）
- 內網仍用 ULA（fc00::/7）+ NPT 翻譯

「**沒 NAT 但有 firewall**」是 v6 LAN 設計。

## 一個常見誤解：「IPv6 肯定取代 IPv4」

**部分對**。長期是。但「取代」可能要 50 年。**IPv4 + IPv6 雙存幾十年**。

新部署都該支援 v6，但 v4 不會消失。

## 一個常見誤解：「IPv6 沒安全問題」

**錯**。v6 引入新攻擊面：

- Router advertisement spoofing
- NDP spoofing（類 ARP spoofing）
- IPv6 地址 enumeration（128 bit 太多但 SLAAC 部分可預測）

新 protocol 新 bug。

## 一個常見誤解：「我家 IP 是 IPv4 就無所謂 IPv6」

**部分對**。但很多用戶 ISP 已經給 v6（dual stack）但你不知道。check：

```bash
curl -6 ifconfig.me
# 應該回你的 IPv6（如果有）
```

如果有 → 你已經在用 v6 訪問支援 v6 的 site。

## 一個常見誤解：「服務只支援 v4 就夠」

**部分對**，但越來越糟。Google 報告 user 用 v6-only 移動網路訪問你 site → v4-only site **完全連不到**（要 NAT64 翻譯，慢且不可靠）。

「**新 site 該雙 stack**」是 best practice。

## 動手練習

**1. 看自己的 IPv6**

```bash
ip a | grep inet6
curl -6 ifconfig.me 2>/dev/null && echo "I have v6" || echo "no v6"
```

**2. ping IPv6**

```bash
ping6 google.com
# 或
ping -6 google.com
```

**3. 看 SLAAC**

```bash
ip -6 route
ip -6 neigh
```

**4. 用 nginx 同時 listen v4 + v6**

```nginx
server {
    listen 80;
    listen [::]:80;
    
    listen 443 ssl;
    listen [::]:443 ssl;
    
    ...
}
```

`[::]:80` 是 IPv6 listen all。

**5. test-ipv6.com**

去 http://test-ipv6.com，自動測你的 v6 配置。
