# Ch 38 — IPv6

> **目標**：理解 IPv6——它怎麼解決 IPv4 位址耗盡（Ch 5）、位址結構和記法、它怎麼讓 NAT（Ch 8）變得不必要（端到端復活）、SLAAC 自動配置、NDP（取代 ARP，Ch 3）、為什麼普及這麼緩慢、以及雙協定（dual-stack）的現實。Ch 5 提過 IPv6 是位址耗盡的長期解法，這章把它講清楚，補完定址的全貌。

> **環境**：Linux（ip -6）。概念為主，串 Ch 5/8/3。

## 為什麼要懂 IPv6？

Ch 5 說 IPv4 只有 43 億個位址、早就用完，靠私有 IP + NAT（Ch 8）撐著。IPv6 是根本解法——它的位址多到「每粒沙子都能有一個 IP」。雖然普及緩慢，但 IPv6 流量持續增長（很多地區已過半），你遲早會遇到——VPS 可能給你 IPv6、行動網路大量用 IPv6、雲端服務支援 IPv6。

理解 IPv6 補完了定址的全貌（Ch 5 的另一半），也讓你看到「沒有 NAT 的網際網路」會是什麼樣（端到端復活，但要重新思考安全）。這章講 IPv6 的核心——位址、自動配置、和 IPv4 的關鍵差異、以及為什麼一個「更好」的協定普及這麼慢（技術遷移的經典案例）。

## 先建立直覺:多到用不完

```
IPv4 vs IPv6 的位址空間（數量級的差異）：

  IPv4：32 位元 = 2³² ≈ 43 億個位址
    早就用完，靠 NAT 撐（Ch 8）
        │
  IPv6：128 位元 = 2¹²⁸ ≈ 340 澗個
    （3.4 × 10³⁸，340 後面 36 個零）
    多到「地球每平方公尺能分到 數萬兆 個」
        │
  → 位址多到「永遠用不完」
    每個裝置、每個容器、甚至每個 app 都能有公網 IP
    → 不需要 NAT（Ch 8）→ 端到端復活（網際網路的初衷）
        │
  IPv6 記法（128 位元寫成 8 組十六進位）：
    2001:0db8:0000:0000:0000:ff00:0042:8329
    簡寫：2001:db8::ff00:42:8329
    （:: 代表「一串 0」，每組前導 0 可省）
```

關鍵心智：IPv6 是 **128 位元**（vs IPv4 的 32 位元）——位址多到 2¹²⁸（3.4×10³⁸），永遠用不完。每個裝置、容器、甚至 app 都能有公網 IP，**不需要 NAT**（Ch 8），端到端直連復活（網際網路的初衷）。記法是 8 組十六進位，`::` 簡寫一串 0、前導 0 可省。

> IPv6 是 Ch 5（IPv4 定址）的後繼、Ch 8（NAT）的終結者。它讓「位址不夠 → NAT」的整個權宜之計變得不必要。如果對 IPv4 定址、NAT 不熟，回看 [Ch 5](./05-ip-addressing-cidr.md) 和 [Ch 8](./08-nat-explained.md)。

## IPv6 位址結構

```bash
# 看你的 IPv6 位址（如果有）
ip -6 addr
# inet6 2001:db8::1234/64 scope global       ← 公網 IPv6
# inet6 fe80::1234/64 scope link             ← link-local（本地，必有）

# IPv6 位址類型：
# 全域單播（2000::/3）：公網位址（像 IPv4 公網）
# link-local（fe80::/10）：只在本地鏈路（每個介面自動有，類似 169.254）
# 唯一本地（fc00::/7）：私有（像 IPv4 的 192.168，但較少用）
# loopback（::1）：本機（像 127.0.0.1）
# 多播（ff00::/8）：取代 IPv4 的廣播（IPv6 沒有廣播！用多播）

# IPv6 的子網（通常 /64）
# 一個 /64 子網有 2^64 個位址（比整個 IPv4 還多！）
# ISP 給家庭通常一個 /56 或 /48（多個 /64 子網）
```

```
IPv6 位址記法規則：
  完整：2001:0db8:0000:0000:0000:ff00:0042:8329
  規則 1：每組前導 0 省略 → 2001:db8:0:0:0:ff00:42:8329
  規則 2：連續的全 0 組用 :: （只能用一次）→ 2001:db8::ff00:42:8329
        │
  特殊位址：
    ::1          loopback（= 127.0.0.1）
    ::           未指定（= 0.0.0.0）
    fe80::/10    link-local（本地鏈路）
        │
  URL 裡的 IPv6 要用中括號：
    http://[2001:db8::1]:8080/   （中括號區分 IP 和 port）
```

> **IPv6 用 `::` 簡寫一串 0，且 URL 裡要用中括號——這些記法細節是實務必知**。IPv6 位址長（128 位元），所以有簡寫規則：**前導 0 省略**（`0db8`→`db8`）、**連續全 0 組用 `::`**（但**只能用一次**，否則有歧義）。所以 `2001:0db8:0000:0000:0000:ff00:0042:8329` 簡寫成 `2001:db8::ff00:42:8329`。記住特殊位址：`::1`（loopback，= 127.0.0.1）、`::`（未指定，= 0.0.0.0）、`fe80::/10`（link-local，每個介面自動有，類似 IPv4 的 169.254）。**在 URL 裡 IPv6 要用中括號**——`http://[2001:db8::1]:8080/`（中括號區分位址和 port，否則 `:8080` 會和位址的 `:` 混淆）。子網通常是 **/64**（一個 /64 有 2^64 個位址，比整個 IPv4 還多！）——這是 IPv6 「位址不值錢」的體現（IPv4 要省著用、IPv6 隨便給）。注意 **IPv6 沒有廣播**（Ch 3 的廣播），改用**多播**（multicast，更有效率，只送給感興趣的）。這些記法和概念差異是用 IPv6 的基礎——看到 `2001:db8::1` 你要認得它是 IPv6，會在 URL/設定裡正確使用。

## SLAAC 與 NDP:自動配置

```
IPv6 的自動配置（比 IPv4 的 DHCP 更優雅）：

  SLAAC（無狀態位址自動配置）：
    IPv6 裝置能「自己」配置位址（不一定要 DHCP）
    1. 介面自動生成 link-local（fe80::）
    2. 聽路由器的 RA（Router Advertisement）廣播
       RA 告訴：網路前綴（如 2001:db8::/64）+ 閘道
    3. 裝置用「前綴 + 自己生成的後綴」組出完整位址
    → 不用 DHCP 伺服器就能上網（無狀態）
        │
  NDP（鄰居發現協定，取代 ARP，Ch 3）：
    IPv6 沒有 ARP，用 NDP（基於 ICMPv6）
    做 ARP 的事（IP→MAC）+ 路由器發現 + 自動配置
    → 比 ARP 更安全、功能更多
        │
  → IPv6 裝置能自己配置（SLAAC）、自己發現鄰居和路由器（NDP）
    比 IPv4 的「ARP + DHCP」更整合
```

```bash
# 看 IPv6 的鄰居（NDP，取代 ARP 的 ip neigh）
ip -6 neigh                        # IPv6 鄰居表（NDP）

# 看 SLAAC 自動配的位址
ip -6 addr | grep "scope global"

# IPv6 的 ICMP（ICMPv6）—— 比 IPv4 的 ICMP 更重要
# NDP、SLAAC、PMTUD 都靠 ICMPv6 → 「絕不能全擋 ICMPv6」（Ch 19 提過）
ping6 2001:4860:4860::8888         # Google 的 IPv6 DNS
```

> **IPv6 用 SLAAC（自己配位址）和 NDP（取代 ARP）做自動配置——而 ICMPv6 是 IPv6 的命脈，絕不能全擋**。**SLAAC**（無狀態位址自動配置）是 IPv6 的優雅之處——裝置能**自己**配置公網位址：介面先自動生成 link-local（fe80::），聽路由器的 **RA（Router Advertisement）** 廣播得知網路前綴和閘道，然後用「前綴 + 自己生成的後綴」組出完整位址——**不用 DHCP 伺服器**就能上網（無狀態，比 IPv4 的 DHCP 簡單）。**NDP**（鄰居發現協定）取代了 IPv4 的 **ARP**（Ch 3）——它基於 **ICMPv6**，做 ARP 的事（IP→MAC）+ 路由器發現 + 自動配置。關鍵警告：**ICMPv6 是 IPv6 的命脈，絕不能全擋**（Ch 19 提過）——IPv4 可以擋 ICMP（只影響 ping/traceroute），但 IPv6 的 NDP、SLAAC、PMTUD（Ch 4）全靠 ICMPv6，**全擋會讓 IPv6 完全壞掉**（連鄰居都發現不了）。這是設 IPv6 防火牆的重大差異（Ch 19 的 nftables inet family 要記得允許必要的 ICMPv6）。理解 SLAAC/NDP，你就懂了 IPv6 的自動配置怎麼運作，以及為什麼 IPv6 防火牆要小心對待 ICMPv6。這也是 IPv6 比 IPv4 「更整合」的設計（把定址、鄰居發現、自動配置整合進 ICMPv6/NDP）。

## 為什麼 IPv6 普及這麼慢

```
IPv6 明明更好，為什麼普及這麼慢（技術遷移的經典案例）：

  1. 不向後相容：
     IPv6 和 IPv4 不能直接互通（不同協定）
     → 要嘛全換、要嘛雙協定（dual-stack）並存
        │
  2. NAT 「夠用」了：
     IPv4 + NAT 雖然醜，但能用
     → 沒有「立刻換」的急迫性（雞生蛋問題）
        │
  3. 遷移成本：
     設備、軟體、人員都要支援/學習 IPv6
        │
  4. 雞生蛋：
     內容商：「沒人用 IPv6，幹嘛支援」
     用戶：「沒內容支援 IPv6，幹嘛開」
        │
  現實解法：dual-stack（雙協定並存）
    裝置同時有 IPv4 和 IPv6，能用哪個用哪個
    → 漸進遷移（不是一夜全換）
        │
  → IPv6 普及慢是「夠用的舊方案 + 遷移成本 + 雞生蛋」
    這是技術遷移的經典難題（更好 ≠ 立刻取代）
```

> **IPv6 普及慢是「NAT 夠用了 + 遷移成本 + 雞生蛋」的經典技術遷移難題——「更好」不等於「立刻取代」**。IPv6 明明解決了 IPv4 的根本問題（位址耗盡），為什麼 1998 年就標準化卻普及這麼慢？關鍵原因：(1) **不向後相容**——IPv6 和 IPv4 是不同協定，不能直接互通，要嘛全換要嘛並存；(2) **NAT「夠用」了**——IPv4 + NAT（Ch 8）雖然醜（破壞端到端、P2P 困難），但**能用**，所以沒有「立刻換」的急迫性；(3) **遷移成本**——所有設備、軟體、人員都要支援/學習；(4) **雞生蛋問題**——內容商說「沒人用 IPv6，幹嘛支援」，用戶說「沒內容支援，幹嘛開」，互相等待。現實的解法是 **dual-stack（雙協定並存）**——裝置同時有 IPv4 和 IPv6，能用哪個用哪個，**漸進遷移**（不是一夜全換）。這是技術遷移的**經典案例**——一個「明顯更好」的技術，因為「舊方案夠用 + 遷移成本 + 網路效應（雞生蛋）」而緩慢普及。這個道理超越 IPv6——很多更好的技術（新協定、新標準）都面臨同樣的困境（為什麼還在用 QWERTY 鍵盤、為什麼 metric 系統在美國推不動）。理解這個，你對「技術採用」有更現實的認識——技術優劣只是一個因素，遷移成本和網路效應往往決定成敗。不過 IPv6 流量持續增長（很多行動網路、地區已過半），dual-stack 是當前現實，你會越來越常遇到 IPv6。

## 故意弄壞:IPv6 的常見問題

```bash
# IPv6 相關的常見問題（dual-stack 時代的坑）

# 1. 程式偏好 IPv6 但 IPv6 不通 → 連線慢/失敗
# dual-stack 主機可能先試 IPv6（失敗）再試 IPv4 → 延遲
# Happy Eyeballs（RFC 8305）：同時試 v4/v6，用先成功的
curl -6 https://example.com        # 強制 IPv6
curl -4 https://example.com        # 強制 IPv4
# 如果 -6 失敗但 -4 成功 → IPv6 配置有問題

# 2. IPv6 防火牆忘了設（只設了 IPv4）
# iptables（v4）和 ip6tables（v6）分開 → 容易漏 v6（Ch 19 的 inet family 解決）
sudo ip6tables -L                  # IPv6 防火牆（別忘了設！）
# → 服務在 IPv6 上裸奔是常見的安全漏洞

# 3. 全擋 ICMPv6 → IPv6 壞掉（上面講的）
# NDP/SLAAC 需要 ICMPv6，全擋連鄰居都發現不了

# 4. 應用不支援 IPv6
# 老應用可能只綁 IPv4（0.0.0.0 不含 IPv6，要 :: 才是所有 v4+v6）
ss -tlnp | grep ':::'              # 監聽 :: = 同時 v4+v6
```

> **dual-stack 時代的坑：IPv6 防火牆忘了設、應用只綁 IPv4、IPv6 配置壞造成連線慢——這些是 IPv6 普及過程的實務問題**。在 IPv4/IPv6 並存（dual-stack）的現實裡，常見問題：(1) **連線慢**——dual-stack 主機可能先試 IPv6（如果配置壞了會失敗）再回退 IPv4，造成延遲。**Happy Eyeballs**（RFC 8305）解決——同時試 v4 和 v6，用先成功的。`curl -6`/`-4` 能強制測試哪個協定有問題；(2) **IPv6 防火牆忘了設**——iptables（v4）和 ip6tables（v6）**分開**，容易只設了 v4 漏了 v6，導致**服務在 IPv6 上裸奔**（這是真實的安全漏洞——你以為防火牆擋了，但只擋了 IPv4，IPv6 完全開放！Ch 19 的 nftables `inet` family 一套管 v4+v6 就是為了解決這個）；(3) **全擋 ICMPv6 讓 IPv6 壞掉**（上面講的）；(4) **應用只綁 IPv4**——老應用綁 `0.0.0.0`（只 IPv4），要綁 `::`（IPv6 的 0.0.0.0，且通常含 v4）才同時服務 v4 和 v6（`ss -tlnp | grep :::` 看有沒有 IPv6 監聽）。這些是 IPv6 部署的實務陷阱——特別是「IPv6 防火牆漏設」這個安全坑，是 dual-stack 時代要警惕的。理解 IPv6 的這些差異，你在遇到它時（VPS 給你 IPv6、雲端服務、行動網路）不會手足無措，也不會留下 IPv6 的安全漏洞。

## 動手練習

1. 看你的 IPv6：`ip -6 addr` 看有沒有 IPv6（link-local 一定有，global 看 ISP），理解位址類型

2. 練記法：把幾個完整 IPv6 位址簡寫（前導 0、::），理解簡寫規則

3. 測 IPv6：`ping6` 和 `curl -6` 測 IPv6 連通（如果有 IPv6），對比 `curl -4`

4. 看 NDP：`ip -6 neigh` 看 IPv6 鄰居表（取代 ARP）

5. 跑「故意弄壞」：檢查你的 IPv6 防火牆（ip6tables -L）有沒有設，理解「只設 v4」的漏洞

## 本章重點整理

- IPv6 是 128 位元（vs IPv4 的 32），位址永遠用不完——每個裝置都能有公網 IP，不需要 NAT（端到端復活）
- 記法：8 組十六進位、`::` 簡寫一串 0（只一次）、前導 0 省略；URL 用中括號 `[2001:db8::1]:port`
- SLAAC（裝置自己配位址）+ NDP（取代 ARP，基於 ICMPv6）；ICMPv6 是命脈，絕不能全擋
- IPv6 沒有廣播（用多播）；子網通常 /64（一個就比整個 IPv4 大）
- 普及慢 = NAT 夠用 + 遷移成本 + 雞生蛋（技術遷移經典）；現實是 dual-stack；坑：IPv6 防火牆漏設（安全漏洞）
