# Ch 31 — GFW 演進史與對抗

> **目標**：把網路審查 vs 反審查的二十年攻防串成完整的歷史脈絡——GFW（防火長城）的技術手段演進（DNS 污染→IP 封鎖→DPI→主動探測→機器學習）、反審查工具的對應演進、以及這場攻防展現的網路技術深度。這是本課最獨特的一章，它不教你「怎麼翻牆」，而是用這場真實的攻防當案例，把前面所學（DNS/TCP/TLS/流量分析）整合成對「網路審查技術」的深刻理解。**本章是技術史與原理的教育**，使用任何工具須遵守當地法律。

> **環境**：歷史與技術原理章。延續 Ch 29-30 的教育框架。

## 為什麼用 GFW 當教材？

GFW（Great Firewall，防火長城）是世界上最龐大、最先進的網路審查系統。它和反審查工具的攻防，是過去二十年網路技術最激烈的實戰演練——它逼迫雙方把 DNS、TCP、TLS、流量分析的技術推到極致。

**用它當教材不是教你翻牆，而是因為它是最好的「網路技術綜合案例」**——理解 GFW 怎麼識別和封鎖流量，你就把前面學的 DNS（Ch 9）、TCP（Ch 6）、TLS（Ch 11）、流量分析（Ch 29-30）全部串起來，看到它們在真實攻防中怎麼運作。這也是學術界（USENIX/IEEE 的審查研究）、人權組織、安全研究者嚴肅研究的領域。理解審查技術，對設計隱私系統、理解流量分析的極限、認識網路的政治面向，都有價值。本章是技術史，幫你整合全課知識。

## 攻防的整體脈絡

```
GFW vs 反審查的二十年攻防（技術演進）：

  時期      審查手段                反審查對應
  ────────────────────────────────────────────
  早期      DNS 污染（Ch 9）         改 hosts / 換 DNS
  ~2010     IP 封鎖                  換 IP / proxy
  ~2010     關鍵字 + RST 注入        加密（VPN/SSH）
  ~2012     DPI 識別協定特徵         Shadowsocks（無特徵，Ch 29）
  ~2015     主動探測                 AEAD 加密（Ch 29）
  ~2018     更強的流量分析           V2Ray 偽裝 HTTPS（Ch 30）
  ~2020     TLS 指紋分析             uTLS / 模仿瀏覽器指紋
  ~2023     SNI 過濾、深度分析       REALITY 借真網站門面（Ch 30）
  持續      機器學習流量分類         行為混淆、持續演進
  ────────────────────────────────────────────
        │
  → 每一步：審查者出新招 → 反審查者對應 → 審查者再出招
    這是持續的軍備競賽（沒有終局）
    每一招都用到本課的某個技術（DNS/TCP/TLS/流量分析）
```

> **GFW 攻防的每一步都對應本課的一個技術——這就是為什麼它是最好的綜合教材**。看這個時間線，你會發現它把全課串起來了：**DNS 污染**（Ch 9，回假 IP）↔ 換 DNS/DoH；**IP 封鎖** ↔ proxy 換出口；**關鍵字+RST 注入**（Ch 6，偵測到敏感詞就注入 RST 斷連線）↔ 加密（看不到內容）；**DPI 識別協定特徵**（Ch 14 的封包分析的攻擊性應用）↔ Shadowsocks 無特徵（Ch 29）；**主動探測** ↔ AEAD（Ch 29）；**流量分析** ↔ V2Ray 偽裝 HTTPS（Ch 30）；**TLS 指紋分析**（Ch 11 的 ClientHello 指紋）↔ 模仿瀏覽器指紋；**SNI 過濾**（Ch 11/9 的 SNI 明文洩漏）↔ REALITY（Ch 30）。每一招攻防都是某個協定知識的實戰應用。這場「持續的軍備競賽」沒有終局——審查者出新招、反審查者對應、審查者再出招。理解這個脈絡，你不只懂了「審查 vs 反審查」，更重要的是**看到了所有網路協定知識怎麼在真實攻防中綜合運作**。這是本課最獨特的價值——用一場真實的、高強度的攻防，把零散的協定知識整合成「網路怎麼被分析、識別、控制、對抗」的完整理解。

## 審查手段一:DNS 污染

```
DNS 污染（最早、最基礎的審查手段，Ch 9）：

  你查「被封網站」的 DNS：
    正常：DNS → 真 IP
    污染：GFW 在路徑上「搶答」一個假 IP（或 NXDOMAIN）
        │
  怎麼做到（Ch 9 的 DNS 是明文 UDP）：
    DNS 查詢是明文 UDP（Ch 7/9）
    GFW 在路徑上看到查詢 → 搶在真 DNS 之前回假答案
    （因為 UDP 無連線，誰先回誰算數）
        │
  對抗（Ch 9 的 DoH/DoT）：
    加密 DNS（DoH/DoT）→ GFW 看不到你查什麼 → 無法污染
    或用可信的境外 DNS（但連線本身可能被封）
        │
  → DNS 污染利用「DNS 明文 + UDP 搶答」
    對抗用「加密 DNS」（讓污染者看不到/改不了）
    這正是 Ch 9 的 DoH/DoT 的實戰意義
```

> **DNS 污染利用「DNS 是明文 UDP，誰先回誰算數」——這正是 Ch 9 講 DoH/DoT 的實戰背景**。DNS 污染是最早的審查手段：你查被封網站的 DNS，GFW 在網路路徑上看到這個**明文 UDP 查詢**（Ch 7/9），搶在真 DNS 伺服器之前回一個**假 IP**（或 NXDOMAIN）——因為 UDP 無連線（Ch 7），「誰先回誰算數」，GFW 的假答案先到，你就拿到假 IP（連到錯的地方或連不上）。這是 Ch 9 的 DNS 明文問題的直接後果。**對抗就是加密 DNS（DoH/DoT，Ch 9）**——查詢加密後，污染者看不到你查什麼、也無法搶答（它不知道你在查什麼，且加密的回應它偽造不了）。這就是 Ch 9 講「DoH 難封鎖、是對抗 DNS 污染的手段」的實戰意義——現在你看到它的完整背景了。DNS 污染的存在也解釋了為什麼翻牆「要先解決 DNS」（Ch 9）——如果 DNS 被污染，你連域名都解析錯，後面的代理都白搭。理解這個，你把 Ch 9（DNS）、Ch 7（UDP）的知識和真實審查連起來了。

## 審查手段二:DPI 與 RST 注入

```
DPI（深度封包檢測）+ RST 注入（Ch 6/14）：

  DPI（Deep Packet Inspection）：
    不只看封包的「位址」，還看「內容」（Ch 14 的封包分析）
    識別：協定特徵、關鍵字、流量模式
        │
  RST 注入（利用 TCP，Ch 6）：
    GFW 偵測到「敏感內容」的連線
    → 偽造 RST 封包（Ch 6）送給「雙方」
    → 雙方都以為對方重置了連線 → 連線斷掉
        │
  巧妙處：GFW 不用「擋」封包，只要「注入 RST」
    （在旁路監測即可，不用在線上攔截 → 規模化容易）
        │
  對抗：
    加密（DPI 看不到內容，但看得到「這是加密流量」）
    → 所以還要「無特徵/偽裝」（Ch 29-30）
        │
  → RST 注入是 Ch 6（TCP RST）的攻擊性應用
    對抗從「加密內容」進化到「隱藏這是代理」（Ch 29-30）
```

> **RST 注入是 Ch 6 的 TCP RST 的攻擊性應用——GFW 偽造 RST 讓雙方以為對方斷線，不用攔截就能切斷連線**。**DPI（深度封包檢測）** 是 Ch 14 封包分析的攻擊性應用——它不只看封包的位址（誰連誰），還看**內容**（識別協定特徵、敏感關鍵字、流量模式）。當 DPI 偵測到「敏感內容」的連線，GFW 用 **RST 注入**（Ch 6 的 TCP RST）切斷它——它**偽造 RST 封包**送給連線雙方，雙方都收到「對方重置了連線」（Ch 6 的 RST 語意），於是連線斷掉。巧妙處：GFW **不用在線上攔截封包**（那需要在線設備，規模化難），只要在旁路監測流量、發現敏感就**注入 RST**（旁路注入，規模化容易）——這是 GFW 能覆蓋全國流量的關鍵架構。對抗 DPI 的第一步是**加密**（DPI 看不到內容）——但加密只解決「看內容」，DPI 還能看出「這是加密的、未知的流量」（特徵），所以對抗進化到**無特徵（Shadowsocks）和偽裝（V2Ray）**（Ch 29-30）。理解 RST 注入，你看到 Ch 6 的 RST、Ch 14 的封包分析怎麼成為審查的工具，以及為什麼「光加密不夠、還要隱藏這是代理」。這把 TCP（Ch 6）、封包分析（Ch 14）、加密（Ch 11）、反審查（Ch 29-30）全串起來了。

## 審查手段三:主動探測與機器學習

```
進階審查手段（近年的攻防前沿）：

  主動探測（active probing，Ch 29）：
    GFW 懷疑某 IP 是代理 server
    → 主動連它，模仿代理協定的握手
    → 看 server 反應，確認是不是代理 → 封鎖
    對抗：AEAD（篡改即失敗、無反應，Ch 29）、回落到真網站（Ch 30）
        │
  TLS 指紋分析（Ch 11）：
    分析 ClientHello 的指紋（支援的加密套件順序等）
    工具的 TLS 庫指紋 ≠ 真瀏覽器 → 露餡
    對抗：uTLS（模仿真瀏覽器的 TLS 指紋）
        │
  SNI 過濾（Ch 11/9）：
    TLS 的 SNI 是「明文」的（Ch 11）→ 看你連哪個域名 → 封
    對抗：ECH（加密 SNI）、REALITY（借真域名，Ch 30）
        │
  機器學習流量分類：
    用 ML 從「流量行為」（大小/時序/方向）分類
    對抗：行為混淆、流量填充（持續演進）
        │
  → 攻防前沿：從「特徵」到「行為」，從「規則」到「ML」
```

> **進階審查從「看特徵」進化到「看行為」、從「規則」到「機器學習」——這是攻防的前沿，也用到本課最深的知識**。近年的審查手段：(1) **主動探測**（Ch 29）——GFW 主動連懷疑的 server、模仿代理握手、看反應確認，AEAD 和回落（Ch 29-30）對抗；(2) **TLS 指紋分析**（Ch 11）——分析 ClientHello 的指紋（加密套件的順序等細節），如果工具的 TLS 庫指紋和真瀏覽器不同就露餡，對抗用 **uTLS**（模仿真瀏覽器的 TLS 指紋）；(3) **SNI 過濾**（Ch 11/9）——TLS 的 **SNI 是明文的**（Ch 11，你連哪個域名會洩漏），GFW 看 SNI 就知道你連被封域名並封鎖，對抗用 **ECH**（加密 SNI）或 REALITY（Ch 30）；(4) **機器學習流量分類**——用 ML 從「流量行為」（封包大小分布、時序、方向對稱性）分類，不依賴特徵，對抗用行為混淆和流量填充。趨勢是**從「看特徵」到「看行為」、從「固定規則」到「機器學習」**。這些前沿攻防用到本課最深的知識——TLS 指紋（Ch 11 的 ClientHello 細節）、SNI 明文（Ch 11/9）、統計流量分析。理解它們，你對「流量在多大程度上能被分析識別」有了最前沿的認識。這也提醒：**SNI 明文是真實的隱私漏洞**（Ch 11 提過——即使 HTTPS 加密內容，SNI 還是洩漏你連哪個域名），ECH 是正在推進的修補。這場攻防把本課所有協定知識推到了極致應用。

## 這場攻防教會我們什麼

```
GFW 攻防的技術啟示（超越翻牆本身）：

  1. 沒有絕對的隱私/匿名：
     流量分析的能力很強（特徵/行為/ML）
     「隱藏」是成本博弈，不是絕對（Ch 30 的攻防經濟學）
        │
  2. 加密 ≠ 隱藏：
     加密保護「內容」，但「元資料」（誰連誰、何時、多少）
     仍然洩漏。SNI、流量模式、時序都是元資料
        │
  3. 明文的代價：
     DNS 明文、SNI 明文 → 都成了審查的切入點
     → 「預設加密一切」（DoH、ECH）的推動力
        │
  4. 軍備競賽的本質：
     攻防雙方持續演進，沒有終局
     技術是中性的，看誰用、怎麼用
        │
  → 理解這場攻防 = 理解網路的「可觀測性」極限
    對設計隱私系統、理解監控、認識網路政治面都有價值
```

> **GFW 攻防最深的啟示是「加密 ≠ 隱藏」和「沒有絕對隱私」——這對任何關心隱私的工程師都重要**。超越翻牆本身，這場攻防教會我們幾個深刻的道理：(1) **沒有絕對的隱私/匿名**——流量分析（特徵、行為、ML）的能力很強，「隱藏」是成本博弈（Ch 30 的攻防經濟學）而非絕對；(2) **加密 ≠ 隱藏**——加密保護「內容」，但**元資料**（誰連誰、何時、多少流量、SNI、時序）仍然洩漏，而元資料往往足以分析行為（這是監控的關鍵——不用看內容，光看「你連了 VPN、然後有大流量」就能推斷）；(3) **明文的代價**——DNS 明文（Ch 9）、SNI 明文（Ch 11）都成了審查切入點，這是「預設加密一切」（DoH、ECH）的推動力；(4) **軍備競賽沒有終局**——技術是中性的，攻防持續演進。理解這場攻防，本質是**理解網路的「可觀測性」極限**——在網路上，什麼能被看到、什麼能被隱藏、隱藏的成本是什麼。這對工程師的價值遠超翻牆：設計隱私系統時知道「元資料也會洩漏」、理解監控和審查的能力與極限、認識網路不只是技術也有政治面向。這是本課用 GFW 當教材的真正目的——不是教翻牆，而是透過這場最激烈的真實攻防，讓你對「網路怎麼被分析、識別、控制、對抗」有最深刻的理解。再次強調：理解技術原理是教育目的，培養深度的網路與隱私素養，實際行為須遵守你所在地的法律。

## 本章重點整理

- GFW vs 反審查是二十年軍備競賽，每一步都對應本課技術：DNS 污染(Ch9)、RST 注入(Ch6)、DPI(Ch14)、TLS 指紋(Ch11)
- DNS 污染利用 DNS 明文 UDP 搶答 → DoH/DoT 對抗（Ch 9 的實戰意義）
- DPI + RST 注入：偵測敏感內容就偽造 RST 切斷（旁路注入，規模化）→ 加密 + 無特徵/偽裝對抗
- 進階手段從「特徵」到「行為」「ML」：主動探測、TLS 指紋、SNI 過濾 → AEAD/uTLS/ECH/REALITY 對抗
- 深層啟示：加密≠隱藏（元資料仍洩漏）、沒有絕對隱私（成本博弈）、明文的代價 → 推動預設加密一切
