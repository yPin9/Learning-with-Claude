# Ch 10 — 運算子優先序與表達式

> **目標**：搞懂運算子優先序與結合性、前/後置遞增、sequence point 與未定義行為、lvalue/rvalue、以及 maximum munch（`a+++b`）。這些是上機考「印出什麼」的另一類殺手。

> **環境**：C，`gcc -Wall`。前置：Ch 4（指標 `*p++`）。

## 為什麼考這個

C 的表達式陷阱很多——`a+++b` 怎麼斷詞、`i = i++ + 1` 印什麼、`*p++` 先做哪個。這些題目測你懂不懂優先序、結合性、和「什麼是未定義行為」。能正確分析（或指出「這是 UB」）展現你對 C 的精確理解。

## 先建立直覺：優先序決定「誰先綁」，結合性決定「同級從哪邊算」

```
   優先序（precedence）：不同運算子誰先算
      a + b * c  →  * 比 + 高 → a + (b*c)
   結合性（associativity）：同優先序從左還右
      a - b - c  →  - 是左結合 → (a-b)-c
      a = b = c  →  = 是右結合 → a = (b=c)
```

不用背整張表，記住幾個「最常考、最容易錯」的相對關係即可（下面）。

## 必記的優先序陷阱

```c
*p.x          // . 比 * 高 → *(p.x)，不是 (*p).x ！要 (*p).x 或 p->x
*p++          // ++ 比 * 高，但後置 → 用 *p 再 p++（Ch 4）
a & b == c    // == 比 & 高 → a & (b==c)！位元 & 比 == 低，要 (a&b)==c
a << 1 + 2    // + 比 << 高 → a << 3，不是 (a<<1)+2 ！移位比加法低
if (x = 5)    // = 不是 ==！這是賦值（永真），不是比較。gcc -Wall 會警告
x ? a : b = c // ?: 比 = 高，但 = 右結合 → 複雜，少寫
```

最常坑人的三個：

1. **位元 `&`/`|` 比 `==`/`!=` 低**：`flags & MASK == 0` 其實是 `flags & (MASK==0)`！要 `(flags & MASK) == 0`。這在韌體 bit 檢查超常踩。
2. **`.` 比 `*` 高**：`*p.x` = `*(p.x)`。要 `(*p).x` 或 `p->x`。
3. **`=` vs `==`**：`if(x=5)` 是賦值（永真），不是比較。

> 韌體實務鐵則：**bit 檢查一律加括號** `(reg & BIT) != 0`——因為 `&` 比 `==` 低，少括號就錯。別賭優先序，加括號最安全。

## 前置 vs 後置遞增

```c
int a = 5;
int b = a++;    // 後置：b = a 的舊值(5)，然後 a 變 6 → b=5, a=6
int c = ++a;    // 前置：a 先變 7，c = a 的新值(7) → c=7, a=7
```

- **後置 `a++`**：回傳舊值，然後遞增。
- **前置 `++a`**：先遞增，回傳新值。

配指標（Ch 4）：`*p++` = 用 `*p` 再 `p++`；`*++p` = 先 `++p` 再解參照；`(*p)++` = 值遞增。

## Sequence point 與未定義行為（最重要）

C 有「sequence point（序列點）」的概念——在某些點之間，運算的順序是**未指定**的。在「兩個 sequence point 之間，對同一個變數修改超過一次」是**未定義行為（UB）**。

```c
int i = 5;
i = i++ + 1;       // UB！i 在一個表達式裡被改了兩次（= 和 ++）
                   // 結果不可預測，不同編譯器/最佳化可能不同值，別問「印什麼」

int j = 0;
j = j++;           // UB
a[i] = i++;        // UB（i 被讀又被改，順序未定）
printf("%d %d", i++, i++);  // UB（同一變數多次修改）+ 參數求值順序未指定
```

**面試正解**：遇到 `i = i++ + 1`、`printf("%d", i++, ++i)` 這種，**不要算「印什麼」——要回答「這是未定義行為（UB）」**。誰敢給你一個確定答案，誰就錯了。面試官常用這種題測你知不知道 UB 的存在。

> 函式參數求值順序也是**未指定（unspecified）**：`f(i++, i++)` 的兩個參數誰先算不一定，所以結果不可靠。別寫這種 code，面試遇到指出「順序未定/UB」。

## maximum munch（最長匹配）

C 的 tokenizer 規則：**每次盡量取「最長的合法 token」。** 這導致 `a+++b` 的斷詞陷阱：

```c
a+++b
// tokenizer 貪心取最長：a ++ + b （不是 a + ++b）
// 所以 = (a++) + b
```

`+++` 被斷成 `++` 和 `+`（最長匹配 `++` 先），所以 `a+++b` = `(a++) + b`。同理 `a-----b` 會斷成 `(a--) - (--b)`（但這也可能 UB，看修改次數）。

**考點**：maximum munch 規則（Nigel Jones Q16）。面試問 `a+++b` 怎麼解析，答 `(a++)+b`。

## lvalue 與 rvalue

- **lvalue（左值）**：能出現在 `=` 左邊的東西——有「位址」、可被賦值（變數、`*p`、`arr[i]`）。
- **rvalue（右值）**：只能在右邊——值、運算結果、常數（`5`、`a+b`、`x++` 的結果）。

```c
int x;
x = 5;        // OK：x 是 lvalue
5 = x;        // 錯：5 是 rvalue，不能賦值
(a+b) = 3;    // 錯：a+b 是 rvalue
*p = 3;       // OK：*p 是 lvalue（有位址）
arr[i] = 3;   // OK：arr[i] 是 lvalue
x++ = 3;      // 錯：x++ 的結果是 rvalue
```

判準：**能不能取址 / 能不能放在 `=` 左邊**。變數、解參照、陣列元素是 lvalue；運算結果、常數、`++` 的回傳是 rvalue。MTK 考古題問過 lvalue/rvalue 定義。

## 考古題詳解

### Q1：`i = i++ + 1` 之後 i 是多少？

<details>
<summary>詳解</summary>

**未定義行為（UB）。** `i` 在同一個表達式裡被修改兩次（賦值 `=` 和 `++`），沒有 sequence point 隔開，結果不可預測。

正確答法：**不要給數字，要說「這是 UB」**。不同編譯器/最佳化等級可能給不同結果（5、6、7 都可能），但任何特定答案都是錯的——因為標準說它未定義。

**考點**：sequence point / UB 的辨識，面試陷阱題（測你知不知道 UB）。
</details>

### Q2：`a+++b` 怎麼解析？（a=3, b=2）

<details>
<summary>詳解</summary>

maximum munch 斷成 `(a++) + b` = `3 + 2` = **5**（然後 a 變 4）。

不是 `a + (++b)`。tokenizer 貪心取最長 token，`++` 先被取走。

**考點**：maximum munch（Nigel Jones Q16）。
</details>

### Q3：`if (flags & MASK == 0)` 有什麼問題？

<details>
<summary>詳解</summary>

優先序錯！`==` 比 `&` 高，所以這是 `flags & (MASK == 0)`——先算 `MASK==0`（多半是 0），再 `flags & 0` = 0，永遠為假！

本意應該是 `if ((flags & MASK) == 0)`——檢查 flags 的某些 bit 是不是都 0。

**考點**：位元 `&` 比 `==` 低，韌體 bit 檢查必加括號。超高頻實務陷阱。
</details>

### Q4：以下哪些是 lvalue？

```c
int x, arr[5], *p = &x;
// x, x+1, *p, arr[2], &x, x++, 5
```

<details>
<summary>詳解</summary>

**lvalue**：`x`、`*p`、`arr[2]`（有位址、可賦值）。
**rvalue**：`x+1`、`&x`（取址的結果是值）、`x++`（後置回傳值）、`5`（常數）。

判準：能放 `=` 左邊 / 能取址的是 lvalue。

**考點**：lvalue/rvalue 區分。
</details>

### Q5：`printf("%d %d %d\n", i, i++, ++i)` 印什麼？

<details>
<summary>詳解</summary>

**未定義 / 未指定。** 兩個原因：(1) 函式參數求值順序未指定；(2) 同一變數 `i` 在參數間被修改多次 = UB。

不同編譯器印不同結果。正解：指出「參數求值順序未定 + 多次修改 = 不可靠/UB」，別算數字。

**考點**：參數求值順序 + UB。
</details>

## 踩雷集錦

1. **給 `i = i++ + 1` 一個確定答案**：它是 UB，沒有確定答案。要指出 UB。
2. **位元 `&`/`|` 不加括號**：`flags & MASK == 0` 因 `==` 優先而錯。bit 檢查一律括號。
3. **`.` `*` 優先序**：`*p.x` = `*(p.x)`。要 `p->x` 或 `(*p).x`。
4. **`=` 寫成比較**：`if(x=5)` 是賦值永真。要 `==`。gcc -Wall 會警告。
5. **`a+++b` 算成 `a+(++b)`**：maximum munch 是 `(a++)+b`。
6. **依賴參數求值順序**：`f(i++, i++)` 順序未定，別寫、別算。
7. **以為移位優先序高**：`a << 1 + 2` = `a << 3`（`+` 比 `<<` 高）。

## 速記

- 必記陷阱：**位元 `&`/`|` 比 `==` 低**（bit 檢查加括號）、`.` 比 `*` 高、`=` ≠ `==`、`<<` 比 `+` 低。
- 後置 `a++`（用舊值再加）、前置 `++a`（先加用新值）。
- **`i = i++ + 1` / `f(i++, i++)` = UB / 未指定**——別算數字，答「未定義」。
- **maximum munch**：`a+++b` = `(a++)+b`。
- **lvalue**（可在 = 左、有位址：變數/`*p`/`arr[i]`）vs **rvalue**（值/常數/運算結果）。
