# Ch 0 — MTK 韌體面試全貌 + 一週讀書計畫

> **目標**：先搞清楚 MTK 韌體工程師面試「考什麼、怎麼考、各佔多少」，再排出一週的具體讀書計畫——別線性讀完 44 章，要按優先序攻高頻考點。

## 為什麼先排計畫，而不是直接讀

你有一週多。44 章一字不漏讀完是不可能、也不必要的——面試的考點高度集中，把時間花在「一定會考」的地方，遠勝平均分配。這章先讓你看清整個面試的形狀，再給你一份「哪些必讀、哪些選讀」的計畫。讀完這章你會知道：明天該翻哪一章。

## MTK 韌體面試的流程

依社群分享（來源見 README），聯發科軟韌體/韌體職位的面試大致是：

```
   投履歷
     │
   ① 線上 C 上機考  ← 電腦隨機抽 C 考題，要當場寫出來（韌體職位的關鍵關卡）
     │
   ② 性格測驗（華德士 Waters 之類）← 非技術，照實答即可
     │
   ③ 技術面試  ← 自我介紹 → 主考官技術問答 → 部門介紹 → 你提問
     │           （問：專題、資料結構、OS、計組、C、嵌入式）
     │
   ④ 主管面試 / HR  ← 動機、人格特質、薪資、研發替代役/實習流程
     │
   offer
```

> 認識論誠實：流程細節（幾關、順序、是否線上）會隨年份、部門、職缺類型（正職/實習/研發替代役）變動。重點不是記死流程，是知道「**有一關 C 上機考**」和「**技術面會跨 C/OS/計組/DS/嵌入式問**」——這決定你怎麼準備。

## 考什麼：五大塊與權重

把社群考古題歸納，這個職位的考點與相對權重（★越多越常考）：

| 領域 | 權重 | 高頻考點 | 對應 Part |
|---|---|---|---|
| **C 語言** | ★★★★★ | volatile/const/static、複雜宣告、bit operation、巨集陷阱、指標、記憶體對齊、整數轉型 | Part 1 |
| **嵌入式/韌體** | ★★★★ | 存取固定位址、ISR、reentrancy、endian、ARM、RTOS | Part 2 |
| **作業系統** | ★★★★ | process/thread、deadlock、同步、scheduling、virtual memory、IPC | Part 3 |
| **計算機組織** | ★★★ | cache、pipeline、編譯連結、補數/浮點、DMA | Part 4 |
| **資料結構** | ★★★ | linked list、tree、sorting、複雜度、hash | Part 5 |
| **行為/非技術** | ★★ | 自我介紹、專題深挖、動機 | Part 6 |

兩個關鍵判斷：

1. **C 是重中之重**——因為有上機考，且技術面也大量問。Part 1 是你最該投資的。
2. **嵌入式專屬考點**（ISR、固定位址、endian、reentrancy）是這職位**有別於一般軟體面試**的地方，常被一般考生忽略——這是你的差異化。Part 2 別跳過。

## 上機考長什麼樣

線上 C 上機考是韌體職位的特色關卡。題型（依考古題）：

- **觀念輸出題**：給一段 code 問「印出什麼/會不會編譯成功」（考 static、`#define`、整數轉型、運算子優先序、指標運算）。
- **手寫實作題**：寫一個巨集（MIN、SQR、判 2 次方）、寫 bit operation、reverse string、reverse linked list、實作 strcpy/memcpy。
- **找 bug / 評論題**：給一段有問題的 code（未初始化指標、volatile 缺失、ISR 寫錯）要你指出問題。

準備重點：**這些要在電腦上真的打出來、能編譯能跑。** 光在腦中想會在現場手忙腳亂。練習 A 直接模擬這關。

## 一週讀書計畫

以下是「一週多」的建議分配。**按優先序，不是按章節順序**——時間不夠就砍低優先的。

```
   Day 1-2：C 語言核心（Part 1，最高優先）
     必讀：Ch 2 static、Ch 3 const/volatile、Ch 6 巨集、Ch 7 bit operation、
           Ch 5 複雜宣告、Ch 9 整數轉型、Ch 10 運算子優先序
     選讀：Ch 1、Ch 4、Ch 8、Ch 11、Ch 12（觀念你熟就快速掃）
     動手：練習 A（C 上機考模擬）— 親手打、編譯、跑

   Day 3：嵌入式/韌體（Part 2，差異化關鍵）
     必讀：Ch 13 固定位址、Ch 14 ISR、Ch 15 reentrancy、Ch 16 endian
     選讀：Ch 17 ARM、Ch 18 RTOS、Ch 19 實務
     動手：練習 B

   Day 4：作業系統（Part 3）
     必讀：Ch 20 process/thread、Ch 22 同步、Ch 23 deadlock、Ch 25/26 記憶體/VM
     選讀：Ch 21 scheduling、Ch 24 經典問題、Ch 27 IPC、Ch 28 syscall
     動手：練習 C

   Day 5：計算機組織（Part 4）
     必讀：Ch 30 cache、Ch 31 pipeline、Ch 33 編譯連結
     選讀：Ch 29 數字、Ch 32 ISA、Ch 34 DMA、Ch 35 並行硬體
     動手：練習 D

   Day 6：資料結構（Part 5）
     必讀：Ch 36 linked list、Ch 38 tree、Ch 40 sorting、Ch 41 複雜度
     選讀：Ch 37 stack/queue、Ch 39 hash
     動手：練習 E（手寫題）

   Day 7：整合衝刺
     上午：Ch 42 行為面試（準備自我介紹、專題、動機）
     下午：Final 模擬面試（完整跑一遍）
     考前一晚：Ch 43 速查表（每科最高頻濃縮）
```

> 如果你時間更緊（少於一週）：只攻 **Part 1（C）+ Part 2（嵌入式）+ Ch 23 deadlock + Ch 22 同步 + Ch 30 cache + Ch 36 linked list + Ch 43 速查表**。這是投報率最高的核心。

## 怎麼用每一章

每章的結構固定，這樣用：

1. **概念複習**：你熟的快速掃過（確認沒漏），不熟的細讀。
2. **考古題詳解**：**先遮答案自己答**，卡住再看——這是主動回憶，記得最牢。
3. **踩雷集錦**：面試最常答錯的地方，重點看。
4. **速記/重點**：當該章的濃縮，複習時只看這個。
5. **自我檢核**：用「面試官問你會怎麼答」的角度自測。

## 心態與非技術提醒

- **講不出來比答錯更糟**：面試官常常想看你的思路，不是只要答案。卡住時把思考過程說出來（「我想這題在考 X，可能要用 Y...」），比沉默好。
- **誠實**：不會就說不會、說你會怎麼查——硬掰被拆穿更扣分。
- **專題要能深挖**：技術面常從你的專題/作品問起，且會一直追問細節。準備好「為什麼這樣做、遇到什麼問題、怎麼解」（Ch 42）。
- **上機考環境**：確認你慣用的編譯/輸入方式，現場別卡在工具。

## 本章重點整理

- MTK 韌體面試：線上 C 上機考 + 性格測驗 + 技術面（跨 C/OS/計組/DS/嵌入式）+ 主管面。
- 權重：C★★★★★、嵌入式★★★★、OS★★★★、計組★★★、DS★★★。C 與嵌入式是重點與差異化。
- 上機考要「真的打出來能跑」——練習 A 模擬它。
- 按優先序讀，不要線性讀完 44 章；時間緊就攻 C + 嵌入式 + deadlock/同步 + cache + linked list + 速查表。
