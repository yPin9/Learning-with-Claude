# Ch 29 — 數字表示與運算

> **目標**：搞懂電腦怎麼表示數字——二補數（two's complement）、有號/無號、浮點數 IEEE 754、溢位。這是計組基礎，也補強 Ch 9（整數陷阱）的底層原理。

> **環境**：概念 + C。前置：Ch 7（位元）、Ch 9（整數轉型）。

## 為什麼考這個

電腦只有 0 和 1——怎麼表示負數、小數？答案是二補數和 IEEE 754。理解它們，你才懂 Ch 9 的整數陷阱（為什麼 signed 溢位環繞、為什麼浮點比較不能用 `==`）的底層原因。面試會問「二補數」「浮點怎麼存」。

## 先建立直覺：用固定位元表示數

```
   n 個 bit 能表示 2^n 種不同的值。怎麼分配給「正數、負數、小數」？
   - 無號整數：全部給非負數（0 ~ 2^n - 1）
   - 有號整數：用「二補數」把一半給負數
   - 小數：用「浮點」（IEEE 754，類似科學記號）
```

## 二補數（two's complement）

表示有號整數的標準方法。**負數 = 把正數的位元全反轉 + 1。**

```
   8-bit 為例：
   +5  = 0000 0101
   -5  = 反轉(1111 1010) + 1 = 1111 1011

   驗證：5 + (-5) = 0000 0101 + 1111 1011 = (1)0000 0000 = 0（進位丟棄）✓
```

二補數的特性：

- **最高位是符號位**（1 = 負、0 = 非負），但它**不只是符號**（是 -2^(n-1) 的權重）。
- **範圍不對稱**：8-bit 是 -128 ~ +127（負數比正數多一個）——因為 0 佔了一個正數位置。
- **0 只有一種表示**（不像「sign-magnitude」有 +0 和 -0）。
- **加減法統一**：`a - b = a + (-b)`，硬體只要一套加法器（這是二補數勝出的關鍵原因）。

為什麼用二補數（不用其他）：**加減法和無號數用同一套電路**（不用特別處理符號）、0 唯一、範圍連續。這是它打敗 sign-magnitude、one's complement 的原因。

快速算二補數的值：最高位權重是負的。`1111 1011` = -128+64+32+16+8+0+2+1 = -5。或「反轉+1 看是多少正數，加負號」。

## 有號 vs 無號（連 Ch 9）

同樣的 bit pattern，當有號或無號解讀，值不同：

```
   1111 1111（8-bit）
   無號：255
   有號（二補數）：-1

   這就是 Ch 9 「-1 轉 unsigned = 255」的底層——bit pattern 沒變，
   只是「怎麼解讀」變了。signed -1 和 unsigned 255 是同一串 bit。
```

Ch 9 的整數陷阱（`-20+6u`、signed 溢位）都源於此——值的儲存是 bit pattern，有號/無號是「解讀方式」。

## 整數溢位（連 Ch 9）

```
   有號溢位：超過範圍會「環繞」到負數（bit pattern 上）
   127 + 1（8-bit signed）= 0111 1111 + 1 = 1000 0000 = -128（環繞！）
   但 C 標準說有號溢位是 UB（Ch 9）——別依賴這行為

   無號溢位：環繞（定義良好，模 2^n）
   255 + 1（8-bit unsigned）= 0
```

底層都是「進位被丟棄、bit pattern 環繞」，但 C 對有號溢位定義為 UB、無號定義為環繞（Ch 9）。

## 浮點數 IEEE 754

表示小數的標準。類似科學記號 `±尾數 × 2^指數`：

```
   單精度 float（32-bit）：
   [符號 1 bit][指數 8 bits][尾數 23 bits]
       sign      exponent      mantissa/fraction

   值 = (-1)^sign × 1.mantissa × 2^(exponent - 127)
                    └─隱含的1─┘      └─bias 127─┘

   雙精度 double（64-bit）：1 + 11 + 52 bits，bias 1023
```

關鍵概念：

- **三部分**：符號（正負）、指數（範圍/大小，有 bias 偏移）、尾數（精度）。
- **指數有 bias**：存的指數 = 真實指數 + bias（127 for float），這樣指數能表示負值又方便比較。
- **隱含的 1**：尾數前面有個隱含的 `1.`（normalized），省一個 bit。
- **特殊值**：指數全 0 或全 1 表示特殊——0、無限大（inf）、NaN（not a number）、denormal。

浮點的兩大陷阱（面試常考）：

### 1. 浮點不精確（不能用 == 比較）

```c
0.1 + 0.2 == 0.3    // false！
```

`0.1`、`0.2`、`0.3` 在二進位浮點裡**無法精確表示**（像十進位無法精確表示 1/3）——所以 `0.1+0.2` ≈ 0.30000000000000004，不等於 0.3 的浮點表示。

**比較浮點要用「差的絕對值 < 一個很小的 epsilon」**：

```c
if (fabs(a - b) < 1e-9) { /* 視為相等 */ }
```

### 2. 精度有限

float 約 7 位有效數字、double 約 15-16 位。超過就丟失精度（大數加小數，小數可能「消失」）。韌體選 float/double 要權衡精度 vs 記憶體/速度（嵌入式常避免浮點，Ch 14 ISR 禁浮點）。

## 考古題詳解

### Q1：什麼是二補數？-5 的 8-bit 二補數是多少？

<details>
<summary>詳解</summary>

二補數：表示有號整數，**負數 = 正數位元全反轉 + 1**。

-5：+5 = `0000 0101`，反轉 = `1111 1010`，+1 = `1111 1011`。

為什麼用二補數：加減法和無號數用同一套電路、0 唯一、範圍連續。

**考點**：二補數計算 + 為什麼用它，必考。
</details>

### Q2：8-bit 有號整數的範圍？為什麼不對稱？

<details>
<summary>詳解</summary>

**-128 ~ +127**（不是 -127~127）。

不對稱原因：8-bit 有 256 種 bit pattern，0 佔一個（屬於非負側），所以非負是 0~127（128 個）、負是 -1~-128（128 個）——負數比正數多一個（多了 -128，但沒有 +128）。

`1000 0000` = -128（最高位權重 -128，其餘 0）。

**考點**：有號範圍不對稱，常考。
</details>

### Q3：為什麼 `0.1 + 0.2 != 0.3`？浮點怎麼正確比較？

<details>
<summary>詳解</summary>

0.1、0.2、0.3 在二進位浮點**無法精確表示**（像十進位無法表 1/3）。`0.1+0.2` 的浮點結果 ≈ 0.30000000000000004 ≠ 0.3 的浮點表示。

正確比較：**用 epsilon**——`fabs(a-b) < 1e-9`（差夠小視為相等），不要用 `==`。

**考點**：浮點不精確 + epsilon 比較，超經典必考。
</details>

### Q4：IEEE 754 float 的三個部分是什麼？

<details>
<summary>詳解</summary>

32-bit float：**符號（1 bit）+ 指數（8 bits，有 bias 127）+ 尾數（23 bits）**。

值 = (-1)^符號 × 1.尾數 × 2^(指數-127)。指數有 bias（存的=真實+127）方便表示負指數和比較；尾數有隱含的前導 1。特殊值（指數全0/全1）表示 0/inf/NaN。

**考點**：IEEE 754 結構。
</details>

### Q5：為什麼嵌入式/ISR 常避免浮點？

<details>
<summary>詳解</summary>

幾個原因（連 Ch 14/17）：
1. 很多 MCU **沒有硬體浮點單元（FPU）**——浮點要軟體模擬，超慢。
2. 浮點暫存器在 context switch / ISR 可能沒被保存（Ch 14 ISR 禁浮點）。
3. 不精確（Ch 上面）——控制系統可能用定點數（fixed-point）更可靠。
4. 耗記憶體/能耗。

嵌入式常用**定點數（fixed-point，用整數模擬小數）**取代浮點。

**考點**：嵌入式避免浮點，串 Ch 14/17。
</details>

## 踩雷集錦

1. **二補數負數算錯**：負數 = 反轉 + 1（不是只反轉，那是 one's complement）。
2. **有號範圍記成對稱**：8-bit 是 -128~+127（負多一個），不是 -127~127。
3. **浮點用 == 比較**：浮點不精確，用 `fabs(a-b) < epsilon`。
4. **以為 signed -1 和 unsigned 255 是不同 bit**：同一串 bit（`1111 1111`），差在解讀（Ch 9）。
5. **以為浮點能表示所有小數**：很多小數（0.1）二進位無法精確表示。
6. **嵌入式亂用浮點**：MCU 可能無 FPU（慢）、ISR 禁浮點。考慮定點數。

## 速記

- **二補數**：負數 = 正數反轉 + 1；最高位是符號（權重 -2^(n-1)）；範圍 **-2^(n-1) ~ 2^(n-1)-1**（不對稱，負多一個）；加減用同套電路（勝出原因）。
- 同 bit pattern，signed/unsigned 解讀不同值（`1111 1111` = -1 或 255，Ch 9 根源）。
- 溢位：底層環繞（bit pattern），但 C 有號 UB、無號定義環繞（Ch 9）。
- **IEEE 754**：符號 + 指數（有 bias）+ 尾數；浮點**不精確**（`0.1+0.2≠0.3`）→ 比較用 **epsilon**（`fabs(a-b)<eps`）。
- 嵌入式常避免浮點（無 FPU/ISR 禁/不精確）→ 用定點數。
