# Ch 42 — 行為面試與軟實力

> **目標**：準備 MTK 技術面/主管面的非技術部分——自我介紹、專案深挖、行為問題（STAR）、英文問答、提問環節、性格測驗。技術過關只是門票，行為面試決定 offer 與級職。

> **環境**：面試準備。前置：無（但專案深挖要你對自己履歷上的東西夠熟）。

## 為什麼這章重要

很多人技術筆試/上機過了，卻倒在主管面——因為把行為面試當「隨便聊聊」。實際上 MTK 主管面會深挖你的專案、考你的溝通與解決問題的思路、確認你能不能融入團隊。韌體工作常要跨團隊（硬體、測試、系統），溝通與態度被看得很重。這章給你框架，不是要你背稿，是讓你想清楚。

## MTK 面試的非技術環節

回顧 Ch 0 的流程，技術之外你會遇到：
- **性格測驗**（線上，技術面前）：人格特質問卷，無標準答案但要**一致**（別前後矛盾）。
- **自我介紹**（技術面/主管面開場）：90 秒～2 分鐘。
- **專案深挖**：針對你履歷的專案追問細節、決策、貢獻。
- **行為問題**：團隊衝突、失敗經驗、壓力處理、為什麼選 MTK。
- **英文**：可能要求英文自我介紹或英文回答幾題（MTK 外商客戶多）。
- **你提問**：最後「你有什麼想問的」——這也是評分項。

## 自我介紹（90 秒框架）

別流水帳念履歷。用這個結構：

```
1. 我是誰（一句）：背景 + 主修 + 核心專長方向
2. 最相關的經歷（30-40 秒）：挑「和韌體最相關」的 1-2 個專案/經驗，講你做了什麼、用什麼技術、結果
3. 為什麼適合這個職位 + 為什麼是 MTK（20 秒）：把你的專長和韌體工程師職責連起來
```

範例骨架（韌體職）：
> 「我是 ___，___ 大學電機/資工系。我對嵌入式系統特別有興趣，做過 ___ 專案，在 STM32 上用 C 從 register level 寫 ___ 驅動，處理過 ___ 問題。我熟 C 和記憶體、中斷、通訊協定（I2C/SPI/UART），這些正是韌體開發的核心。MTK 在 ___ 領域是領導者，我想在這裡把底層功夫做深。」

把你**真正做過**的填進去。沒有嵌入式專案？挑最接近底層的（OS 課程專案、C 的系統程式、任何碰硬體的）。

## 專案深挖：最關鍵的部分

主管會針對你說的專案連環追問。準備**每個履歷專案**都能回答：
- **你具體做了什麼**（不是「我們團隊做了」，是「我負責 ___」）。
- **為什麼這樣設計**（技術決策的理由，考你的判斷）。
- **遇到什麼困難、怎麼解的**（debug 過程最能展現實力——連結 Ch 19 韌體 debug：你怎麼用 JTAG/printf/邏輯分析儀找 bug）。
- **學到什麼 / 會怎麼改進**（反思能力）。

陷阱：別在履歷寫你不熟的東西。寫了「熟悉 RTOS」就要能答 Ch 18 的 priority inversion；寫了「I2C」就要能畫時序（Ch 13 周邊）。**被問到答不出自己履歷的東西，是致命傷。**

## 行為問題：STAR 法

行為問題（「講一個你遇到衝突的經驗」）用 **STAR** 結構，避免講成流水帳或抽象空話：

```
S (Situation)：背景，一兩句交代情境
T (Task)：你的任務/面對的問題是什麼
A (Action)：你具體採取了什麼行動（重點，講「我」做了什麼）
R (Result)：結果如何，量化更好（效能提升 X%、bug 解決、如期交付）
```

常見題與準備方向：
- **最有成就感/最難的專案**：用 STAR，挑能展現技術深度的。
- **失敗或犯錯的經驗**：誠實講一個真的錯誤 + **你學到什麼、之後怎麼避免**（重點在成長，別挑「我太完美主義」這種假答案）。
- **團隊衝突**：展現你能溝通、對事不對人、找共識，不是「我都對」。
- **壓力/deadline 處理**：展現你會排優先序、求助、不崩潰。
- **為什麼選 MTK / 韌體**：做功課——MTK 做什麼（手機 SoC Dimensity、Wi-Fi、IoT、車用）、為什麼吸引你。別答「因為大公司穩定」。

## 英文準備

MTK 客戶與文件多英文。至少準備：
- **英文自我介紹**（把上面的中文版翻成英文，練到流暢）。
- 幾個技術詞的英文說法（你已經會了——本課術語都中英並陳）。
- 心態：不用完美口音，能清楚表達技術內容即可。卡住時放慢、簡單句子。

## 你要問面試官的問題

「你有什麼想問的？」**一定要問**（答「沒有」=沒興趣/沒準備）。問好問題展現你思考過這份工作：
- 「這個職位的韌體主要跑在什麼平台上？team 用什麼 RTOS / 開發流程？」
- 「新人前半年大概會接觸哪些任務？」
- 「team 在 debug 硬體相關問題時，主要用哪些工具和流程？」
- 「這個 team 接下來一年最大的技術挑戰是什麼？」

別問：薪水（除非到談薪階段）、「你們會加班嗎」（問法要正面）、Google 一秒查得到的公司基本資料。

## 性格測驗

線上人格問卷（如類似 PI、DISC 的測驗）。原則：
- **誠實 + 一致**：題目會重複換句問同一特質，前後矛盾會被抓出來。
- 別過度「演」成你以為公司想要的樣子——可能矛盾，也可能 mismatch 到不適合的位置。
- 放輕鬆作答，這通常是篩 red flag（極端答案）而非主要評分。

## 踩雷集錦

1. **履歷寫了卻答不出**：寫「精通 X」就要扛得住深挖。不熟的別寫「精通」，寫「接觸過」。
2. **自我介紹念流水帳**：把每段經歷都念一遍。挑最相關的 1-2 個講深。
3. **講專案都說「我們」**：主管要知道**你**做了什麼。明確區分團隊貢獻和個人貢獻。
4. **行為題講空話**：「我學習能力很強」沒用，要用 STAR 給具體事例佐證。
5. **失敗經驗講假答案**：「我太認真」這種假謙虛一聽就知道。講真的錯 + 真的成長。
6. **問「你有問題嗎」答「沒有」**：=不感興趣。準備 2-3 個好問題。
7. **不做公司功課**：不知道 MTK 做什麼產品。至少知道 Dimensity（手機 SoC）、它在 Wi-Fi/IoT/車用的布局。
8. **英文完全沒準備**：被要求英文自介時卡住。先練好中文版再翻譯練熟。

## 速記

- **環節**：性格測驗（誠實一致）、自我介紹（90 秒：我是誰→最相關經歷→為何適合+為何 MTK）、專案深挖、行為題、英文、你提問。
- **專案深挖最關鍵**：每個履歷專案都能講「我做了什麼/為什麼這樣設計/怎麼 debug/學到什麼」。**履歷寫的都要扛得住問**。
- **行為題用 STAR**（Situation/Task/Action/Result），講「我」、結果量化。失敗題講真錯+真成長。
- **一定要問問題**（展現興趣），別問薪水/加班/可 Google 的。
- 做 MTK 功課：Dimensity SoC、Wi-Fi/IoT/車用。
- 英文自介練熟。
