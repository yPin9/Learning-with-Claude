# Ch 10 — RS-485 差分信號

> 目標：理解 RS-485（EIA-485）差分信號的物理層原理，掌握 ESP32 UART RS-485 模式的設定，實作正確的 DE/RE 時序控制，避免常見的半雙工切換問題。

## RS-485 vs RS-232 vs TTL UART 比較

| 特性 | TTL UART | RS-232 | RS-485 |
|------|----------|--------|--------|
| 信號類型 | 單端（對 GND） | 單端（對 GND） | 差分（A−B） |
| 邏輯電壓 | 0/3.3V 或 0/5V | ±3V ~ ±15V | |VA−VB| > 0.2V |
| 最大距離 | 約 1 m | 約 15 m | 1200 m（低速） |
| 最大節點數 | 點對點 | 點對點 | 32 個（標準），256 個（1/8 負載） |
| 抗共模雜訊 | 差 | 差 | 優（共模抑制比高） |
| 最大速率 | 取決於驅動 | 20 kbps（標準） | 10 Mbps（短距） |
| 雙工 | 全雙工 | 全雙工 | 典型半雙工 |

工業場景選 RS-485 的原因只有兩個：距離長、抗雜訊強。對一般短距離的 MCU 通訊，UART 夠用。

## 差分信號原理

RS-485 使用兩條訊號線：**A（+）** 和 **B（−）**：

```
差分電壓 V_diff = V_A - V_B

邏輯 1（mark）：V_A - V_B > +0.2V
邏輯 0（space）：V_A - V_B < -0.2V
```

雜訊（共模雜訊，Common Mode Noise）會同時加在 A 和 B 上，因此差值不受影響：

```
有雜訊 V_noise 時：
V_A' = V_A + V_noise
V_B' = V_B + V_noise
V_A' - V_B' = V_A + V_noise - V_B - V_noise = V_A - V_B  ✓
```

這就是為何工廠環境（有電機、變頻器等雜訊源）一定要用差分信號的原因。

## 半雙工架構

RS-485 標準通常採用**半雙工（half-duplex）**：同一時間只能一個方向傳輸，共用一對差分線。

需要 **DE（Driver Enable，驅動器致能）** 和 **RE（Receiver Enable，接收器致能，通常低有效）** 兩個控制腳：

```
傳輸模式（TX）：DE=HIGH, /RE=HIGH（關閉接收器）
接收模式（RX）：DE=LOW,  /RE=LOW （關閉驅動器，開啟接收器）
```

```
ESP32 UART TX/RX ─── MAX485 ─── A/B 差分線 ─── 遠端節點
          │          │
         GPIO        DE, /RE
```

MAX485 / MAX3485 的典型接線：

```
MAX485 pin    連接
──────────    ──────
A             差分線 A（+）
B             差分線 B（−）
DI            ESP32 UART TX
RO            ESP32 UART RX
DE            GPIO（傳輸時拉高）
/RE           GPIO（接收時拉低，可與 DE 接同一 GPIO 反相器，或直接接 DE 共用同一 GPIO 但邏輯相反）
VCC           3.3V 或 5V
GND           GND
```

最簡單的接法：DE 和 /RE 接同一個 GPIO，因為 DE=高且 /RE=高 = TX 模式，DE=低且 /RE=低 = RX 模式，剛好互補，只要不需要同時收發就成立。

## 終端電阻

總線兩端各接 **120 Ω** 終端電阻（接在 A 和 B 之間），抑制傳輸線的信號反射：

```
Termination resistor                Termination resistor
       ┌──120Ω──┐                         ┌──120Ω──┐
Master A─────────────────────────────── A Node1
Master B─────────────────────────────── B Node1

傳輸線特性阻抗通常是 120 Ω，終端電阻等於特性阻抗，反射係數 = 0
```

短距離（< 10 m）、低速（< 100 kbps）可以省略終端電阻，但工業現場一律加上。

## ESP32 UART RS-485 模式

ESP32 的 UART controller 內建 RS-485 半雙工支援，不需要外部邏輯：

### CONF0_REG RS-485 相關 bit

```
UART_CONF0_REG:
  [22]  rs485_en         : 1=啟用 RS-485 模式
  [23]  rs485_tx_rx_en   : 1=TX 時也開啟接收（偵測碰撞），0=TX 時關閉 RX
  [24]  rs485_rx_dly_num : RX delay（bit 數）
  [25]  rs485_tx_dly_num : TX delay（bit 數）
```

啟用 RS-485 後，UART controller 會在 TX 開始時自動透過 **RTS 腳**輸出 DE 控制信號：

- 發送時：RTS 輸出高（對應 DE=HIGH）
- 空閒時：RTS 輸出低（對應 DE=LOW）

這樣就不需要軟體手動控制 GPIO，硬體自動處理 DE/RE 時序。要用這個功能，DE 腳必須接到 ESP32 的 RTS GPIO。

不過，硬體自動 DE 有一個限制：它在 TX FIFO 不空時就拉高 DE，在 TX shift register 送完最後一個 bit 之後立刻拉低，沒有額外的 guard time。如果 MAX485 的傳播延遲加上接收端的反應時間超過這個邊界，第一個或最後一個 bit 可能出問題。

## 完整 RS-485 收發實作

```c
#include <stdint.h>
#include <stddef.h>

#define REG_WRITE(addr, val)  (*((volatile uint32_t *)(addr)) = (val))
#define REG_READ(addr)        (*((volatile uint32_t *)(addr)))
#define REG_SET_BIT(addr, b)  REG_WRITE((addr), REG_READ(addr) | (b))
#define REG_CLR_BIT(addr, b)  REG_WRITE((addr), REG_READ(addr) & ~(b))

// 假設使用 UART2（0x3FF6E000），DE 接 GPIO4
#define RS485_UART_PORT  2
#define RS485_DE_GPIO    4

#define UART2_BASE       0x3FF6E000UL
#define UART_CONF0_REG   0x20
#define UART_STATUS_REG  0x1C
#define UART_FIFO_REG    0x00
#define UART_INT_RAW_REG 0x04
#define UART_INT_CLR_REG 0x10

// GPIO output 設定
#define GPIO_OUT_W1TS_REG  0x3FF44008UL   // 寫 1 = GPIO 輸出高
#define GPIO_OUT_W1TC_REG  0x3FF4400CUL   // 寫 1 = GPIO 輸出低
#define GPIO_ENABLE_W1TS   0x3FF44020UL
#define GPIO_FUNC_OUT_SEL(n)  (0x3FF44530UL + (n)*4)

// TX_DONE_INT bit 14
#define TX_DONE_INT (1 << 14)

static void de_set(int high) {
    if (high) {
        REG_WRITE(GPIO_OUT_W1TS_REG, (1u << RS485_DE_GPIO));
    } else {
        REG_WRITE(GPIO_OUT_W1TC_REG, (1u << RS485_DE_GPIO));
    }
}

// 初始化 RS-485（在 uart_init() 之後呼叫）
void rs485_init(void) {
    // DE GPIO 設為輸出，初始為低（RX 模式）
    REG_WRITE(GPIO_FUNC_OUT_SEL(RS485_DE_GPIO), 0x100);  // direct GPIO output
    REG_WRITE(GPIO_ENABLE_W1TS, (1u << RS485_DE_GPIO));
    de_set(0);

    // UART2 CONF0：啟用 RS-485，關閉 TX 時接收（避免回聲干擾）
    // bit22=rs485_en=1, bit23=rs485_tx_rx_en=0
    REG_SET_BIT(UART2_BASE + UART_CONF0_REG, (1u << 22));
    REG_CLR_BIT(UART2_BASE + UART_CONF0_REG, (1u << 23));
}

// RS-485 發送
// 注意：發送前拉高 DE，發完等 TX 真的空了才拉低
void rs485_write(const uint8_t *data, size_t len) {
    size_t i;
    uint32_t base = UART2_BASE;

    // 1. 清除 TX_DONE_INT
    REG_WRITE(base + UART_INT_CLR_REG, TX_DONE_INT);

    // 2. 拉高 DE（進入 TX 模式）
    // 重要：DE 拉高到第一個 start bit 之間必須有足夠的 setup time
    // MAX485 要求 DE 拉高到開始傳輸至少 0（立即可傳），但保守起見加幾個 nop
    __asm__ __volatile__("nop; nop; nop; nop; nop; nop; nop; nop;");
    de_set(1);
    __asm__ __volatile__("nop; nop; nop; nop; nop; nop; nop; nop;");

    // 3. 填入 TX FIFO
    for (i = 0; i < len; i++) {
        // 等 FIFO 不滿（txfifo_cnt，bit 23:16）
        while (((REG_READ(base + UART_STATUS_REG) >> 16) & 0xFF) >= 127) {}
        REG_WRITE(base + UART_FIFO_REG, data[i]);
    }

    // 4. 等待 TX 完全空（TX_DONE_INT）
    // TX_DONE 代表 shift register 也空了，最後一個 bit 已經送出
    uint32_t timeout = 500000;
    while (!(REG_READ(base + UART_INT_RAW_REG) & TX_DONE_INT)) {
        if (--timeout == 0) break;
    }
    REG_WRITE(base + UART_INT_CLR_REG, TX_DONE_INT);

    // 5. 拉低 DE（回到 RX 模式）
    // 這裡的延遲很關鍵：stop bit 送完後，MAX485 還有傳播延遲，
    // 要等遠端收到 stop bit 之後才能拉低 DE。
    // 保守做法：等至少半個 bit period。
    // 9600 baud = 104us/bit，這裡用 100 個 nop ≈ 125ns（不夠，要用 busy-wait）
    // 較好的方法是用 esp_rom_delay_us()，這裡用簡單 busy loop 示意
    volatile uint32_t d = 200; while (d--) {}
    de_set(0);
}

// RS-485 接收（帶 timeout，polling）
size_t rs485_read(uint8_t *buf, size_t max_len, uint32_t per_byte_timeout) {
    size_t count = 0;
    uint32_t base = UART2_BASE;

    while (count < max_len) {
        uint32_t t = per_byte_timeout;
        while ((REG_READ(base + UART_STATUS_REG) & 0xFF) == 0) {
            if (--t == 0) goto done;
        }
        buf[count++] = (uint8_t)(REG_READ(base + UART_FIFO_REG) & 0xFF);
    }
done:
    return count;
}
```

## DE/RE 時序問題詳解

這是 RS-485 最容易踩的坑：

**問題 1：DE 拉高太晚，第一個 byte 的 start bit 消失**

```
UART TX:  ‾‾‾‾\___ start bit ___data___
DE:            ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
                    ^
              DE 拉高晚於 start bit → 接收端看不到 start bit
```

解法：DE 拉高後至少加幾個 NOP 再讓 UART 開始送。或使用硬體自動 DE（UART RTS 腳）。

**問題 2：DE 拉低太早，最後一個 byte 的 stop bit 被截**

```
UART TX:  ___data___ stop bit ‾‾‾‾‾
DE:       ‾‾‾‾‾‾‾‾‾‾‾‾‾\___
                          ^
              TX FIFO 空了就拉低 → stop bit 沒有被驅動器送出
```

解法：等 `TX_DONE_INT`（shift register 空了）再拉低 DE，而不是等 TXFIFO 空。這就是 `uart_flush_tx()` 的用途。

**問題 3：傳播延遲**

MAX485 有 ~100 ns 的傳播延遲，加上電纜延遲（5 ns/m × 1200 m = 6 µs），在拉低 DE 之前必須考慮這個延遲，否則遠端在 stop bit 還在傳播途中，本端就已關閉驅動器，stop bit 波形被截斷。

實際工程做法：等 TX_DONE 之後再等 **2 個 bit period** 的時間才拉低 DE。9600 baud 的 2 bit period ≈ 208 µs，很保守但很安全。

## 常見問題排查

| 症狀 | 原因 |
|------|------|
| 第一個 byte 收到的值是 shift 過的 | DE 拉高太慢，start bit 被吃掉 |
| 最後一個 byte 後接收方得到 framing error | DE 拉低太快，stop bit 被截 |
| 整筆資料都沒收到 | DE/RE 反接，或 A/B 差分線接反 |
| 偶爾資料錯誤 | 終端電阻未接，反射干擾 |
| 短距離測試正常，拉長後出問題 | 終端電阻未接，或電纜阻抗不匹配 |
